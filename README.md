# Агентские навыки Koda

Коллекция навыков (skills) для AI-ассистента Koda.

* Официальный сайт: <https://kodacode.ru>
* Скачать Koda для JetBrains, VSCode или CLI: <https://download.kodacode.ru>
* Сообщество в Telegram: [@kodacommunity](https://t.me/kodacommunity)

## Введение

**Навыки** — это переиспользуемые наборы инструкций для агента, которые помогает сфокусироваться на конкретных знаниях и задачах.
Когда задача соответствует описанию навыка, модель вызывает соответствующий инструмент и загружает полные инструкции.
В запросах к моделям также можно явно указывать требования запуска нужного навыка.

Поддержка навыков продуктами Koda:
* плагин с версии 0.7.0 (VSCode/JetBrains)
* koda-cli с версии 0.3.0

## Быстрый старт

Установка навыка для установки навыков :)

1. **Создайте** файл в домашней директории:
   - Linux/MacOS: `~/.koda/skills/koda-learn/SKILL.md`
   - Windows: `%USERPROFILE%\.koda\skills\koda-learn\SKILL.md`
2. **Скопируйте** в этот файл содержимое [по ссылке](https://raw.githubusercontent.com/XCode-NLP/KodaSkills/main/skills/koda-learn/SKILL.md) и сохраните
3. **Активируйте**:
   - плагин: в режиме "Агент" на панели "Навыки" нажмите кнопку "Обновить список навыков"
   - koda-cli: выполните команду `/skill enable koda-learn`

Так вы сможете просто попросить любую модель в Koda установить навык для решения какой-либо задачи.
Так навык будет установлен в директорию текущего проекта (локально), поскольку Koda не имеет доступа к файловой системе за его пределами.

Аналогично можно установить любой другой навык из этого репозитория.
Ниже расписаны некоторые подробности.

## Установка

Навыки должны располагаться по следующим путям:

| Продукт                       | Директория                              |
| ----------------------------- | --------------------------------------- |
| **Плагин (VSCode/JetBrains)** | `.koda/skills/<имя_навыка>/SKILL.md`    |
| **CLI**                       | `.kodacli/skills/<имя_навыка>/SKILL.md` |
| **Все**                       | `.agents/skills/<имя_навыка>/SKILL.md`  |

Для **глобальной** установки (для всех проектов) директорию навыка следует располагать в домашней директории:
* Linux/MacOS: `~/` или `$HOME`
* Windows: `%USERPROFILE%`

Например: `%USERPROFILE%\.agents\skills\koda-learn\SKILL.md`

Для **локальной** установки (для одного проекта) достаточно скопировать навык в соответствующую папку в корне этого проекта.

Установить навыки можно командой [npx skills](https://github.com/vercel-labs/skills):

```shell
# установка в интерактивном режиме
npx skills add XCode-NLP/KodaSkills

# установка одного конкретного навыка
npx skills add XCode-NLP/KodaSkills --skill koda-cli-subagent
```

Также можно использовать аргументы `-y` для явного подтверждения, `-g` для глобальной установки.
Доступны и другие аргументы, их описание есть в репозитории [skills](https://github.com/vercel-labs/skills).

## Активация

**В плагинах Koda** навыки включены по умолчанию, но перед этим их список нужно обновить вручную.

После установки, обновления или удаления навыков следует нажать кнопку обновления списка в панели **Навыки** (режим Агент).

Убедитесь, что навык отобразился в списке и переключатель напротив в зелёном положении.

**В koda-cli** требуется ручное включение навыков:

- при незапущенном `koda`: `koda skills enable <имя_навыка>`
- при запущенном `koda`:
  - `/skill reload`
  - `/skill enable <имя_навыка>`

Если вы не видите навык в списке `/skill list` (`koda skills list`), обновите список: `/skill reload`

## Формат SKILL.md

Каждый навык содержит YAML frontmatter с метаданными:

```yaml
---
name: skill-name          # Идентификатор (kebab-case, 1-64 символов)
description: "Описание"   # Когда срабатывает и что делает (1-1024 символов)
metadata:
  author: koda
  version: "1.0.0"
---
```

**Требования к имени**:
- ✅ Валидно: `code-review`, `sprint-planner`, `github-flow`
- ❌ Невалидно: `Code-Review` (верхний регистр), `-my-skill` (дефис в начале), `my--skill` (двойной дефис)

Имя навыка должно совпадать с именем его директории.

Файл `SKILL.md` обязателен: директория без него не считается навыком и не попадает в `metadata.json`.

### Дополнительные файлы навыка

По [спецификации Agent Skills](https://agentskills.io/specification) директория навыка может содержать любые файлы помимо `SKILL.md`. Для удобства рекомендуются следующие поддиректории:

- `scripts/` — исполняемые скрипты;
- `references/` — дополнительная документация, которую агент читает по необходимости;
- `assets/` — шаблоны, изображения и другие статические ресурсы.

Ссылки на дополнительные файлы указывайте относительными путями от корня навыка. Генератор `metadata.json` автоматически включает все файлы директории навыка, поэтому отдельно перечислять их не нужно.

## Обслуживание репозитория

### Автоматическое обновление

При пуше в ветку `main` или слияния pull-request срабатывает workflow `.github/workflows/update-metadata.yml`, который:

1. Запускает скрипт генерации `metadata.json` и проверяет результат по схеме `metadata-schema.json`
2. Создаёт коммит с обновлённым `metadata.json` (если есть изменения)
3. Использует сообщение вида: `Update metadata 2024-01-01T00:00:00Z`

### Команды Makefile

```bash
help            Показать справку по командам
install         Подготовить виртуальное окружение генератора
metadata        Запустить генерацию metadata.json
clean           Удалить виртуальное окружение генератора
```

### О файле metadata.json

Файл `metadata.json` содержит метаданные всех навыков репозитория и автоматически обновляется при пуше в ветку `main` через GitHub Actions.

Генератор включает в метаданные все файлы директории навыка: обязательный `SKILL.md`, а также дополнительные файлы из `scripts/`, `references/`, `assets/` и любые другие. Служебные файлы вроде `.DS_Store` и `__pycache__` пропускаются.

Директория считается навыком только при наличии `SKILL.md`. Директории без этого файла пропускаются и в `metadata.json` не попадают.

```json
{
  "skills": [
    {
      "name": "skill-name",
      "description": "Описание навыка",
      "license": "MIT",
      "compatibility": "Требуется Python 3.11 и доступ к сети",
      "metadata": {
        "author": "koda",
        "version": "1.0.0"
      },
      "allowed-tools": "read_file grep_search",
      "files": [
        {
          "name": "SKILL.md",
          "path": "skill-name",
          "url": {
            "web": "Ссылка на файл для просмотра в браузере",
            "raw": "Ссылка на сырое содержимое файла"
          },
          "revision": "66b9739416d786420d6d2e19b6c6b05f4bcc602d",
          "sha256": "da470071cd83482e7841967224bd045686f6687889b38a5741cc8867949c3e33",
          "size": 5249,
          "lastUpdate": "2026-07-21T09:27:18Z"
        },
        {
          "name": "REFERENCE.md",
          "path": "skill-name/references",
          "url": {
            "web": "Ссылка на файл для просмотра в браузере",
            "raw": "Ссылка на сырое содержимое файла"
          },
          "revision": "0f1c8a1b2c3d4e5f60718293a4b5c6d7e8f901a2",
          "sha256": "0f1c8a1b2c3d4e5f60718293a4b5c6d7e8f901a2b3c4d5e6f708192a3b4c5d6e",
          "size": 1024,
          "lastUpdate": "2026-07-20T10:03:57Z"
        }
      ]
    }
  ],
  "count": 10,
  "lastUpdate": "2024-01-01T00:00:00Z"
}
```

Поле `name` в элементе `files` содержит имя файла без пути, а `path` — директорию файла относительно `skills/` без имени файла. Полный путь в репозитории собирается как `skills/<path>/<name>`.

Необязательные поля frontmatter попадают в объект навыка, если они заданы в `SKILL.md`:

- `license` — название лицензии или ссылка на файл лицензии в директории навыка;
- `compatibility` — требования к окружению, до 500 символов;
- `metadata` — карта дополнительных свойств; в метаданные попадают только строковые значения, включая `author` и `version`;
- `allowed-tools` — имена заранее разрешённых инструментов через пробел.

Некорректные необязательные поля не отбрасывают навык: генератор пропускает такое поле и выводит предупреждение.

Отдельного поля `version` на уровне навыка нет: версия хранится в карте `metadata` и доступна как `metadata.version`.

Для проверки целостности каждый файл содержит `sha256` (хэш содержимого в шестнадцатеричном виде) и `size` (размер в байтах). Поле `lastUpdate` хранит дату последнего коммита, изменившего файл, в часовом поясе UTC; если история Git недоступна, используется время изменения файла.

Поле `revision` содержит хэш коммита, в котором файл последний раз изменялся. Поля `url.web` и `url.raw` привязаны к этому коммиту, поэтому после каждого изменения файла ссылки обновляются и всегда отдают ровно ту версию, для которой посчитан `sha256`. Для файлов, не отслеживаемых Git, поле `revision` отсутствует, а ссылки указывают на ветку `main`.

Генератор описывает закоммиченное состояние: `sha256`, `size`, `revision`, `lastUpdate` и frontmatter берутся из Git, а не из рабочей копии. Поэтому незакоммиченные правки попадут в `metadata.json` только после коммита; для файлов, которых ещё нет в Git, используются рабочая копия и ветка `main`.

Подробная схема описана в [./metadata-schema.json](./metadata-schema.json).
