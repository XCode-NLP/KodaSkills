# Разбор проекта WordPress

## Когда использовать

Используй этот навык, чтобы быстро понять, в каком репозитории WordPress ты
работаешь и каких команд и соглашений держаться до внесения изменений.

## Что нужно на входе

- Корень репозитория (текущая рабочая директория).

## Порядок работы

1. Запусти детектор (он печатает JSON в стандартный вывод):
   - `node skills/wp-project-triage/scripts/detect_wp_project.mjs`
2. Если нужен точный контракт вывода, прочитай:
   - `skills/wp-project-triage/references/triage.schema.json`
3. Используй отчёт, чтобы выбрать ограничения рабочего процесса:
   - тип (или типы) проекта;
   - наличие инструментов PHP и Node;
   - наличие тестов;
   - подсказки о версиях и их источники.
4. Если в отчёте нет нужных сигналов, обнови детектор, а не гадай.

## Проверка

- JSON должен разбираться и содержать `project.kind`, `signals` и `tooling`.
- Перезапусти детектор после изменений, влияющих на структуру и инструменты (добавил
  `theme.json`, `block.json`, конфигурацию сборки).

## Сбои и отладка

- Если детектор сообщает `unknown`, проверь, что корень репозитория верный.
- Если сканирование медленное, добавь или расширь список игнорируемых директорий в
  скрипте.
