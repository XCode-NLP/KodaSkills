# Оформление и отчётность

Этот справочник определяет, как подавать пользователю аналитические результаты на данных MPSTATS.

## Цель

Вывод MPSTATS должен выглядеть как аналитика маркетплейса, а не как дамп сырого API. Ответ должен помогать пользователю быстро принять решение:

- что происходит;
- почему это важно;
- что делать дальше.

## Структура ответа по умолчанию

Для большинства аналитических запросов используй такой порядок:

1. Короткий вывод.
2. Ключевые метрики.
3. Доказательства в таблицах и/или на графиках.
4. Интерпретация.
5. Риски, оговорки или следующие шаги.

Если задача простая, держи структуру компактной. Если задача похожа на отчёт, разворачивай её.

## Таблицы: когда они обязательны

Включай хотя бы одну таблицу, если в результате есть что-то из перечисленного:

- несколько товаров, продавцов, брендов или категорий;
- сравнение периодов;
- ценовая сегментация;
- рейтинги;
- сравнение ниш;
- сравнение продавцов или конкурентов;
- верхние строки на уровне SKU.

Хорошие примеры таблиц:

- топ продавцов по выручке;
- сравнение категорий или ниш;
- разбивка по ценовым корзинам;
- динамика по месяцам;
- сравнение 2–5 ниш-кандидатов.

Избегай гигантских таблиц. Обычно достаточно 5–15 строк, если пользователь не просил полный выгруз.

## Графики: когда их стоит включать

Включай график или блок, готовый под график, если в данных есть содержательный визуальный сигнал:

- временные ряды (`by_date`, тренды, прогнозы, сезонность);
- ценовая сегментация;
- доли рынка или концентрация продавцов;
- сравнение периодов;
- распределение выручки по корзинам или сущностям.

Рекомендуемые типы графиков:

- линейный график для выручки и продаж во времени;
- столбчатая диаграмма для топ продавцов, брендов, SKU или категорий;
- стековая столбчатая диаграмма для ценовой сегментации и разбивки долей;
- столбчатая диаграмма для сравнения периодов между собой.

Если итоговый канал не поддерживает отрисовку графиков, дай компактную текстовую интерпретацию и таблицу, которая ясно показывает ту же закономерность.

## Правила повествования

- Начинай с вывода, а не с механики извлечения данных.
- Не вставляй сырой JSON, если об этом не просили явно.
- Каждый блок метрик должен отвечать на вопрос «почему это важно».
- Обсуждая нишу, продавца или товар, показывай и возможность, и риск.
- В рекомендациях прямо говори, почему один вариант сильнее остальных.

## Стандарт HTML/PDF-отчёта

Если создаётся отдельный HTML- или PDF-отчёт, он должен следовать подаче в стиле MPSTATS.

### Принципы стиля MPSTATS

- Аналитика в первую очередь, а не рекламный буклет.
- Аккуратный гибрид дашборда и отчёта.
- Сильная иерархия информации.
- Блоки данных, карточки метрик, ясные разделители.
- Фирменная, но сдержанная графика.
- Фокус на решениях, а не на украшении.

### Ожидаемые разделы отчёта

Используй подходящее подмножество под задачу:

1. Заголовок и метаданные отчёта.
2. Резюме для руководства.
3. Методика и пометка об источнике данных.
4. Карточки KPI.
5. Основные разделы анализа.
6. Таблицы.
7. Графики.
8. Ключевые выводы.
9. Риски и оговорки.
10. Рекомендованные следующие шаги.

### Фирменная цветовая система MPSTATS

Отчёты ОБЯЗАНЫ использовать фирменную палитру MPSTATS: яркий зелёный на почти белом. **Значения ниже взяты из официального шаблона MPSTATS PPTX** — не подбирай приблизительно, используй точные hex-коды.

**Основная палитра:**

| Роль | Hex | Применение |
|------|-----|-------|
| Основной зелёный | `#17BF50` | Акцент, выделение заголовков, основной цвет графиков, декоративные сферы |
| Светлый акцентный зелёный | `#4DF085` | Подсветка внутри зелёных сфер, вторичные акценты |
| Чернильный (почти чёрный) | `#171B20` | Заголовки, основной текст на светлом фоне |
| Приглушённый текст | `#676F79` | Подписи, пояснения, подзаголовки, второстепенный текст |
| Линия (сильная) | `#D3D2D2` | Более заметные разделители, границы таблиц |
| Линия (мягкая) | `#DBE0E4` | Обводки карточек, тонкие разделители |
| Бумага | `#F9FAFB` | Фон карточек |
| Фон | `#F3F5F7` | Фон страницы и полотна |
| Белый | `#FFFFFF` | Внутренний фон контента, где нужно |
| Чистый чёрный | `#000000` | Логотип, только для текста с максимальным контрастом |

Фирменный шаблон НЕ использует красный, янтарный и «рисковые» цвета для украшения. В аналитике риск и предупреждение допустимы, но должны быть приглушены и использоваться скупо — это утилитарные цвета, а не фирменные:

| Роль | Hex | Применение |
|------|-----|-------|
| Риск (утилитарный) | `#C23B32` | Метки риска, только отрицательные изменения |
| Фон риска | `#FDEBEA` | Фон блока риска |
| Предупреждение (утилитарный) | `#C98900` | Только метки осторожности |
| Фон предупреждения | `#FFF5DA` | Фон блока предупреждения |

**Цвета графиков:**

Основная серия всегда `#17BF50`. Две серии: `#17BF50` против `#D3D2D2` (зелёный против приглушённого серого). Несколько серий, по порядку:

1. `#17BF50` — основная;
2. `#171B20` — чернильный (высокий контраст);
3. `#676F79` — приглушённый;
4. `#4DF085` — светлый акцент;
5. `#C98900` — янтарный (только если без пятой линии никак).

Бренд предпочитает монохромные графики (зелёный и нейтральные). НЕ вводи синий, фиолетовый или бирюзовый — это вне фирменного стиля.

**Шаблон CSS-переменных для HTML-отчётов:**

```css

  --bg: #F3F5F7;
  --paper: #F9FAFB;
  --card: #FFFFFF;
  --ink: #171B20;
  --muted: #676F79;
  --line: #DBE0E4;
  --line-strong: #D3D2D2;
  --accent: #17BF50;
  --accent-light: #4DF085;
  --good: #17BF50;
  --warn: #C98900;
  --warn-soft: #FFF5DA;
  --risk: #C23B32;

```

### Типографика

Фирменный шрифт — **Manrope** (переменный, начертания 400/600/700/800). Запасной стек: `Manrope, "Helvetica Neue", Arial, sans-serif`. Для данных и чисел Manrope хорошо работает на любых размерах; если нужна «табличная» моноширинность цифр, используй `font-variant-numeric: tabular-nums`.

**Шкала размеров** (взята из шаблона, в pt и в эквивалентах px для HTML при 96 DPI):

| Роль | Размер | Начертание | Заметки |
|---|---|---|---|
| Главная метрика / крупное число | 60–80pt (80–110px) | 800 | Карточки KPI, заголовочные метрики |
| Заголовок раздела | 45–50pt (60–67px) | 700 | Заголовки страниц, заголовки разборов |
| Подзаголовок | 22–30pt (30–40px) | 700 | Заголовки блоков и графиков |
| Крупный текст | 18–22pt (24–30px) | 600 | Вводные абзацы, врезки |
| Основной текст | 12–15pt (16–20px) | 400–600 | Основной текст, строки таблиц |
| Подпись / метка | 9–11pt (12–15px) | 600 прописными или 400 | Подписи осей, заголовки таблиц, колонтитулы |

Основной текст: межстрочный интервал 1,4–1,5. Заголовки: 1,1–1,2. Межбуквенный интервал у подписей и меток: `0.04em` прописными.

### Контент никогда не должен обрезаться

HTML-отчёты текут — это **не** слайды фиксированного размера. «Слайд» в этом стиле — широкая скруглённая карточка на странице, а не коробка 16:9 с жёсткими краями. Поэтому:

- используй `min-height: 720px; height: auto` (никогда `height: 720px`) для контейнера карточки;
- никогда не ставь `overflow: hidden` на карточку — переполнение означает ошибку вёрстки, а не то, что надо маскировать;
- размещай метаданные колонтитула в обычном потоке (`margin-top: auto` внутри flex-колонки), а не через `position: absolute` — абсолютный колонтитул наезжает на контент, как только тот вырастает;
- если контент не вписывается визуально сбалансированно, **уменьшай контент** (короче примечание, меньше врезка, меньше прозы), а не контейнер;
- внутри двухколоночных макетов ставь `align-items: stretch`, чтобы колонки совпадали по высоте; не фиксируй высоты колонок через `calc()` относительно родителя.

Если ты видишь макет, которому для правильного вида нужен `overflow: hidden`, — макет неверный, исправляй макет. Никогда не соглашайся на обрезанный текст, особенно числа, пометки об аномалиях и сноски: именно это пользователю и нужно прочитать.

### Экспорт в PDF — правила постраничной разбивки (обязательны)

Если отчёт будет печататься или выгружаться в PDF (через `print`, `puppeteer`, `weasyprint`, `prince` и т. п.), браузеры по умолчанию **не** сохраняют фоны, **не** держат карточки вместе и разрывают таблицы посреди строки. Ты обязан явно добавить печатный CSS.

**Правила:**

- **Один `.slide` = одна страница.** Каждый слайд получает `page-break-after: always` / `break-after: page`. Задай `@page { size: 1280px 720px; margin: 0 }` под полотно слайда (или `size: A4 landscape; margin: 0`, если удобнее бумажный формат).
- **Фоны должны печататься.** Используй `print-color-adjust: exact` и префикс `-webkit-` на `html, body` и `body *`. Без этого браузеры срезают фоны карточек, заливки врезок и декоративные сферы.
- **Карточки, блоки и врезки никогда не разрываются.** Применяй `break-inside: avoid` (и `page-break-inside: avoid` для совместимости) к `.kpi`, `.block`, `.callout`, `.table-note`.
- **Строки таблиц не разрываются, заголовки повторяются.** Задай `thead { display: table-header-group }`, `tfoot { display: table-footer-group }`, `tr { break-inside: avoid }`. Если таблица идёт через страницы, заголовок повторяется на каждой.
- **Фиксируй размеры слайда для печати.** В `@media print` закрепи `.slide { width: 1280px; height: 720px; min-height: 720px; box-shadow: none; border-radius: 0 }`. Скруглённая карточка — для экрана; на печатной странице карточкой является сама страница.
- **Убери последний разрыв страницы.** `.slide:last-of-type { break-after: auto }` предотвращает пустую страницу в конце.

**Обязательный блок печатного CSS (скопируй дословно в `<style>` отчёта):**

```css
@page {
  size: 1280px 720px;
  margin: 0;
}

@media print {
  html, body {
    background: var(--paper);
    -webkit-print-color-adjust: exact;
    print-color-adjust: exact;
  }
  body * { -webkit-print-color-adjust: exact; print-color-adjust: exact; }

  .slide {
    margin: 0;
    width: 1280px;
    height: 720px;
    min-height: 720px;
    box-shadow: none;
    border-radius: 0;
    page-break-after: always;
    break-after: page;
    page-break-inside: avoid;
    break-inside: avoid;
  }
  .slide:last-of-type { page-break-after: auto; break-after: auto; }

  .kpi, .block, .callout, .table-note { break-inside: avoid; page-break-inside: avoid; }

  thead { display: table-header-group; }
  tfoot { display: table-footer-group; }
  tr     { break-inside: avoid; page-break-inside: avoid; }
}
```

**Вписывание контента:** в экранном режиме слайд растёт под контентом (`min-height: 720px`, см. «Контент никогда не должен обрезаться»), в печатном — жёстко закреплён за одной страницей. Поэтому **каждый слайд должен вписываться в одно полотно 1280×720**. Если на экране он не вписывается при таком размере, PDF обрежет — решай на уровне контента (разбей на два слайда, уменьши врезки, сократи строки таблицы), но никогда за счёт увеличения печатной страницы.

**Рекомендуемые команды экспорта:**

```bash
# Chrome / Chromium headless (лучшая точность с веб-шрифтами, SVG-графиками и сферами)
chrome --headless --disable-gpu --no-margins \
       --print-to-pdf=report.pdf --print-to-pdf-no-header \
       --no-pdf-header-footer file://"$PWD"/report.html

# Puppeteer (Node) — передай { printBackground: true, preferCSSPageSize: true }
# WeasyPrint (Python) — понимает @page и свойства break-* из коробки
```

Всегда передавай флаг, эквивалентный `printBackground: true` / `--no-margins`, иначе движок печати срежет фоны и добавит свои колонтитулы.

### Визуальный мотив: светлая карточка и зелёные 3D-сферы

Фирменный почерк — **мягко отрендеренные 3D-сферы и листья** в углах светлой скруглённой карточки на почти белом фоне. Это и есть узнаваемый облик MPSTATS — плоские зелёные градиенты НЕ являются фирменным стилем.

**Рецепт обложки и первого экрана:**

- Фон страницы: `#F3F5F7`.
- Центрированная скруглённая карточка: `#F9FAFB`, `border-radius: 24-32px`, мягкая тень `0 8px 24px rgba(23,27,32,0.04)`.
- 3D-сферы в 2–3 углах карточки (слева сверху, справа сверху, справа снизу). Сферы объёмные с деликатным бликом; часть — с текстурой вроде сетки. Это настоящие рендеры, а не CSS-градиенты — используй готовые PNG/SVG, когда они есть.
- Логотип `mpstats` в левом верхнем углу карточки (зелёный квадратный знак и чёрный текст).
- Заголовок: 60–80pt, начертание 800, `#171B20`, по левому краю.
- Подзаголовок: 22–30pt, `#676F79`, обычное начертание, ниже заголовка с `margin-top: 16px`.

Если готовых 3D-сфер нет, используй **запасной вариант**: небольшие скопления перекрывающихся кругов в `#17BF50` / `#4DF085` с `filter: blur(4px)` и `opacity: 0.7-0.9`. Ставь их по углам и никогда поверх области контента.

**Рецепт раздела и контентной страницы:**

- Тот же фон `#F3F5F7`, та же скруглённая карточка, но с **приглушёнными сферами** (только 1–2, меньше, в одном углу), чтобы они не спорили с данными.
- Верхняя строка: номер раздела, заголовок раздела и метаданные страницы (дата, источник) справа.
- Контентная сетка: 2–3 колонки карточек KPI либо широкий блок графика и более узкая колонка комментария.

**Избегай:**

- линейных градиентных баннеров на первом экране (старый вид `linear-gradient(135deg, #004D26 → #00B956)` неверен — это НЕ этот бренд);
- синих, фиолетовых и бирюзовых акцентов;
- нескольких конкурирующих декоративных элементов на одном слайде;
- тяжёлых теней и глассморфизма;
- тёмных фонов страниц (бренд светлый в первую очередь).

### Рецепт карточки KPI

```
.kpi {
  background: var(--card);
  border: 1px solid var(--line);
  border-radius: var(--radius-block);
  padding: 24px 28px;
}
.kpi__label { color: var(--muted); font-size: 13px; font-weight: 600; text-transform: uppercase; letter-spacing: 0.04em; }
.kpi__value { color: var(--ink); font-size: 56px; font-weight: 800; line-height: 1.05; margin-top: 8px; }
.kpi__delta--up { color: var(--accent); font-weight: 700; }
.kpi__delta--down { color: var(--risk); font-weight: 700; }
```

Используй компактные сетки: 3–4 KPI в ряд, одинаковая ширина, `gap: 16-20px`.

### Рецепт таблицы

- Строка заголовков: `background: transparent; color: var(--muted); font-size: 12px; text-transform: uppercase; letter-spacing: 0.04em; border-bottom: 1px solid var(--line-strong); padding: 12px 16px;`.
- Строки тела: `border-bottom: 1px solid var(--line); padding: 14px 16px; color: var(--ink);`.
- Числовые колонки: по правому краю, `font-variant-numeric: tabular-nums`.
- Строка первой сущности: без особого выделения; опирайся на порядок, а не на цвет.
- Изменения: `▲` в `#17BF50`, `▼` в `#C23B32`, оба 12–13px рядом с числом.
- Без чередования фона строк. Без вертикальных линий сетки. Границы только между строками.

### Рецепт графика

- Одноерийный график во времени: линия `#17BF50`, толщина `2.5px`, заливка под ней `#17BF50` с `opacity: 0.08`.
- Оси: `#DBE0E4`, `1px`.
- Текст осей: `#676F79`, `11-12px`, начертание 500.
- Сетка: только горизонтальная, `#DBE0E4` с `opacity: 0.6`.
- Заголовок над графиком: 18–22px, начертание 700, `#171B20`.
- Подзаголовок и пояснение: 12–13px, `#676F79`.
- Легенда: образцы `10×10px` со скруглением 2px, подписи 12px `#171B20`.
- Без 3D, без теней у столбцов и линий, без второй оси, если она явно не нужна.

### Блок вывода и врезка

```
.callout {
  background: rgba(23, 191, 80, 0.06);   /* подкрашено --accent */
  border-left: 3px solid var(--accent);
  border-radius: 8px;
  padding: 16px 20px;
  color: var(--ink);
}
.callout__label { color: var(--accent); font-size: 12px; font-weight: 700; text-transform: uppercase; letter-spacing: 0.04em; margin-bottom: 4px; }
```

Для врезок о риске замени `--accent` на `--risk`, фон — `rgba(194, 59, 50, 0.05)`. Используй их только когда действительно отмечаешь риск, а не для украшения.

## Минимальные правила вывода по типу задачи

### Быстрый фактический ответ

- короткое резюме;
- одна небольшая таблица, если строк несколько.

### Сравнительный анализ

- рекомендация в начале;
- обязательная таблица сравнения;
- график, если есть данные о тренде или долях.

### Исследование ниши или товара

- резюме о возможности;
- таблица с ключевыми метриками;
- хотя бы один вид тренда или сегментации, когда он доступен;
- явные риски и соображения о входе.

### Разбор продавца или бренда

- главный вывод;
- таблица KPI;
- таблица ведущих сущностей;
- график динамики во времени, если он есть.

### Запрос полного отчёта

- HTML или PDF уместен;
- включи карточки KPI, таблицы и графики, где это применимо;
- стиль должен следовать принципам отчётов MPSTATS выше.
