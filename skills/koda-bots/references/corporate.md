# Корпоративные платформы: MS Teams, Google Chat, Webex

Общее для всех трёх: бот живёт в организации, доступ выдаётся администратором, а публикация в каталоге требует проверки. Это меняет порядок работ — сначала согласования, потом код.

## Microsoft Teams

Документация: <https://learn.microsoft.com/en-us/microsoftteams/platform/bots/what-are-bots>.
Teams SDK: <https://learn.microsoft.com/en-us/microsoftteams/platform/teams-sdk/getting-started/quickstart>.
Microsoft 365 Agents Toolkit: <https://learn.microsoft.com/en-us/microsoftteams/platform/toolkit/teams-toolkit-fundamentals>.

### Состояние стека

Microsoft активно перестраивает инструменты, и в названиях легко запутаться. На ноябрь 2026 года:

- **Teams AI library** переименована в **Teams SDK**. Версия Teams AI library v1 объявлена устаревшей.
- **Teams SDK** общедоступна для JavaScript и C#, для Python — в статусе developer preview.
- **Bot Framework SDK** по-прежнему поддерживается, но Microsoft направляет новые проекты в Microsoft 365 Agents SDK.
- **Microsoft 365 Agents Toolkit** — прежний Teams Toolkit, инструмент создания и развёртывания.

Перед началом работы уточни, какой стек принят в организации заказчика. Смешивать Bot Framework и Teams SDK в одном боте не стоит.

### Области развёртывания

Бот работает в одном или нескольких контекстах:

- **личный чат** — один на один с пользователем;
- **групповой чат** — несколько участников;
- **канал команды** — обсуждение в команде.

Возможности различаются: часть типов карточек и упоминаний ведёт себя по-разному в канале и в личном чате.

### Ключевые понятия

- **Activity handler** — обрабатывает события: сообщения, упоминания, вход и выход участников, нажатия на карточки, ошибки.
- **Conversation** — диалог с историей и состоянием.
- **Bot logic** — правила и условия, определяющие ответ.

### Карточки

Основной способ сделать настраиваемый интерфейс — **Adaptive Cards**: JSON-структура с текстом, полями ввода, кнопками и действиями. Вёрстку проверяй в Adaptive Cards Designer, а поведение — в реальном клиенте: Teams и веб-версия отображают некоторые элементы по-разному.

### Доступ и публикация

- Для внутреннего использования приложение загружается в каталог организации администратором.
- Для публикации в общем каталоге Teams нужна проверка Microsoft.
- Разрешения запрашиваются через Microsoft Entra ID; лишние scopes усложняют согласование.
- Бот не может писать пользователю первым, пока тот не установил приложение или не начал диалог.

### SDK

| Язык                    | Пакет                           |
|-------------------------|---------------------------------|
| JavaScript / TypeScript | `botbuilder`                    |
| Python                  | `botbuilder-core`               |
| C#                      | `Microsoft.Bot.Builder`         |
| Java                    | `com.microsoft.bot:bot-builder` |

### Особенности

- Локальная отладка требует туннеля к публичному HTTPS-адресу либо использования средств Agents Toolkit.
- Токены и идентификаторы арендатора берутся из конфигурации приложения Entra ID.
- Проверяй подпись входящих запросов: Bot Framework использует JWT, а не HMAC.
- Для уведомлений без диалога используй входящий вебхук или Connector, но помни, что это не бот.

## Google Chat

Документация REST API: <https://developers.google.com/workspace/chat/api/reference/rest>.
Обзор для разработчиков: <https://developers.google.com/workspace/chat/quickstart/webhooks>.

### Модель

Приложение Google Chat — это сервисный аккаунт или OAuth-клиент с доступом к Chat API. Базовый адрес — `https://chat.googleapis.com`, версия API — `v1`.

Официального SDK именно для Chat нет. Работают через `google-api-python-client` и `googleapis`, то есть через общий REST-клиент Google.

### Ресурсы

| Ресурс                           | Назначение                                       |
|----------------------------------|--------------------------------------------------|
| `v1.spaces`                      | Пространства: создание, список, поиск, настройка |
| `v1.spaces.members`              | Участники пространства                           |
| `v1.spaces.messages`             | Сообщения: создание, изменение, удаление, поиск  |
| `v1.spaces.messages.attachments` | Вложения                                         |
| `v1.spaces.messages.reactions`   | Реакции                                          |
| `v1.spaces.threads`              | Обсуждения внутри пространства                   |
| `v1.spaces.spaceEvents`          | События пространства                             |
| `v1.media`                       | Загрузка и скачивание медиа                      |

Ключевые методы:

- `POST /v1/{parent=spaces/*}/messages` — отправить сообщение;
- `PATCH /v1/{message.name=spaces/*/messages/*}` — изменить;
- `POST /v1/{name=spaces/*/messages/*}:replaceCards` — заменить карточки в сообщении;
- `GET /v1/spaces:findDirectMessage` — найти личный чат с пользователем;
- `POST /upload/v1/{parent=spaces/*}/attachments:upload` — загрузить вложение.

### Два способа получать события

1. **Вебхук в пространстве** — самый простой путь для уведомлений. Адрес выдаётся в настройках пространства, авторизация не нужна, но и приём сообщений недоступен: только отправка.
2. **HTTP-эндпоинт приложения Chat** — полноценный бот, который принимает события и отвечает. Требует настройки в консоли Google Cloud и проверки подлинности запросов.

Для интерактивного бота нужен второй вариант. Вебхук годится для оповещений из CI, мониторинга и других односторонних сценариев.

### Карточки

Сообщения с карточками — JSON v2 (`cardsV2`). Кнопки присылают действия на эндпоинт приложения. Старый формат карточек v1 считается устаревшим.

### Особенности

- Приложение работает в контексте рабочего пространства Google Workspace; личные аккаунты не поддерживаются.
- Публикация в Marketplace требует проверки Google.
- Для доступа к пространствам нужны соответствующие scopes и добавление приложения в пространство.
- Проверяй подлинность запросов: Google подписывает их JWT-токеном, а не общим секретом.

## Webex

Документация REST API: <https://developer.webex.com/docs/api/basics>.
Боты: <https://developer.webex.com/docs/bots>.

### Модель

- Базовый адрес — `https://webexapis.com/v1/`.
- Авторизация — `Authorization: Bearer <access token>`.
- Для бота регистрируется отдельная учётная запись бота, у неё свой токен.

Ключевые методы:

| Метод                   | Назначение          |
|-------------------------|---------------------|
| `POST /v1/messages`     | Отправить сообщение |
| `GET /v1/messages`      | Список сообщений    |
| `GET /v1/contents/{id}` | Скачать вложение    |
| `GET /v1/rooms`         | Список пространств  |
| `POST /v1/memberships`  | Добавить участника  |

### Отправка сообщений и вложений

- Вложение — до **100 МБ** на файл.
- Локальный файл отправляется как `multipart/form-data` с полем `files`.
- Удалённый файл передаётся ссылкой в массиве `files`, по одной ссылке за запрос.
- Webex показывает предпросмотр для PDF, DOC, DOCX, XLS, XLSX, PPT, PPTX, JPG, BMP, GIF, PNG.
- Метаданные файла можно получить запросом `HEAD /v1/contents/{id}`.

### Разметка

Форматирование передаётся в поле `markdown`, поддерживается ограниченное подмножество: жирный, курсив, ссылки, упорядоченные и неупорядоченные списки с вложенностью, цитаты, инлайн-код, блоки кода.

Переносы строк задаются через `\n`: два подряд для нового абзаца, два пробела и один `\n` для разрыва строки.

Упоминания:

- `<@personEmail:user@example.com|Имя>`;
- `<@personId:...|Имя>`;
- `<@all>` для всех.

### Ограничения частоты

Точные политики не документированы: Webex прямо пишет, что правила дробные и пересекаются. Ориентиры из документации:

- большинство REST-методов — около **300 запросов в минуту**;
- `/people` и `/messages` имеют повышенную квоту, которая настраивается динамически;
- при превышении возвращается `429` с заголовком `Retry-After`.

Рекомендации Webex: не использовать учётные записи живых сотрудников для больших объёмов, брать отдельный служебный аккаунт или аккаунт бота, разносить параллельные нагрузки по разным пользователям, так как лимиты считаются на пользователя.

### Безопасность файлов

Организация может включить антивирусную проверку. Тогда возможны ответы:

- `423 Locked` — файл на проверке, ждать по `Retry-After`;
- `410 Gone` — файл заражён, скачивание запрещено;
- `428 Precondition Required` — файл не сканируется (например, зашифрован); запрос с `allow=unscannable` снимает блокировку, но ответственность переходит на вас.

### Особенности

- Бот не может писать в пространство, куда его не добавили.
- Для больших рассылок лучше несколько служебных аккаунтов, чем один.
- Проверяй подлинность входящих вебхуков, если используешь их для событий.

## Что общего

1. **Администратор нужен на старте.** Без согласования приложения в арендаторе бот не запустится.
2. **Публикация — отдельный проект.** Проверка в каталоге занимает время и требует описаний, политики конфиденциальности и иконок.
3. **Авторизация — не HMAC.** Teams и Google Chat проверяют JWT, а не общий секрет, как Slack. Не переноси шаблон проверки из Slack.
4. **Карточки — основной интерфейс.** Adaptive Cards и Google Chat Cards v2 требуют отдельного тестирования в реальных клиентах.
5. **Вложения ограничены и проверяются.** Учитывай антивирусную проверку и лимиты размера.
6. **Личные данные под контролем.** Корпоративные платформы чувствительны к утечкам: не логируй содержимое переписки и не отправляй данные во внешние сервисы без разрешения.
