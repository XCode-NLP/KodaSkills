# WhatsApp

Официальная документация:

- Cloud API: <https://developers.facebook.com/docs/whatsapp/cloud-api>
- Справочник Messages API: <https://developers.facebook.com/docs/whatsapp/cloud-api/reference/messages>
- Сервисные сообщения и окно обслуживания: <https://developers.facebook.com/docs/whatsapp/cloud-api/guides/send-messages>
- Лимиты рассылки: <https://developers.facebook.com/docs/whatsapp/messaging-limits>
- Политика: <https://business.whatsapp.com/policy>

Сверено с документацией Meta в ноябре 2026 года, актуальная версия API в примерах — `v27.0`.

## Официальный и неофициальный путь

| Путь                                             | Что это                                                         | Риски                                                                                  |
|--------------------------------------------------|-----------------------------------------------------------------|----------------------------------------------------------------------------------------|
| **Cloud API** (официальный)                      | HTTP API Meta, номер регистрируется в WhatsApp Business Account | Требует бизнес-аккаунта, верификации и утверждения шаблонов; зато нет риска блокировки |
| **On-premises API**                              | Прежнее решение Meta, размещалось у клиента                     | Meta сворачивает поддержку, новые проекты начинать не стоит                            |
| **Twilio, 360dialog и подобные**                 | Провайдеры поверх Cloud API                                     | Проще старт, дороже и меньше контроля                                                  |
| **`baileys`, `whatsapp-web.js`** (неофициальные) | Эмуляция клиента WhatsApp Web                                   | Нарушают условия использования, номер могут заблокировать без предупреждения           |

Для продуктивной среды используй Cloud API. Неофициальные библиотеки годятся только для личных экспериментов, и предупреди пользователя об этом явно, прежде чем писать код.

## Что нужно для старта

1. Аккаунт Meta for Developers и приложение типа Business.
2. WhatsApp Business Account (WABA) и номер телефона, не привязанный к обычному WhatsApp.
3. Верификация бизнеса — без неё ограничены лимиты и число получателей.
4. Постоянный токен доступа системного пользователя: временный живёт сутки и для продуктивной среды не годится.
5. Публичный HTTPS-эндпоинт для вебхука.

## Эндпоинты

Базовый адрес — `https://graph.facebook.com`. Версию API указывай в пути явно и фиксируй в конфигурации: Meta выпускает новые версии и снимает старые.

| Метод  | Путь                                             | Назначение                            |
|--------|--------------------------------------------------|---------------------------------------|
| `POST` | `/{Version}/{Phone-Number-ID}/messages`          | Отправить сообщение                   |
| `POST` | `/{Version}/{Phone-Number-ID}/media`             | Загрузить медиа                       |
| `GET`  | `/{Version}/{Media-ID}`                          | Получить метаданные и ссылку на медиа |
| `POST` | `/{Version}/{Phone-Number-ID}/message_templates` | Создать шаблон                        |
| `GET`  | `/{Version}/{WABA-ID}/message_templates`         | Список шаблонов                       |
| `POST` | `/{Version}/{Phone-Number-ID}/register`          | Зарегистрировать номер                |

Обязательные поля тела запроса: `messaging_product` (`whatsapp`), `recipient_type` (`individual` или `group`), `to` (номер или идентификатор группы), `type` и объект с тем же именем, что `type`.

```bash
curl -X POST \
  "https://graph.facebook.com/v27.0/${PHONE_NUMBER_ID}/messages" \
  -H "Authorization: Bearer ${WHATSAPP_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "messaging_product": "whatsapp",
    "recipient_type": "individual",
    "to": "+79001234567",
    "type": "text",
    "text": { "preview_url": false, "body": "Здравствуйте! Это бот компании." }
  }'
```

Ответ означает только то, что запрос **принят**, а не что сообщение доставлено. Статус доставки приходит отдельными событиями вебхука.

Номера указывай с плюсом и кодом страны. Если плюс опущен, Meta подставит код страны твоего бизнес-номера, и сообщение может уйти не тому получателю.

## 24-часовое окно обслуживания

Когда пользователь пишет или звонит, открывается 24-часовое окно обслуживания (customer service window). Каждое новое сообщение или звонок пользователя сбрасывает таймер на 24 часа.

Внутри окна можно отправлять **сервисные сообщения** свободной формы. Когда окно закрыто, разрешены только заранее утверждённые **шаблоны**.

Следствия для архитектуры:

1. Уведомления, рассылки и напоминания строятся на шаблонах, а не на свободном тексте.
2. Шаблон утверждается заранее и меняется только через повторную проверку.
3. Переменные в шаблоне передаются массивом `parameters` и подставляются в текст.
4. Категория шаблона (маркетинг, утилиты, аутентификация) влияет на тарификацию и на вероятность отклонения.
5. Храни время последнего сообщения пользователя, чтобы не отправлять заведомо отклоняемый запрос.

Meta отдельно предупреждает о редкой известной проблеме: сообщение от пользователя приходит, но ответить в окне не удаётся. Обрабатывай ошибку и сообщай пользователю, а не повторяй запрос в цикле.

## Типы сообщений

По справочнику Messages API поддерживаются:

| Тип                                              | Что содержит                         | Примечание                        |
|--------------------------------------------------|--------------------------------------|-----------------------------------|
| `text`                                           | `body`, `preview_url`                | Простой текст                     |
| `image`, `video`, `document`, `audio`, `sticker` | Медиа по `id` или `link`, подпись    | Стикер — только WebP              |
| `location`                                       | Широта, долгота, название, адрес     | —                                 |
| `contacts`                                       | Карточки контактов                   | —                                 |
| `reaction`                                       | Реакция на предыдущее сообщение      | —                                 |
| `interactive`                                    | Кнопки, список, Flow, каталог, товар | Тип задаётся в `interactive.type` |
| `template`                                       | Утверждённый шаблон с параметрами    | Только так можно писать вне окна  |

`interactive.type` принимает значения `button`, `list`, `flow`, `product`, `product_list`, `catalog_message`, `call_permission_request`. Быстрые ответы — до трёх кнопок. В списке заголовок раздела ограничен 24 символами.

## Вебхук

Подписка настраивается в кабинете приложения Meta. Проверка адреса выполняется один раз:

1. Meta отправляет `GET` с параметрами `hub.mode`, `hub.verify_token`, `hub.challenge`.
2. Сверь `hub.verify_token` со своим значением.
3. Верни `hub.challenge` как есть, простым текстом и со статусом `200`.

События приходят методом `POST`. Каждый запрос подписан заголовком `X-Hub-Signature-256` — это HMAC-SHA256 от **сырого тела** запроса с ключом из app secret.

```python
import hashlib
import hmac


def verify_signature(raw_body: bytes, signature_header: str, app_secret: str) -> bool:
    """Проверяет X-Hub-Signature-256. Сравнение за постоянное время."""
    if not signature_header or not signature_header.startswith("sha256="):
        return False
    expected = hmac.new(app_secret.encode(), raw_body, hashlib.sha256).hexdigest()
    received = signature_header.removeprefix("sha256=")
    return hmac.compare_digest(expected, received)
```

Важно: подпись считается по сырому телу, до разбора JSON. Если фреймворк уже распарсил тело, возьми исходные байты — иначе подпись не сойдётся.

Форма события: `entry[].changes[].value` содержит `messaging_product`, `metadata` и `messages` либо `statuses`. Статусы (`sent`, `delivered`, `read`, `failed`) приходят отдельными событиями и нужны для отслеживания доставки. Подпишись на топик `messages`, иначе статусов не будет.

## Медиа

1. Загрузи файл через `POST /{Phone-Number-ID}/media` с типом MIME и получи `id`.
2. Отправь сообщение с этим `id` в поле соответствующего типа.
3. Входящие медиа приходят как `id`; чтобы скачать, сначала запроси `GET /{Media-ID}` и получи ссылку, затем скачай её с тем же токеном.

Ссылки на медиа временные: сохраняй файл к себе, если он нужен позже. Имя файла и MIME-тип проверяй сам, не доверяй данным отправителя.

## Лимиты и качество номера

- Пропускная способность зависит от качества номера и растёт по мере успешной работы. Актуальные уровни — в разделе «Лимиты рассылки» из списка выше.
- Качество считается по отзывам за последние семь дней с учётом свежести: блокировки, жалобы, отключения уведомлений, архивирование.
- Ошибка `429` означает превышение частоты: используй очередь и задержку.
- Коды ошибок смотри в справочнике Meta: `131026` — получатель недоступен, `131047` — окно закрыто, `132000` — неверные параметры шаблона.

## Опт-ин и правила

1. Отправляй сообщения только тем, кто дал согласие, и фиксируй факт согласия.
2. В первом сообщении объясни, кто пишет и как отписаться.
3. Обрабатывай отказы: слово «стоп» и подобное должно прекращать рассылку.
4. Не отправляй маркетинг в шаблонах категории «утилиты»: Meta отклоняет такие шаблоны и может ограничить аккаунт.
5. Не покупай базы номеров: жалобы быстро снижают качество номера.
6. Избегай открытых приветственных сообщений без конкретики — Meta прямо называет их в списке рекомендаций по качеству.

## Пример на Python

```python
import os

import httpx

API_VERSION = "v27.0"
PHONE_NUMBER_ID = os.environ["WHATSAPP_PHONE_NUMBER_ID"]
TOKEN = os.environ["WHATSAPP_TOKEN"]


async def send_text(to: str, body: str) -> dict:
    url = f"https://graph.facebook.com/{API_VERSION}/{PHONE_NUMBER_ID}/messages"
    payload = {
        "messaging_product": "whatsapp",
        "recipient_type": "individual",
        "to": to,
        "type": "text",
        "text": {"preview_url": False, "body": body},
    }
    async with httpx.AsyncClient(timeout=15) as client:
        response = await client.post(
            url,
            json=payload,
            headers={"Authorization": f"Bearer {TOKEN}"},
        )
        response.raise_for_status()
        return response.json()
```

## Пример на TypeScript

```ts
const API_VERSION = 'v27.0';
const phoneNumberId = process.env.WHATSAPP_PHONE_NUMBER_ID!;
const token = process.env.WHATSAPP_TOKEN!;

export async function sendText(to: string, body: string) {
  const response = await fetch(
    `https://graph.facebook.com/${API_VERSION}/${phoneNumberId}/messages`,
    {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${token}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        messaging_product: 'whatsapp',
        recipient_type: 'individual',
        to,
        type: 'text',
        text: { preview_url: false, body },
      }),
    },
  );

  if (!response.ok) {
    throw new Error(`WhatsApp API ${response.status}: ${await response.text()}`);
  }

  return response.json();
}
```

## Тестирование

- В кабинете Meta есть тестовый номер и список получателей для отладки.
- Проверь подтверждение вебхука с неверным `hub.verify_token`.
- Проверь запрос с испорченной подписью — должен быть отказ.
- Проверь повторную доставку одного события: дедуплицируй по `messages[].id`.
- Проверь отправку вне 24-часового окна: должна быть ошибка, а не молчаливый пропуск.
- Проверь шаблон с недостающим числом параметров.

## Частые ошибки

| Симптом                  | Причина                                          | Решение                                  |
|--------------------------|--------------------------------------------------|------------------------------------------|
| `401` на все запросы     | Временный токен истёк                            | Постоянный токен системного пользователя |
| `131047`                 | Окно обслуживания закрыто                        | Отправляй утверждённый шаблон            |
| `132000`                 | Число параметров шаблона не совпало              | Сверь шаблон и массив `parameters`       |
| Вебхук не подтверждается | Неверный `hub.verify_token` или ответ не текстом | Верни `hub.challenge` как plain text     |
| Подпись не сходится      | Считаешь по распарсенному телу                   | Бери сырые байты запроса                 |
| Медиа не скачивается     | Ссылка устарела                                  | Запрашивай `GET /{Media-ID}` заново      |
| Нет статусов доставки    | Не подписан топик `messages`                     | Подпишись на события сообщений           |
| Шаблон отклонён          | Категория не соответствует содержанию            | Пересмотри категорию и формулировку      |
| Номер заблокирован       | Неофициальная библиотека                         | Переходи на Cloud API                    |
