# Telegram

Официальная документация: <https://core.telegram.org/bots/api>.
Проверяй актуальные лимиты и поля перед реализацией: Bot API меняется чаще, чем большинство других платформ.

## Что понадобится

1. Создай бота у `@BotFather` и получи токен.
2. Включи нужные возможности: inline-режим, платежи, мини-приложение, группы.
3. Для мини-приложения настрой HTTPS-адрес через BotFather или `setChatMenuButton`.
4. Для платежей подключи платёжного провайдера и получи токен провайдера.

## Доставка обновлений

| Способ                      | Когда использовать                                        | Особенности                                                           |
|-----------------------------|-----------------------------------------------------------|-----------------------------------------------------------------------|
| Long polling (`getUpdates`) | Локальная разработка, небольшой бот, нет публичного HTTPS | Не требует домена; один экземпляр на токен; задержка и лишний трафик  |
| Вебхук (`setWebhook`)       | Продакшен                                                 | Нужен HTTPS и публичный домен; Telegram повторяет доставку при ошибке |

При вебхуке указывай `secret_token` и проверяй заголовок `X-Telegram-Bot-Api-Secret-Token`.
Ограничь `allowed_updates`, чтобы не получать лишние типы обновлений.
Возвращай `200` быстро, а тяжёлую работу выноси в очередь.

```python
import os

from aiogram import Bot
from aiogram.webhook.aiohttp_server import SimpleRequestHandler, setup_application
from aiohttp import web

WEBHOOK_PATH = "/telegram/webhook"
WEBHOOK_SECRET = os.environ["TELEGRAM_WEBHOOK_SECRET"]

async def on_startup(app: web.Application) -> None:
    await app["bot"].set_webhook(
        url=f"{os.environ['PUBLIC_BASE_URL']}{WEBHOOK_PATH}",
        secret_token=WEBHOOK_SECRET,
        allowed_updates=["message", "callback_query"],
    )

def create_app(bot: Bot, dp) -> web.Application:
    app = web.Application()
    app["bot"] = bot
    SimpleRequestHandler(dispatcher=dp, bot=bot, secret_token=WEBHOOK_SECRET).register(app, path=WEBHOOK_PATH)
    setup_application(app, dp, bot=bot)
    app.on_startup.append(on_startup)
    return app
```

## Библиотеки

| Язык       | Библиотека                | Когда выбирать                                                    |
|------------|---------------------------|-------------------------------------------------------------------|
| Python     | `aiogram` 3.x             | Асинхронный бот, роутеры, фильтры, FSM, мини-приложения           |
| Python     | `python-telegram-bot` 21+ | Асинхронный бот с `Application`, удобные обработчики и `JobQueue` |
| TypeScript | `grammY`                  | Типизированный бот, middleware, удобная работа с контекстом       |
| TypeScript | `telegraf`                | Зрелый бот с большим числом плагинов                              |
| Go         | `go-telegram-bot-api`     | Простой бот без лишних зависимостей                               |

Не смешивай библиотеки и не оборачивай одну в другую без причины.

## Команды и фильтры

- Команды регистрируй через `setMyCommands`, иначе пользователь не увидит подсказку.
- В группах команда приходит с суффиксом `@botname`; фильтр должен это учитывать.
- Личные сообщения и группы различаются по `chat.type`; не предполагай, что бот всегда в личке.
- Для глубоких ссылок используй `https://t.me/<bot>?start=<payload>` и читай `message.text` после `/start`.
- Для админских команд проверяй `from_user.id` по белому списку, а не только наличие команды.

## Клавиатуры и кнопки

- `InlineKeyboardMarkup` — кнопки под сообщением, обрабатываются `callback_query`.
- `ReplyKeyboardMarkup` — кнопки вместо клавиатуры, присылают обычный текст.
- `callback_data` ограничен 64 байтами. Не клади туда JSON с длинными значениями: используй короткий идентификатор и храни состояние отдельно.
- На каждый `callback_query` отвечай `answerCallbackQuery`, иначе у пользователя останется индикатор загрузки.
- После нажатия обновляй сообщение через `editMessageText` или `editMessageReplyMarkup`, а не отправляй новое без необходимости.

## Состояния и диалоги

- В `aiogram` используй `StatesGroup` и `FSMContext`; хранилище состояний должно быть внешним для продуктивной среды.
- В `python-telegram-bot` используй `ConversationHandler` или собственное хранилище.
- Всегда предусматривай выход из диалога: `/cancel`, кнопка «Отмена», таймаут.
- Не храни в состоянии весь объект сообщения: только необходимые поля.

## Лимиты

| Что                | Ограничение                                                                        |
|--------------------|------------------------------------------------------------------------------------|
| Текст сообщения    | 4096 символов                                                                      |
| Подпись к медиа    | 1024 символа                                                                       |
| `callback_data`    | 64 байта                                                                           |
| Файл через Bot API | до 50 МБ на отправку, до 20 МБ на скачивание                                       |
| Частота            | около 30 сообщений в секунду суммарно; в один чат — не более 1 сообщения в секунду |
| Группы             | около 20 сообщений в минуту в одну группу                                          |

При `429` Telegram возвращает `retry_after`. Не повторяй сразу: выдержи паузу.
Для массовых рассылок используй очередь и ограничение скорости, а не цикл без задержек.

## Медиа и файлы

- Отправляй файл по `file_id`, если он уже загружен, — это быстрее и не требует повторной загрузки.
- Для больших файлов используй локальный Bot API server или внешнее хранилище со ссылкой.
- Проверяй MIME-тип и расширение; не доверяй имени файла от пользователя.
- Скачанные файлы сохраняй в отдельную директорию с ограниченными правами и очищай по расписанию.

## Платежи

1. `sendInvoice` — счёт с ценой, валютой и payload.
2. `pre_checkout_query` — проверь наличие товара и цену, ответь `answerPreCheckoutQuery` за 10 секунд.
3. `successful_payment` — подтверждение оплаты; проверь `telegram_payment_charge_id` и не выдавай товар дважды.
4. Храни заказы и статусы в БД, а не в памяти.

## Мини-приложения

- Проверяй `initData` на сервере: `secret_key = HMAC_SHA256("WebAppData", bot_token)`, затем `HMAC_SHA256(secret_key, data_check_string)`.
- Не доверяй `initDataUnsafe` на клиенте.
- Проверяй срок жизни `auth_date`, чтобы старые данные нельзя было переиспользовать.
- Для платежей внутри мини-приложения используй `openInvoice` и серверную проверку статуса.

## Безопасность

- Не логируй токен и `initData`.
- Проверяй `secret_token` вебхука сравнением за постоянное время.
- Ограничивай доступ к админским командам по ID пользователей.
- Экранируй пользовательский текст, если вставляешь его в HTML или Markdown.
- Не выполняй команды из сообщений пользователя и не передавай их в shell.
- Для LLM-бота отделяй инструкции системы от текста пользователя и не давай модели прямой доступ к секретам.

## Тестирование

- Юнит-тесты — на чистые функции и парсеры.
- Интеграционные — на фейковые `Update` через `dp.feed_update` или прямой вызов обработчика.
- Вебхук — локальный сервер и туннель (`cloudflared`, `ngrok`) только для отладки.
- Проверь повторную доставку одного `update_id`, пустой текст, стикер вместо текста, нажатие устаревшей кнопки.
- Проверь поведение при недоступном API: бот не должен падать и терять очередь.

## Частые ошибки

| Симптом                            | Причина                                                           | Решение                                      |
|------------------------------------|-------------------------------------------------------------------|----------------------------------------------|
| Бот молчит после деплоя            | Вебхук не установлен или указывает на старый домен                | `getWebhookInfo`, `setWebhook`               |
| Ошибка `409 Conflict`              | Одновременно работают polling и вебхук или два экземпляра polling | Оставь один способ доставки и один экземпляр |
| `429 Too Many Requests`            | Нет ограничения скорости                                          | Очередь, `retry_after`, повтор с задержкой   |
| Кнопка «крутится»                  | Не вызван `answerCallbackQuery`                                   | Отвечай на каждый callback                   |
| `BUTTON_DATA_INVALID`              | `callback_data` длиннее 64 байт                                   | Короткий идентификатор в состоянии           |
| Пользователь получает ответ дважды | Повторная доставка обновления                                     | Дедупликация по `update_id`                  |
| В группе команда не срабатывает    | Команда с суффиксом `@botname`                                    | Учитывай суффикс в фильтре                   |
| Мини-приложение не авторизуется    | Неверный порядок HMAC                                             | Сначала ключ `WebAppData`, затем данные      |
