# Региональные мессенджеры: Viber, LINE, WeChat, KakaoTalk

Эти платформы сильно различаются по модели доступа: где-то есть открытый REST API, где-то бота собирают в закрытом конструкторе. Ниже только то, что подтверждено официальной документацией.

## Viber

Документация: <https://developers.viber.com/docs/api/rest-bot-api/>.
Клавиатуры: <https://developers.viber.com/docs/tools/keyboards/>.

### Важное ограничение доступа

С 5 февраля 2024 года боты Viber создаются **только на коммерческих условиях**: нужно подать заявку в Rakuten Viber или обратиться к официальному партнёру (<https://help.viber.com/hc/en-us/articles/15247629658525>). Свободного создания бота, как в Telegram, нет. Проверь это до того, как обещать пользователю готового бота.

Боты работают на iOS и Android с Viber 6.5 и новее, на десктопе — с 6.5.3.

### Аутентификация и адреса

Токен аккаунта передаётся заголовком `X-Viber-Auth-Token`. Без него возвращается ошибка `missing_auth_token`.

| Метод  | Адрес                                            |
|--------|--------------------------------------------------|
| `POST` | `https://chatapi.viber.com/pa/set_webhook`       |
| `POST` | `https://chatapi.viber.com/pa/send_message`      |
| `POST` | `https://chatapi.viber.com/pa/broadcast_message` |

### Вебхук

`set_webhook` принимает `url`, `event_types`, `send_name`, `send_photo`.

- URL обязан использовать SSL с сертификатом от доверенного центра. Самоподписанные сертификаты не поддерживаются.
- Сразу после установки Viber присылает проверочный колбэк с `event: "webhook"`. Ответ должен быть `200`, иначе `set_webhook` вернёт `status: 1` (`invalidUrl`).
- Обязательные события, которые нельзя отфильтровать: `message`, `subscribed`, `unsubscribed`.
- Можно отфильтровать: `delivered`, `seen`, `failed`, `conversation_started`.
- Пустой список `event_types` означает «только обязательные события»; отсутствие параметра — «все события».
- Чтобы отключить личный чат с ботом, отправь `set_webhook` с пустым `url`.

Проверочный колбэк:

```json
{
   "event": "webhook",
   "timestamp": 1457764197627,
   "message_token": 241256543215
}
```

### Отправка сообщений

Максимальный размер JSON-запроса — 30 КБ. Обязательные поля: `receiver` (идентификатор подписчика), `type`, `sender.name` (до 28 символов).

```json
{
   "receiver": "01234567890A=",
   "min_api_version": 1,
   "sender": { "name": "Магазин" },
   "tracking_data": "order-42",
   "type": "text",
   "text": "Заказ готов к выдаче."
}
```

Типы: `text`, `picture`, `video`, `file`, `location`, `contact`, `sticker`, `carousel content`, `url`.

- Текст — до 7000 символов, поддерживает разметку.
- `tracking_data` — до 4096 символов, возвращается в ответе пользователя.
- `sender.avatar` — не больше 100 КБ, рекомендуется 720×720.

Ответ содержит `message_token` и `billing_status` от 0 до 5, по которому видно, был ли запрос платным.

### Клавиатуры

Клавиатура прикрепляется к любому сообщению через поле `keyboard` и заменяет системную клавиатуру. Клиент всегда показывает последнюю отправленную клавиатуру.

```json
{
   "receiver": "01234567890A=",
   "min_api_version": 7,
   "type": "text",
   "text": "Выберите действие",
   "keyboard": {
      "Type": "keyboard",
      "DefaultHeight": false,
      "Buttons": [
         {
            "ActionType": "reply",
            "ActionBody": "help",
            "Text": "Помощь",
            "TextSize": "regular"
         }
      ]
   }
}
```

### Рассылка

`broadcast_message` работает только по подписчикам.

- Максимум **300** получателей в одном запросе (`broadcast_list`).
- Ограничение частоты — **500 запросов за 10 секунд**.
- Размер JSON — до 30 КБ.
- Поддерживаются подстановки из данных получателя.

### Подписчики

API не позволяет получить список всех подписчиков. Идентификатор приходит в `sender.id` события `message` или в `user.id` события `subscribed`, поэтому его нужно сохранять самому. Первое сообщение пользователя делает его подписанным, но события `subscribed` при этом **не будет**.

## LINE

Документация Messaging API: <https://developers.line.biz/en/reference/messaging-api/>.
Токены доступа: <https://developers.line.biz/en/docs/basics/channel-access-token/>.

### Модель

Бот — это LINE Official Account с каналом Messaging API в LINE Developers Console. Приём событий — только вебхук, long polling нет.

- Токен канала передаётся заголовком `Authorization: Bearer <channel access token>`.
- Вебхук настраивается для каждого канала в консоли.
- Ограничение частоты — **2000 запросов в секунду** (раздел Rate limits в справочнике).

### Что есть в API

- **Messages** — отправка, проверка доставки, отзыв.
- **Webhooks** — события: добавление в друзья, сообщения, действия с кнопками, вход в группу и выход из неё.
- **Getting content** — скачивание того, что прислал пользователь, по `messageId` из события.
- **Users** — профиль пользователя. Своего собственного user ID через API получить нельзя: он виден только в консоли.
- **Group chats** и **Multi-person chats** — сведения о группах и участниках.
- **Rich menu** и **Per-user rich menu** — меню внизу чата, общее и персональное.
- **Audience** и **narrowcast** — сегментированные рассылки.
- **Insights** — статистика отправок и числа друзей.
- **Coupon** — купоны.

### Объекты сообщений и действий

Типы действий (`action objects`): `postback`, `message`, `uri`, `datetimepicker`, `camera`, `cameraRoll`, `location`, `richmenuswitch`, `clipboard`.

Rich menu — картинка с областями (`area objects`), каждой области назначается действие. Персональное меню ставится конкретному пользователю по `userId`.

### SDK

| Язык                    | Пакет                   |
|-------------------------|-------------------------|
| Python                  | `line-bot-sdk`          |
| JavaScript / TypeScript | `@line/bot-sdk`         |
| PHP                     | `linecorp/line-bot-sdk` |
| Ruby                    | `line-bot-api`          |
| Go                      | `line-bot-sdk-go`       |

### Особенности

- Flex Message — основной способ сделать настраиваемую вёрстку; это JSON-структура, а не HTML.
- Рассылка `narrowcast` требует заранее созданной аудитории.
- Ответ на событие должен укладываться в таймаут вебхука: тяжёлую работу выноси в очередь.

## WeChat и WeCom

Это две разные платформы с разными API, и путать их нельзя.

### Личный WeChat

Официального API для ботов в личном WeChat нет. Библиотеки вроде `wechaty` работают через эмуляцию клиента и нарушают условия использования. Для продуктивной задачи личный WeChat не подходит.

### WeCom (企业微信)

Документация групповых ботов: <https://developer.work.weixin.qq.com/document/path/91770>.

Самый простой путь — групповой бот с вебхуком. Адрес выдаётся при создании бота в группе:

```
https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<ключ>
```

Вебхук содержит ключ, поэтому его нельзя публиковать в открытых источниках: любой, кто его получит, сможет отправлять сообщения в вашу группу.

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<ключ>' \
  -H 'Content-Type: application/json' \
  -d '{
    "msgtype": "text",
    "text": {
      "content": "Сборка завершена",
      "mentioned_list": ["@all"]
    }
  }'
```

Поддерживаемые типы сообщений:

| `msgtype`       | Ограничение                                                |
|-----------------|------------------------------------------------------------|
| `text`          | до 2048 байт UTF-8                                         |
| `markdown`      | до 4096 байт, урезанный набор разметки                     |
| `markdown_v2`   | до 4096 байт, списки, таблицы, код; без цвета и упоминаний |
| `image`         | base64, до 2 МБ, JPG или PNG                               |
| `news`          | от 1 до 8 статей, заголовок до 128 байт                    |
| `file`          | по `media_id` из интерфейса загрузки                       |
| `voice`         | по `media_id`                                              |
| `template_card` | карточка `text_notice` или `news_notice`                   |

Упоминания:

- в `text` и `markdown` — массивы `mentioned_list` (userid, `@all`) и `mentioned_mobile_list` (телефоны, `@all`), а также синтаксис `<@userid>` в `content`;
- в `markdown_v2` упоминания и цвет шрифта не поддерживаются;
- `markdown_v2` на клиентах ниже 4.1.36 (Android — 4.1.38) отображается как обычный текст.

Цвета в `markdown` ограничены тремя: `<font color="info">`, `<font color="comment">`, `<font color="warning">`.

Для полноценного бота, который принимает сообщения, нужен не групповой вебхук, а приложение WeCom с собственным сервером и проверкой подписи. Групповой вебхук — только отправка.

### SDK

- Python: `wechatpy` для официальных аккаунтов.
- Для WeCom проще работать через HTTP: набор методов невелик, а обёртки отстают от изменений.

## KakaoTalk

Документация Kakao Talk Message API: <https://developers.kakao.com/docs/en/kakaotalk-message/rest-api>.
Документация чат-ботов (Open Builder): <https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/ai_chatbot_callback_guide>.

У Kakao две разные возможности, и их важно не смешивать.

### Kakao Talk Message API

Это отправка сообщений по шаблону, а не полноценный бот.

- Работает только между пользователями одного сервиса.
- «Send to me» — сообщение в собственный чат «Мои сообщения» текущего авторизованного пользователя.
- «Send to friends» — до **5 друзей** за раз, требует отдельного разрешения и реализации выбора получателей через Friends picker или API списка друзей. Есть суточные и месячные квоты.
- Нужен scope `talk_message` в согласиях Kakao Login.
- Токен — `Authorization: Bearer <access token>`.
- Тело — `application/x-www-form-urlencoded`.

| Метод  | Адрес                                                  |
|--------|--------------------------------------------------------|
| `POST` | `https://kapi.kakao.com/v2/api/talk/memo/default/send` |
| `POST` | `https://kapi.kakao.com/v2/api/talk/memo/send`         |
| `POST` | `https://kapi.kakao.com/v2/api/talk/memo/scrap/send`   |

Шаблоны: `feed`, `list`, `location`, `commerce`, `text`, `calendar`. Для custom-шаблона передаётся `template_id` из конструктора шаблонов и, при необходимости, `template_args`.

Успех определяется по `result_code`, равному 0.

Для scrap-сообщений домен страницы должен быть заранее зарегистрирован в разделе Product Link.

### Чат-боты через Open Builder

Чат-бот KakaoTalk Channel собирается в конструкторе Kakao i Open Builder: сценарии, блоки, приветствие. Своего кода для приёма сообщений нет — вместо этого регистрируется **сервер навыков** (스킬 서버), HTTP-эндпоинт, который Open Builder вызывает при попадании в блок со «ответом навыка».

- Публичного API для программного создания ботов нет: всё настраивается в консоли.
- Сервер навыков получает запрос с данными пользователя и блока и возвращает ответ в формате Open Builder.
- Для асинхронных сценариев есть механизм callback: в ответе навыка ставится `useCallback: true`, а результат потом отправляется на адрес из настроек блока.

Практический вывод: если нужен именно чат-бот в KakaoTalk, план работ включает ручную настройку в консоли Open Builder, и это надо явно проговорить с заказчиком.
