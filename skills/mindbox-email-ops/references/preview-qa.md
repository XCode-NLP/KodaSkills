# Проверки, предпросмотр и QA

**Когда читать:** нужен скачанный HTML, диагностика конкретной проблемы отрисовки либо предпросмотр пришёл без PNG-ссылок. Предпросмотр каждой итерации требует только `SKILL.md`.
**Что вернуть:** к §3 «Правка» визуального порядка работы в `SKILL.md` либо пользователю с результатом QA.

- **HTML не скачивается автоматически.** Скачивай HTML только для HTML-QA или диагностики, где HTML нужно прочитать. PNG-QA HTML не нужен: PNG даёт MCP. Сначала зафиксируй абсолютный `<projectRoot>`; не полагайся на рабочий каталог запускающего процесса. Для кампании называй файл по `internalId` кампании из `campaign_get`: `<internalId>.html`:

  ```bash
  # macOS/Linux
  curl --fail --location --silent --show-error "<htmlUrl>" \
    --output "<projectRoot>/<internalId>.html"

  # Windows PowerShell
  & curl.exe --fail --location --silent --show-error "<htmlUrl>" `
    --output "<projectRoot>/<internalId>.html"
  ```

  GUID кампании не требует очистки имени и предотвращает конфликты между разными кампаниями. Новое QA-скачивание той же кампании заменяет прежний локальный файл: так и должно быть; файл представляет последний скачанный рендер бэкенда, а не обязательно последнюю правку JSX. Не используй одно имя кампании и не придумывай своё имя без `internalId` кампании. Если скачивание не удалось, сохрани `htmlUrl`, сообщи ошибку `curl` и не подставляй вместо HTML что-то другое. Считай скачивание успешным только при коде выхода `0` и непустом файле результата. Ошибка скачивания не отменяет удачный предпросмотр бэкенда и сама по себе не блокирует сохранение. HTML-QA недоступно, пока скачивание не повторено успешно; PNG-QA через MCP от скачивания HTML не зависит. Для отдельного предпросмотра без целевой кампании используй `<projectRoot>/standalone-preview.html`; он представляет последний отдельный рендер и не должен использоваться как артефакт конкретной кампании.
- **Просьба проверить письмо или его отрисовку уже является согласием на диагностику:** не спрашивай отдельно, можно ли скачать HTML или открыть PNG.
- **HTML-QA** читает скачанный файл выборочно и проверяет ожидаемые тексты, изображения, вёрстку и очевидные проблемы экранирования и структуры против запроса пользователя. Не втягивай весь HTML в контекст модели без нужды. Где полотно расходится с отправленным письмом — ссылки `#`, примеры значений, заглушки — написано на странице вики `email.tags.template`, «В предпросмотре»: ничто из этого не дефект. В HTML полотна каждая ссылка внутри `<Text>` — `#`, в том числе обычные. Адреса и ссылку на отписку проверяй по JSX, а не по HTML полотна; ссылка внутри `<SyncBlock>` — `email.topics.unsubscribe_link`.

  PNG-QA использует ссылки на десктопный и мобильный снимки из ответа предпросмотра и визуально проверяет содержимое, обрезку, адаптивную ветку и загрузку изображений. Это QA по мере возможностей, а не полный тест совместимости с Outlook и Gmail.
- **PNG-ссылки лежат в том же ответе предпросмотра** — без второго инструмента и второго вызова. Никаких локальных скриншотов, кроме запасного пути ниже. Просили только мобильный или только десктопный — покажи эту ссылку; для диагностики адаптивности — обе. Для пользователя это «десктопный снимок» и «мобильный снимок».
- **Запасной путь, если PNG-ссылок нет.** Если предпросмотр вернул ошибку или пришёл без PNG-ссылок, а пользователю всё равно нужна визуальная проверка, в Cowork можно как аварийный запасной вариант использовать Claude in Chrome, чтобы посмотреть HTML-предпросмотр и снять снимок. Скажи пользователю прямо, что это запасной путь, а не стандартные PNG из ответа инструмента. Браузер здесь только читает: заходить с ним в интерфейс Mindbox и что-то нажимать за пользователя запрещено.
- **Диагностика повторных жалоб.** Если пользователь сообщает о проблеме с содержимым или отрисовкой собранной кампании, возьми текущий JSX, вызови свежий HTML-предпросмотр, скачивай HTML только если нужно проверить HTML-фрагменты; при визуальной проблеме или проблеме адаптивности смотри десктопную и мобильную PNG-ссылки из ответа предпросмотра. Используй существующий локальный HTML, только если он доказуемо свеж для того же JSX.

QA нашло дефект, и Генератор изменил JSX — локальный HTML тоже устарел. Пользователь продолжает QA — повтори предпросмотр и скачивание; иначе новый JSX получает свой обычный предпросмотр.
