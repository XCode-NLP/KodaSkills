# Навык работы с GitHub CLI

Используй инстанс и правила ниже при построении всех команд `gh`.

## Инстанс

Все операции `gh` и `git` используют хост `github.com`.

### Предусловия (разовая настройка силами пользователя)

Если аутентификация ещё не выполнена, сообщи пользователю, что она требуется, и попроси выполнить шаги ниже вручную. Не выполняй эти шаги сам.

1. Установи CLI `gh`, если он ещё не установлен:

```bash
brew install gh
```

2. Выполни команду для аутентификации на GitHub:

```bash
gh auth login
```

## Проверка кода в PR

Когда просят проверить pull request GitHub (дан URL или идентификатор PR), извлеки `<owner/repo>` и `<PR_ID>` из URL (если репозитория нет, спроси пользователя), затем через `gh api` получи метаданные PR (`repos/<owner>/<repo>/pulls/<PR_ID>`) и его дифф (`repos/<owner>/<repo>/pulls/<PR_ID>/files --paginate`). Чтобы полностью понять контекст и влияние всех изменений кода, прочитай всю кодовую базу исходной ветки — один дифф не передаёт окружающую логику, зависимости и общий дизайн, с которыми взаимодействуют изменения. Сообщи заголовок PR, автора и ветки, затем проверь все изменённые файлы на: секреты, инъекции и XSS (безопасность); неэффективные алгоритмы и утечки памяти (производительность); запахи кода и мёртвый код (качество); отсутствующую обработку ошибок; избыточное журналирование или журналирование чувствительных данных; отсутствующую или устаревшую документацию. Для каждой находки укажи путь к файлу, номера строк, проблемный фрагмент и предлагаемое исправление. Если всё в порядке, перечисли, что проверено, и скажи, что выглядит хорошо.

## Правила

- Всегда явно передавай `--repo <owner>/<repo>` для любой подкоманды `gh`, которая его принимает (например, `pr list`, `issue list`, `run list`): без него команда выводит репозиторий из текущей директории git и может молча вернуть неверный результат.
- В `gh api` используй путь относительно `https://api.github.com`, например `gh api repos/<owner>/<repo>/pulls`.
- Все вызовы `gh api`, возвращающие списки, постраничны (по умолчанию 30 на страницу). Всегда передавай `--paginate`, чтобы получить все страницы: `gh api --paginate "repos/<owner>/<repo>/pulls"`.
- Для `gh pr list` предпочитай явные флаги состояния: `--state closed` для закрытых, `--state merged` для слитых, `--state all` для всех состояний. Без `--state` по умолчанию возвращаются открытые PR.
- НИКОГДА не обращайся к инстансу GitHub Enterprise, если пользователь явно не дал имя хоста и не подтвердил, что оно верное. Если URL ссылается на незнакомый хост, остановись и попроси пользователя подтвердить.
