# Единые соглашения об именах ключей

Хорошо выстроенные имена ключей улучшают сопровождаемость кода, отладку и позволяют эффективно сканировать ключи.

**Правильно:** использовать двоеточие как разделитель с последовательной иерархией.

```
# Шаблон: сервис:сущность:id:атрибут
user:1001:profile
user:1001:settings
order:2024:items
cache:api:users:list
session:abc123
```

**Python** (redis-py):
```python
# Хорошо: короткий осмысленный ключ
redis.set("product:8361", cached_html)
page = redis.get("product:8361")
```

**Java** (Jedis):
```java
// Хорошо: короткий осмысленный ключ, полученный из URL
jedis.set("product:8361", "<some cached HTML>");
String page = jedis.get("product:8361");
```

**Неправильно:** непоследовательные имена, пробелы или очень длинные ключи.

```
# Они путают и тратят память
User_1001_Profile
my key with spaces
com.mycompany.myapp.production.users.profile.data.1001
```

**Java** (Jedis):
```java
// Плохо: полный URL в качестве ключа тратит память и замедляет сравнение
jedis.set("http://www.verylongurlkey.com/store/products/product.html?id=8361",
          "<some cached HTML>");
```

**Советы по именам ключей:**
- Держи ключи короткими, но читаемыми — они занимают память
- Предусматривай префиксы ключей для мультитенантных приложений
- Извлекай короткие идентификаторы из URL и длинных строк, а не бери их целиком
- Для больших бинарных значений используй в качестве ключа хеш, а не само значение
- Используй единый разделитель (двоеточие — общепринятый вариант)

Источник: [Redis Keys](https://redis.io/docs/latest/develop/use/keyspace/)
