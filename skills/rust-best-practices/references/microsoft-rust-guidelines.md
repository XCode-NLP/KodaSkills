# Microsoft Pragmatic Rust Guidelines (краткий пересказ)

Источник: https://microsoft.github.io/rust-guidelines/ (версия 2026.6, лицензия MIT).
Девяносто рекомендаций с кодами `M-`, написанных для команд, которые поставляют Rust в больших
масштабах, с главой, адресованной ИИ-агентам, пишущим код. Читай это про проектирование структур
ошибок, политику паник, политику `unsafe`, async, структуру рабочей области, производительность
и про то, что делает код удобным для работы агента. Рекомендации «must» — жёсткие ограничения;
«should» допускает суждение; дух важнее буквы.

## Универсальное

- **M-UPSTREAM-GUIDELINES**: следуй Rust API Guidelines, Style Guide, Design
  Patterns и справочнику по UB. Особенно C-CONV, C-GETTER, C-COMMON-TRAITS, C-CTOR
  (предоставляй `Foo::new()`, даже когда есть `Default`), C-FEATURE.
- **M-STATIC-VERIFICATION**: линты компилятора, clippy, rustfmt, cargo-audit, cargo-hack,
  cargo-udeps и Miri как проверки при сдаче кода. Включай `[lints.rust]`, например
  `unsafe_op_in_unsafe_fn` и `missing_debug_implementations`, группы clippy с
  `priority = -1` и ограничительные линты вроде `undocumented_unsafe_blocks`,
  `allow_attributes_without_reason`, `map_err_ignore`.
- **M-LINT-OVERRIDE-EXPECT**: `#[expect(clippy::x, reason = "...")]` для локальных
  переопределений; невыполненный `expect` даёт предупреждение, поэтому устаревшие
  подавления находятся. `#[allow]` только для сгенерированного кода и макросов.
- **M-PUBLIC-DEBUG**: выводи `Debug` на публичных типах. Типы, хранящие секреты, получают
  написанный вручную `Debug` (`UserSecret(...)`) плюс модульный тест, утверждающий, что
  секрет никогда не появляется в выводе.
- **M-PUBLIC-DISPLAY**: типы, предназначенные для чтения, особенно ошибки и обёртки строк,
  реализуют `Display`. Те же правила сокрытия, что и для `Debug`.
- **M-SMALLER-CRATES**: сомневаешься — разбей на большее число крейтов (быстрее сборка, нет
  циклов). `web_server`, `web_client`, `web_protocols` вместо одного крейта `web` с модулями.
- **M-WEASEL-WORDS**: никаких суффиксов `Service`, `Manager`, `Factory`. `Bookings` или
  `BookingDispatcher`; `Builder` вместо `Factory`; освобождение — это `Drop`, а не менеджер.
  Повторяемое создание принимает `impl Fn() -> Foo`.
- **M-SHORT-NAMES**: не больше двух коротких слов на идентификатор. Не вшивай имя модуля в
  тип (`foo::Id`, а не `foo::FooId`).
- **M-REGULAR-FN**: ассоциированные функции — для создания экземпляров. Вычисление без
  получателя — свободная функция, а не `Database::check_parameters(p)`.
- **M-DOCUMENTED-MAGIC**: магические значения получают комментарий о том, почему выбрано
  такое значение, к чему приводит его изменение и какие внешние системы задействованы.
  Предпочитай именованный `const` с doc-комментарием.
- **M-LOG-STRUCTURED**: структурированные события с шаблонами сообщений, именами
  `<component>.<operation>.<state>`, именами атрибутов OpenTelemetry, с сокрытием PII. Не
  форматируй заранее через `format!`.

## Библиотеки: совместимость

- **M-TYPES-SEND**: публичные типы и порождаемые ими future являются `Send`. Проверяй через
  `const _: () = assert_send::<Foo>();`. `Rc`, удерживаемый через `.await`, делает future
  `!Send`.
- **M-ESCAPE-HATCHES**: обёртки над нативными дескрипторами предоставляют
  `pub unsafe fn from_native(..)` плюс `into_native` / `to_native` с документированными
  требованиями безопасности.
- **M-DONT-LEAK-TYPES**: в публичных API предпочитай типы std. Сторонние типы только за
  флагом возможности (`serde`) или при существенной выгоде.
- **M-FOREIGN-REEXPORTS**: не делай `pub use` элементов чужого крейта; пользователи зависят
  от него напрямую. Исключения: зонтичные крейты, техническое разделение, скрытые пути
  макросов.
- **M-IMPL-ASREF**: параметры могут принимать `impl AsRef<str>` / `AsRef<Path>` /
  `AsRef<[u8]>`, когда владение не нужно. Поля структур хранят `String`, `PathBuf`.
- **M-IMPL-RANGEBOUNDS**: принимай `impl RangeBounds<T>`, а не пары `(low, high)`, чтобы
  вызывающие писали `1..3`, `1..`, `..`.
- **M-IMPL-IO**: пиши sans-IO функции. Синхронный одноразовый ввод-вывод принимает
  `impl Read` / `impl Write`; асинхронный, независимый от рантайма, — `futures::io::AsyncRead`.

## Библиотеки: удобство

- **M-SIMPLE-ABSTRACTIONS**: публичные типы уровня сервиса не раскрывают вложенные
  параметры-типы. `Service<Backend>` нормально; `Service<Backend<Store>>` — нет.
- **M-AVOID-WRAPPERS**: держи `Rc`, `Arc`, `Box`, `RefCell` вне публичных API; используй `&T`,
  `&mut T`, `T`. Умные указатели только когда они фундаментальны или подтверждены
  бенчмарками.
- **M-DI-HIERARCHY**: предпочитай конкретные типы, затем дженерики по узким трейтам, затем
  `dyn Trait`, обёрнутый в собственную структуру (`DynamicDataAccess(Arc<dyn DataAccess>)`).
  Не переноси C#-шный `IDatabase` в `Rc<dyn Database>`. Тестовые двойники: перечисление с
  вариантом `Mock(MockCtrl)`.
- **M-ERRORS-CANONICAL-STRUCTS**: ошибки — структуры под конкретную ситуацию, а не одно
  глобальное перечисление. Каждая хранит `Backtrace`, необязательную вышестоящую причину и
  вспомогательные методы (`config_file(&self) -> &Path`). Держи любой `ErrorKind` приватным и
  открывай методы в стиле `is_io()`. Захватывай backtrace в `new()` или `From`. `Display`
  печатает сводку, backtrace и причину. Реализуй `std::error::Error`. Переиспользуй одну общую
  ошибку в похожих функциях (`ParseError` для `parse_json` и `parse_toml`).
- **M-FROM-ERROR**: реализуй `From<Upstream> for Error`, чтобы `?` преобразовывал; `map_err`
  только для чужих ошибок или чтобы добавить контекст.
- **M-INIT-BUILDER**: до двух необязательных параметров — собственные конструкторы (`new`,
  `with_a`, `with_b`, `with_a_b`). Начиная с четырёх перестановок — `FooBuilder` с сеттерами,
  названными по полям (`x()`, а не `set_x()`), `build()` и `Foo::builder()`.
  `FooBuilder::new()` не публичный. Обязательные параметры приходят через
  `deps: impl Into<FooDeps>`.
- **M-INIT-CASCADED**: конструкторы с четырьмя и более параметрами группируют их в смысловые
  типы: `Deposit::new(account, amount)`.
- **M-SERVICES-CLONE**: тяжеловесные сервисы реализуют дешёвый `Clone` через
  `Arc<Inner>`; клоны разделяют состояние.
- **M-ESSENTIAL-FN-INHERENT**: основная функциональность — в собственных методах; реализации
  трейтов делегируют им, поэтому вызывающим не нужен импорт.
- **M-BALANCED-MODULES**: главные элементы в корне крейта; остальное группируй по сценарию
  использования (`account`, `network`), а не по виду (`traits`, `errors`).
- **M-NO-PRELUDE**: никакого prelude и никакой цели для `use foo::*`. Исправляй вместо этого
  дизайн модулей.
- **M-PARAMETER-CONSISTENCY**: общие параметры в одном порядке везде. Специфичные для вызова
  первыми, повсеместные (`&logger`) последними, замыкания последними, не больше одного
  замыкания.
- **M-COLLECTION-TRAITS**: собственные коллекции предоставляют `Iter`, `IterMut`, `IntoIter`,
  `iter()` / `iter_mut()`, `IntoIterator` для владеемого и заимствованного, `FromIterator`,
  `Extend`, `DoubleEndedIterator` / `ExactSizeIterator`, где применимо. `size_hint()`
  правдив.
- **M-ASYNC-FN**: `async fn foo() -> Result<T, E>` вместо `fn foo() -> impl Future`.
  Явная форма только в трейтах или для горячих функций (M-ASYNC-STACK-SIZE).

## Библиотеки: устойчивость

- **M-AVOID-STATICS**: избегай статиков и thread-local там, где важно согласованное значение.
  Две semver-несовместимые копии крейта получают разные статики.
- **M-BUILD-RESULT**: сеттеры билдера не падают; валидация, включая перекрёстные проверки
  полей, живёт в `build() -> Result<_, _>`.
- **M-INTEGRATION-TESTS**: тесты, использующие только публичный API, кладутся в `tests/`.
  Предпочитай интеграционный тест всякий раз, когда подошёл бы любой.
- **M-LOG-NOT-PRINT**: рабочий код использует фреймворк телеметрии, а не `println!` /
  `dbg!`. Исключение — только CLI, которые пишут свой интерфейс в stdout.
- **M-MOCKABLE-SYSCALLS**: типы, выполняющие файловый, сетевой ввод-вывод, работу с часами,
  энтропией или другой недетерминированный ввод-вывод, должны быть мокабельными. Предоставляй
  `new_mocked() -> (Self, MockCtrl)` за флагом `test-util`; не предлагай `Default`, который
  выполняет ввод-вывод.
- **M-NO-GLOB-REEXPORTS**: реэкспортируй по отдельности (`pub use foo::{A, B, C};`). Glob —
  только для модулей HAL платформы, выбираемых по `cfg(target_os)`.
- **M-STRONG-TYPES**: самый сильный тип std (`PathBuf` / `Path` для данных ОС). Простые числа
  остаются простыми на границах API; никаких `NonZero` или `Saturating` там.
- **M-STRONG-TYPES-GUARD**: newtype, кодирующий инвариант (месяц 1..=12), обеспечивает его в
  конструкторе, возвращающем `Result`. Паникующий `const fn new` допустим. Никакого
  безошибочного `From`; используй `TryFrom` / `FromStr`.
- **M-TEST-UTIL**: моки, инспекция чувствительных данных, переопределения безопасности и
  генераторы фейковых данных — за одной возможностью `test-util`.

## Библиотеки: сборка

- **M-OOBE**: неплатформенные крейты собираются на всех целях Tier 1 только с cargo и rustc,
  без дополнительных инструментов и переменных окружения. Кодогенерация выполняется при
  публикации, а её результат поставляется в крейте.
- **M-SYS-CRATES**: крейты `-sys` собирают нативный код из `build.rs` с крейтом `cc`,
  встраивают проверяемые вышестоящие исходники (URL плюс хэш), делают необязательные
  инструменты необязательными, заранее генерируют вывод bindgen и поддерживают статическую и
  динамическую компоновку через `libloading`.
- **M-FEATURES-ADDITIVE**: любая комбинация возможностей компилируется. Используй возможность
  `std`, никогда `no-std`. Возможность никогда не удаляет и не меняет публичный элемент
  (добавление вариантов `#[non_exhaustive]`-перечисления нормально).

## Макросы

- **M-MACRO-LAST-RESORT**: макросы только когда язык не справляется; они непрозрачны, медленно
  компилируются и хрупки при смене редакций.
- **M-EXAMPLE-OVER-PROC**: `macro_rules!` вместо процедурных макросов, когда его достаточно.
- **M-MACROS-DONT-LIE**: макросы никогда не меняют вид типа, не изменяют сигнатуру функции и
  не добавляют и не убирают `async`.
- **M-MACRO-MAIN-CRATE**: структура: `foo` (реэкспорты), `foo_proc` (фасад),
  `foo_proc_impl` (логика и тесты). Не поддерживай переименованные импорты.
- **M-MACRO-VERSION-PIN**: сопутствующие крейты макросов закрепляются через `=x.y.z` и
  публикуются вместе.
- **M-MACRO-HELPERS**: сгенерированный код обращается к сторонним элементам через скрытый
  `#[doc(hidden)] pub mod _private { pub use ::bar::Bar; }`.
- **M-PROC-IMPL**: крейт процедурного макроса — тонкая прослойка над обычным библиотечным
  крейтом с логикой и snapshot-тестами (`insta`); тесты `trybuild` для сообщений об ошибках.
- **M-PROC-IMPLIED-ITEMS**: макросы не порождают скрытых или лишних публичных типов (кроме
  обработчиков в стиле Rocket «функция плюс структура»).

## Приложения

- **M-APP-ERROR**: приложения и крейты одного приложения могут использовать `anyhow`, `eyre`
  или похожие; библиотеки следуют M-ERRORS-CANONICAL-STRUCTS. Не смешивай несколько типов
  ошибок уровня приложения.
- **M-MIMALLOC-APPS**: приложения ставят `#[global_allocator]` в `mimalloc` (сообщается о
  выигрыше до 25%).
- **M-TARGET-CPU**: серверные приложения компилируются под наибольший `target-cpu`, который
  гарантирует развёртывание (`x86-64-v3` через `.cargo/config.toml`). Библиотеки это
  игнорируют.

## FFI

- **M-FFI-NAMING**: крейты `-sys` импортируют C-библиотеки; крейты `-ffi` экспортируют Rust как
  библиотеку в стиле C.
- **M-FFI-TRANSLATES**: бизнес-логика в безопасном основном крейте; крейт `-ffi` только
  транслирует типы и сигнатуры. Никаких полей-указателей `repr(C)` в основных типах.
- **M-ISOLATE-DLL-STATE**: через границы DLL разделяй только переносимые данные: типы
  `#[repr(C)]` без статиков, thread-local, `TypeId` и указателей на непереносимые данные.

## Корректность

- **M-UNSAFE**: `unsafe` только для новой абстракции, подтверждённой бенчмарком потребности в
  производительности или вызовов FFI и платформы. Запрещено: приведение перечислений через
  `transmute`, `unsafe impl Send` для обхода ограничений, `transmute` для обхода времён жизни.
  Каждое использование требует рассуждения о безопасности обычным текстом; новые абстракции
  тестируются на состязательном коде и проходят Miri.
- **M-UNSAFE-IMPLIES-UB**: помечай функцию или трейт `unsafe`, только когда неверное
  использование грозит неопределённым поведением, а не просто опасными операциями
  (`delete_database()`).
- **M-UNSOUND**: безопасная функция, которая может вызвать UB через любые безопасные вызовы,
  несостоятельна по звуковости. Несостоятельные абстракции недопустимы никогда. Если не можешь
  её инкапсулировать, открывай `unsafe fn` и документируй контракт. Границы звуковости — это
  границы модулей.
- **M-PANIC-IS-STOP**: паники — не исключения; паника означает, что программу нужно остановить
  сейчас же. Не используй паники для сообщения об ошибках и не рассчитывай, что их поймают.
  Допустимо: ошибки программирования (`expect("must never happen")`), контексты const, методы
  в стиле `unwrap`, запрошенные пользователем, `unwrap()` на отравленной блокировке. Код всё
  равно должен быть минимально устойчив к паникам.
- **M-PANIC-ON-BUG**: обнаруженные баги и нарушения контрактов паникуют, и в библиотеках, и в
  приложениях. Не возвращай `Error`, с которым вызывающий ничего не может сделать. Ошибочный
  ввод возвращает `Result` (`parse_uri(&str) -> Result<Uri, ParseError>`). Предпочитай типы,
  делающие плохое состояние непредставимым.
- **M-PANIC-CONTINUATION**: `catch_unwind` — крайняя мера. Библиотеки не ловят и не
  продолжают. Серверы могут ловить на уровне запроса, но затем должны перейти к
  контролируемому перезапуску.
- **M-PANIC-MESSAGE**: у каждой намеренной паники (`panic!`, `assert!`, `unreachable!`,
  `todo!`) есть сообщение с относящимися значениями:
  `assert!(buf.len() >= HEADER_SIZE, "buffer too small: got {} bytes", buf.len())`.

## Производительность

- **M-HOTPATH**: сразу реши, важна ли производительность крейта; если да — найди и замерь
  горячие пути (criterion или divan), регулярно профилируй, документируй горячие места.
- **M-THROUGHPUT**: оптимизируй под элементы на цикл процессора; пакетные API; никакого
  горячего ожидания и поштучной работы там, где возможно пакетирование.
- **M-YIELD-POINTS**: долгая асинхронная работа, нагружающая процессор, уступает
  (`yield_now().await`) примерно каждые 10–100 микросекунд.
- **M-MEM-REUSE**: позволяй вызывающим владеть буферами и переиспользовать их:
  `get_in(id, &mut value)` рядом с удобным `get(id)`; предоставляй `clear()`. Арены для
  глубоких стеков вызовов.
- **M-LOG-OVERHEAD**: никакой телеметрии в горячих внутренних циклах; никакого `format!` на
  каждое событие.
- **M-AVOID-INDIRECTION**: не наслаивай `Arc` на горячих типах; поднимай горячие кэшируемые
  поля (`enabled: bool`) в владеющую структуру.
- **M-BOX-DST**: часто создаваемые неизменяемые последовательности, невидимые пользователю,
  используют `Box<[T]>`, `Box<str>` или `Arc<str>` вместо `Vec` / `String`.
- **M-SHRINK-TO-FIT**: `shrink_to_fit()` на долгоживущих расширяемых коллекциях, построенных
  без резервирования.
- **M-FAST-HASHER**: `foldhash` или `FxHash` для доверенных внутренних ключей; хэшер по
  умолчанию для недоверенного ввода.
- **M-INITIAL-CAPACITY**: `with_capacity`, когда размер известен; `collect()` вместо циклов с
  `push`.
- **M-ASYNC-STACK-SIZE**: отслеживай размер горячих future через `size_of_val` в тесте;
  уменьшай состояние, удерживаемое через `.await`; выноси подготовку из асинхронного блока.

## Проект

- **M-CARGO-WORKSPACE**: разделяй метаданные, версии и линты через
  `[workspace.dependencies]` и `[workspace.lints]`, с `default-features = false`
  в определениях зависимостей рабочей области.
- **M-CRATES-FLAT-FOLDER**: один `Cargo.toml` рабочей области, крейты — соседи в
  `crates/`, никогда не вложены в другой крейт или его `src/`.
- **M-CRATES-IN-WORKSPACE**: каждый крейт — член рабочей области; соседи подключаются как
  `sibling.workspace = true`.
- **M-LATEST-EDITION**: новые крейты используют последнюю стабильную редакцию (2024 или
  новее).
- **M-MSRV**: задавай минимальную поддерживаемую версию Rust при создании; повышай её
  консервативно в минорных выпусках.

## Документация

- **M-CANONICAL-DOCS**: публичные элементы получают однострочную сводку, расширенную
  документацию, затем `# Examples`, `# Errors`, `# Panics`, `# Safety` (обязательно для
  `unsafe fn`), `# Abort` по применимости. Параметры описываются прозой, а не таблицей.
- **M-DOC-INLINE**: `#[doc(inline)]` на `pub use` внутренних элементов крейта; не для типов
  std или сторонних.
- **M-FIRST-DOC-SENTENCE**: первое предложение на одной строке, около 15 слов; оно становится
  сводкой модуля.
- **M-MODULE-DOCS**: у каждого публичного модуля есть документация `//!`: что он содержит,
  когда его использовать, примеры, наблюдаемые побочные эффекты.

## ИИ (специфика агентов)

- **M-DESIGN-FOR-AI**: то, что делает API удобным для людей, делает его удобным для агентов:
  идиоматичный дизайн, подробная документация на каждом модуле и публичном элементе, сразу
  применимые примеры, сильные типы, API, тестируемые через фейки или моки, хорошее покрытие
  наблюдаемого поведения. Проверки компилятора уравновешивают ограниченное понимание агента.
- **M-NO-META-DESIGN-DOCUMENTATION**: никаких дневников дизайна, эссе «почему мы выбрали X» и
  таблиц самоотчёта агента (список `Rule | Applied | Where`) в документации крейта или модуля.
  Документируй конечное состояние. Раздел README о долгосрочных архитектурных целях допустим.
- **M-RUST-SHAPED**: при переносе с C#, Java или C++ не переводи конструкции один к одному.
  Сохраняй доменную логику; используй идиомы Rust для ошибок, задач, владения и трейтов.
  `throw_if_null()` сигнализирует о проблеме.
- **M-SINGLE-ITEM-PATH**: один путь на публичный элемент. Не сочетай
  `pub mod db { pub struct Connection; }` с `pub use db::Connection;`. Агенты склонны
  добавлять реэкспорты при рефакторинге вместо переработки дизайна. `pub(crate) mod` с
  единственным `pub use` нормален.
- **M-TAUTOLOGICAL-TESTS**: не пиши тесты, которые пересказывают константы или повторяют ветки
  реализации (`assert_eq!(CHECKPOINTS, [0, 90, 180, 270])`). Проверяй свойства: равномерность
  шага, монотонность, обратимость.
