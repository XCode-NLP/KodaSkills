# Шаблоны проектирования Rust (дайджест)

Источник: https://rust-unofficial.github.io/patterns/ (книга сообщества, обновлена в сентябре
2026). Идиомы, шаблоны проектирования и антишаблоны с кодом. Читай это, когда нужен конкретный
шаблон (конструктор, охранник RAII, новый тип, посетитель, `mem::take`) или когда хочешь проверить,
не является ли что-то известным антишаблоном.

## Идиомы

**Заимствованные типы для аргументов.** Принимай `&str`, `&[T]`, `&T` вместо `&String`, `&Vec<T>`,
`&Box<T>`. Тогда вызывающие могут передавать владеющие значения, заимствования или литералы через
приведение при разыменовании, и ты избегаешь лишнего уровня косвенности.

```rust
fn three_vowels(word: &str) -> bool { /* ... */ }
three_vowels(&String::from("Ferris"));  // &String coerces to &str
three_vowels("Curious");                // literal works too
```

**Склеивай строки через `format!`.** `format!("Hello {name}!")` — самый читаемый способ смешать
литералы и переменные. Заранее выделенная `String` с `push_str` быстрее на горячих путях.

**Конструкторы.** Давай ассоциированную функцию `new` без `self`, даже когда она не принимает
аргументов и дублирует `Default`.

**Трейт `Default`.** `#[derive(Default)]`, когда его реализует каждое поле; синтаксис обновления
структуры для частичной настройки:

```rust
let conf = MyConfiguration { check: true, ..Default::default() };
```

`Default` у типа только один; для других начальных состояний используй именованные конструкторы.

**Коллекции — это умные указатели.** Владеющая коллекция реализует `Deref` к своему заимствованному
виду (`Vec<T>` -> `[T]`, `String` -> `str`), поэтому методы вида доступны на владельце. Методы,
достигаемые через `Deref`, не учитываются в ограничениях трейтов, поэтому обобщённому коду могут
понадобиться `Borrow` или `AsRef`.

**Завершение в деструкторах.** В Rust нет `finally`; помещай очистку в реализацию `Drop` охранника,
привязанного к именованной переменной (`let _exit = Guard;`). Она выполняется при ранних возвратах
через `?` и при раскрутке стека. `let _ = ..` уничтожает значение сразу. Деструкторы можно обойти
аварийным завершением, бесконечным циклом или паникой при раскрутке, поэтому не полагайся на них в
существенной работе.

**`mem::take` и `mem::replace`.** Перемещай поле из значения `&mut`, подставляя заглушку вместо
клонирования. `take` использует `Default` (пустая `String` не выделяет память); `replace`
принимает явное значение; `Option::take` — для `Option`.

```rust
fn a_to_b(e: &mut MyEnum) {
    if let MyEnum::A { name, x: 0 } = e {
        *e = MyEnum::B { name: mem::take(name) };
    }
}
```

**Динамическая диспетчеризация на стеке.** Получи `dyn Trait` над значениями разных типов без
`Box`, привязав ссылку в выражении `if` (продление времени жизни временного значения с Rust 1.79):

```rust
let readable: &mut dyn io::Read = if arg == "-" {
    &mut io::stdin()
} else {
    &mut fs::File::open(arg)?
};
```

**Перебор `Option`.** `Option` — итератор из нуля или одного элемента: `vec.extend(opt)`,
`iter.chain(opt.iter())`. `std::iter::once`, когда всегда `Some`. Для простого ветвления
`if let Some(..)` читается лучше.

**Передача переменных в замыкание.** Когда замыканию нужно часть захватов клонировать или
заимствовать, а другие переместить, перепривяжи их во внутреннем блоке, затем используй `move`:

```rust
let closure = {
    let num2 = num2.clone();    // cloned
    let num3 = num3.as_ref();   // borrowed
    move || *num1 + *num2 + *num3  // num1 moved
};
```

**`#[non_exhaustive]` и приватные поля.** В библиотеке помечай публичные структуры, перечисления и
варианты `#[non_exhaustive]`, когда можешь позже добавить поля или варианты. Внутри пакета приватное
поле `_b: ()` блокирует литералы структур. Используй это умеренно: оно заставляет ниже по стеку
писать ветки с подстановочным знаком, и мажорное обновление версии часто лучше.

**Простая инициализация в документации.** Когда примеру в документации нужна большая подготовка,
оберни его в скрытую вспомогательную функцию (`# fn call_send(conn: Connection) {`), принимающую
подготовленные значения параметрами. Пример компилируется, но не выполняет свои утверждения.

**Временная изменяемость.** Заверши изменение на этапе настройки, затем заморозь:
`let data = data;`.

**Возвращай потреблённый аргумент при ошибке.** Функция, которая может отказать и забирает владение,
возвращает аргумент внутри ошибки, чтобы вызывающий мог повторить без клонирования
(`String::from_utf8` и `FromUtf8Error::into_bytes`).

## Шаблоны проектирования

Раздел открывается YAGNI: многие классические шаблоны в Rust не нужны. Стратегия — это просто
трейты; `Option::map` уже стратегия.

### Поведенческие

**Команда.** Храни действия как значения: `Box<dyn Trait>` для структур-команд с несколькими
методами (`execute` и `rollback`), указатели `fn()` для простых действий, замыкания `Fn` для
захваченного состояния. Указатели на функции и замыкания избегают динамической диспетчеризации.

**Интерпретатор.** Когда повторяющаяся проблема — небольшой язык, определи грамматику и
интерпретатор. Для лёгкого синтаксиса DSL используй `macro_rules!`.

**Новый тип.** Кортежная структура с одним полем создаёт отдельный тип (`Miles` против
`Kilometres`), скрывает секреты (`Password(String)`, чей `Display` печатает `****`) или
ограничивает набор трейтов. Стоимости во время выполнения нет; цена — обвязка пересылки
(`derive_more` помогает).

**RAII с охранниками.** Захватывай в конструкторе, освобождай в `Drop` и открывай ресурс только
через охранник, реализующий `Deref` (как `MutexGuard`). Проверка заимствований не даёт ссылкам,
полученным через охранник, пережить его.

**Стратегия.** Взаимозаменяемые алгоритмы как трейт с обобщённым ограничением для статической
диспетчеризации; для небольших вариаций достаточно ограничения-замыкания
(`F: Fn(u8, u8) -> u8`).

**Посетитель.** Прогоняй несколько алгоритмов по неоднородным данным (AST), не изменяя их: трейт
`Visitor<T>` с одним методом `visit_*` на тип узла плюс общие помощники обхода `walk_*`. Для
однородных данных используй итераторы.

### Порождающие

**Конструктор.** `Foo::builder()` возвращает `FooBuilder` с цепочкой сеттеров и `build()`.
Избегает размножения конструкторов и позволяет добавлять поля, не ломая вызывающих. Сеттеры,
принимающие `&mut self`, часто эргономичнее принимающих по значению. `derive_builder` убирает
обвязку.

**Свёртка.** Отображай дерево в новое дерево трейтом `Folder`, чьи методы `fold_*` по умолчанию
рекурсивно обходят детей; переопределяй только изменяемые узлы. (Это не `Iterator::fold`.)

### Структурные

**Предпочитай небольшие пакеты.** Пакеты с одной задачей компонуются, собираются параллельно и
переиспользуются. Цена: ад зависимостей (две версии `url` дают несовместимые типы `Url`), нет
отбора на crates.io, меньше межпакетной LTO.

**Удерживай небезопасность в небольших модулях.** Кладите `unsafe` в наименьший модуль, который
может поддержать свои инварианты, и оборачивай его в безопасный интерфейс. `String` — это
`Vec<u8>`, чьи безопасные методы поддерживают инвариант UTF-8.

**Компонуй структуры.** Когда одна большая структура вызывает конфликты заимствований, разбей её
на меньшие и скомпонуй в родителе; тогда каждую часть можно заимствовать отдельно, и дизайн обычно
улучшается.

## Антишаблоны

**Клонирование ради проверки заимствований.** `.clone()`, добавленный только чтобы убрать ошибку
заимствования, создаёт отдельную копию, чьи дальнейшие изменения не отражаются в оригинале. Клоны
`Rc` и `Arc` дешевы и нормальны. Клоны допустимы в прототипах, но должны быть осознанными; исправь
дизайн владения или используй `mem::take` и `replace`. Clippy отмечает ненужные клоны.

**`#![deny(warnings)]`.** Новые релизы компилятора добавляют lint'ы, которые начинаются как
предупреждения, поэтому сборка ломается после обновления инструментария, а также это блокирует
дополнительные инструменты lint. Используй `RUSTFLAGS="-D warnings"` в CI или запрещай конкретные
lint'ы по имени.

**Полиморфизм через `Deref`.** Реализация `Deref<Target = Base>` на `Derived` для наследования
методов удивляет: подтипирования нет, трейты `Base` не переносятся в ограничения, семантика `self`
отличается, а неявный механизм вводит читателей в заблуждение. `Deref` — для умных указателей.
Пиши явные методы пересылки, определи трейт или используй пакет делегирования (`delegate`,
`ambassador`).

## Функциональное программирование

**Парадигмы.** Императивный стиль говорит как; декларативный — что. Предпочитай комбинаторы
итераторов циклам с изменяемым накоплением: `(1..11).fold(0, |a, b| a + b)`.

**Обобщения как классы типов.** Каждый обобщённый аргумент даёт отдельный тип, поэтому кодируй
протокол или состояние в параметре типа, и неверные вызовы не скомпилируются:
`impl FileDownloadRequest<Nfs> { fn mount_point(&self) -> &Path }` не существует для варианта
BOOTP. Альтернативы: конструктор для разделений на этапе создания, стратегия, когда меняется только
поведение. Цена: больший бинарник.

**Функциональная оптика.** Iso, Poly Iso и Prism, показанные через API Visitor в Serde. В Rust
напрямую используется редко; полезна в основном для чтения таких API, как Serde.
