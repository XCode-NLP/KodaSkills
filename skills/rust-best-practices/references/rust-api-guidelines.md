# Рекомендации по API Rust (дайджест)

Источник: https://rust-lang.github.io/api-guidelines/ (официальный проект rust-lang).
Читай это, когда проектируешь или проверяешь публичный API либо публикуешь пакет. Покрыты все
54 пункта контрольного списка, сгруппированные как в оригинале.

## Именование

- **C-CASE**: `UpperCamelCase` для типов, трейтов, вариантов перечислений; `snake_case` для
  модулей, функций, методов, локальных переменных; `SCREAMING_SNAKE_CASE` для констант и
  статических значений; короткие параметры типов (`T`); короткие времена жизни в нижнем регистре
  (`'a`, `'de`). Аббревиатура — одно слово в `UpperCamelCase` (`Uuid`, `Stdin`) и в нижнем
  регистре в `snake_case` (`is_xid_start`). Имена пакетов никогда не несут приставку `-rs` или
  `-rust`.
- **C-CONV**: приставки нестандартных преобразований:

  | Приставка | Стоимость | Владение |
  |---|---|---|
  | `as_` | бесплатно | заимствованное -> заимствованное |
  | `to_` | дорого | заимствованное -> заимствованное; заимствованное -> владеющее (не `Copy`); владеющее -> владеющее (`Copy`) |
  | `into_` | переменная | владеющее -> владеющее (не `Copy`) |

  `as_` и `into_` раскрывают представление; `to_` остаётся на том же уровне абстракции, но
  выполняет работу (`Path::to_str` проверяет UTF-8). Обёртки раскрывают значение через
  `into_inner()`. `mut` идёт в порядке типа: `as_mut_slice`.
- **C-GETTER**: без приставки `get_`: `first(&self) -> &First`, `first_mut(&mut self)`. Голое
  `get` только когда есть одна очевидная вещь для получения (`Cell::get`). У проверяемых
  аксессоров есть собратья `unsafe fn get_unchecked`.
- **C-ITER**: коллекции дают `iter(&self) -> Iter` (элементы `&U`), `iter_mut` и
  `into_iter(self) -> IntoIter`. Неоднородные типы (`str`) используют `bytes()`, `chars()`.
- **C-ITER-TY**: тип итератора называется по методу: `into_iter` -> `IntoIter`, `keys` -> `Keys`,
  `percent_encode` -> `PercentEncode`.
- **C-FEATURE**: в именах возможностей нет слов-заполнителей: `abc`, а не `use-abc`. Включай std
  как `default = ["std"]`, `std = []`, с `#![no_std]` и `#[cfg(feature = "std")] extern crate std;`.
  Возможности аддитивны, поэтому `no-abc` почти всегда неверно.
- **C-WORD-ORDER**: будь согласован со std: типы ошибок строятся как «глагол-объект-ошибка»
  (`ParseBoolError`, значит `ParseAddrError`, а не `AddrParseError`).

## Совместимость

- **C-COMMON-TRAITS**: сразу реализуй `Copy`, `Clone`, `Eq`, `PartialEq`, `Ord`, `PartialOrd`,
  `Hash`, `Debug`, `Display`, `Default`, где применимо. Из-за правила сиротства пакеты ниже по
  стеку не могут их добавить. Давай пустой `new()` рядом с `Default` и делай так, чтобы они вели
  себя одинаково.
- **C-CONV-TRAITS**: реализуй `From`, `TryFrom`, `AsRef`, `AsMut`. Никогда не реализуй `Into` или
  `TryInto` напрямую. `From<u16> for u32` для безошибочного, `TryFrom<u32> for u16` для
  допускающего отказ; никогда `From<u32> for u16`.
- **C-COLLECT**: коллекции реализуют `FromIterator<T>` и `Extend<T>`, чтобы работали `collect`,
  `partition` и `unzip`.
- **C-SERDE**: типы структур данных реализуют `Serialize` и `Deserialize` за необязательной
  возможностью, названной ровно `serde`:
  `#[cfg_attr(feature = "serde", derive(Serialize, Deserialize))]`.
- **C-SEND-SYNC**: `Send` и `Sync` выводятся автоматически; проверяй их на типах с сырыми
  указателями и закрепляй тестом: `fn assert_send<T: Send>() {}`, затем
  `assert_send::<MyType>();`.
- **C-GOOD-ERR**: любой `E` в публичном `Result<T, E>` реализует `std::error::Error` и должен быть
  `Send + Sync`. Упакованные ошибки — `Box<dyn Error + Send + Sync + 'static>` (`'static` даёт
  `downcast_ref`). Никогда не используй `()` как тип ошибки. Сообщения `Display` в нижнем регистре,
  краткие, без завершающей пунктуации. Не реализуй устаревший `description()`.
- **C-NUM-FMT**: типы, похожие на числа, которые ты стал бы сочетать через `|` или `&` (битовые
  флаги), реализуют `LowerHex`, `UpperHex`, `Octal`, `Binary`. Величинам (`Nanoseconds(u64)`) они
  не нужны.
- **C-RW-VALUE**: обобщённые функции принимают `R: Read` и `W: Write` по значению; `&mut R` тоже
  реализует `Read`, поэтому вызывающие передают `&mut f`, чтобы продолжать им пользоваться. Скажи
  об этом в документации.

## Макросы

- **C-EVOCATIVE**: ввод макроса похож на вывод (`struct S: u32 { .. }`, элементы вида констант
  заканчиваются `;`).
- **C-MACRO-ATTR**: макросы, порождающие элементы, принимают атрибуты на каждом элементе, чтобы
  работали `#[cfg(..)]` и `#[derive(..)]`.
- **C-ANYWHERE**: макросы элементов работают в области модуля и функции; тестируй оба случая.
  Порождаемый `super::U` ломается внутри функции.
- **C-MACRO-VIS**: порождаемые элементы приватны, если во вводе не сказано `pub`.
- **C-MACRO-TY**: фрагмент `$t:ty` принимает примитивы, относительные и абсолютные пути, `super::`
  и обобщения. Не порождай вложенный `pub mod`, который не видит локальные типы.

## Документация

- **C-CRATE-DOC**: документация уровня пакета подробна и включает примеры.
- **C-EXAMPLE**: у каждого публичного модуля, трейта, структуры, перечисления, функции, метода,
  макроса и псевдонима типа есть пример — в разумных пределах. Показывай, зачем это использовать, а
  не механически как.
- **C-QUESTION-MARK**: примеры используют `?`, никогда `try!` или `unwrap()`, потому что
  пользователи копируют их дословно. Скрывай обвязку строками с `#`:

  ```rust
  /// ```
  /// # use std::error::Error;
  /// # fn main() -> Result<(), Box<dyn Error>> {
  /// let value = parse_it("...")?;
  /// # Ok(())
  /// # }
  /// ```
  ```

- **C-FAILURE**: `# Errors`, когда может вернуться `Err` (включая методы трейтов, чьи реализации
  могут отказать); `# Panics`, когда функция может упасть; `# Safety` у каждой `unsafe fn` с
  перечислением всех инвариантов вызывающего.
- **C-LINK**: связывай элементы в прозе через `` [`Type`] ``.
- **C-METADATA**: в `[package]` есть `authors`, `description`, `license`, `repository`, `keywords`,
  `categories`; `documentation` только если это не docs.rs; `homepage` только если отличается от
  `repository`.
- **C-RELNOTES**: веди заметки о релизах, отмечай ломающие изменения и помечай релизы
  аннотированными тегами (`git tag -a`).
- **C-HIDDEN**: `#[doc(hidden)]` на реализациях, которые пользователи никогда не вызывают
  (`From<PrivateError> for PublicError` существует только чтобы работал `?`). Для внутренностей
  используй `pub(crate)`.

## Предсказуемость

- **C-SMART-PTR**: умные указатели не добавляют собственных методов; используй ассоциированные
  функции (`Box::into_raw(b)`, а не `b.into_raw()`), чтобы вызов не был неоднозначен с целевым
  значением.
- **C-CONV-SPECIFIC**: размещай преобразования на более конкретном типе (`str::as_bytes`,
  `str::from_utf8`). Предпочитай `to_`, `as_` и `into_` вместо `from_`: они лучше выстраиваются в
  цепочки.
- **C-METHOD**: если у функции есть явный получатель, сделай её методом
  (`impl Foo { fn frob(&self, w: Widget) }`). Методам не нужен импорт, они автоматически берут
  ссылку и выражают владение через `self`.
- **C-NO-OUT**: возвращай несколько значений кортежем или структурой, а не выходными параметрами
  `&mut`. Исключение: переиспользование буфера, принадлежащего вызывающему (`Read::read`).
- **C-OVERLOAD**: реализуй трейты `std::ops` только когда операция похожа на оператор и разделяет
  его свойства (`Mul` должна быть ассоциативной).
- **C-DEREF**: только умные указатели реализуют `Deref` и `DerefMut`. Правила приведения и
  разрешения методов рассчитаны на них (`Box`, `String`, `Rc`, `Arc`, `Cow`).
- **C-CTOR**: конструкторы — статические собственные методы. Основной — `new()`; вторичные
  получают суффикс `_with_foo` (`open_with_offset`); ресурсы ввода-вывода используют доменные имена
  (`File::open`, `TcpStream::connect`); конструкторы-преобразования называются `from_foo` и могут
  быть `unsafe` (`Box::from_raw`) или принимать дополнительные аргументы (`u64::from_str_radix`),
  в отличие от `From`. Много параметров — значит конструктор.

## Гибкость

- **C-INTERMEDIATE**: раскрывай уже сделанную работу. `binary_search` сообщает индекс вставки при
  промахе; ошибка `String::from_utf8` возвращает длину валидного префикса и байты;
  `HashMap::insert` возвращает старое значение.
- **C-CALLER-CONTROL**: если функции нужно владение, принимай по значению и никогда не клонируй
  заимствование внутри. Если она только читает или изменяет, принимай `&` или `&mut`. Ограничивай
  через `Copy`, только когда это требуется, а не чтобы заявить о дешевизне.
- **C-GENERIC**: предполагай как можно меньше. Только перебираешь?
  `fn foo<I: IntoIterator<Item = i64>>(iter: I)`, а не `&[i64]`. `File::open` принимает
  `AsRef<Path>`. Цена: размер кода, один конкретный тип на параметр, многословные подписи.
- **C-OBJECT**: решай заранее, трейт — это ограничение или объект. Обобщённые методы и `Self` вне
  получателя блокируют объектную безопасность; исключай их через `where Self: Sized`:

  ```rust
  trait MyTrait {
      fn object_safe(&self, i: i32);
      fn not_object_safe<T>(&self, t: T) where Self: Sized;
  }
  ```

## Безопасность типов

- **C-NEWTYPE**: `struct Miles(pub f64)` против `struct Kilometers(pub f64)` даёт статические
  различия при нулевой стоимости во время выполнения. (В руководстве приводят Mars Climate
  Orbiter.)
- **C-CUSTOM-TYPE**: не передавай `bool`, `u8` или `Option` там, где смысл неоднозначен.
  `Widget::new(Small, Round)`, а не `Widget::new(true, false)`. Перечисления к тому же могут
  расти позже.
- **C-BITFLAG**: независимые флаги используют пакет `bitflags`; перечисление моделирует ровно один
  выбор. Явные дискриминанты подходят для сериализации и взаимодействия с C.
- **C-BUILDER**: вводи `TBuilder`, когда у типа много входных данных, составные данные,
  необязательная конфигурация, несколько разновидностей или побочные эффекты при сборке.
  Конструктор принимает только обязательные данные, методы конфигурации выстраиваются в цепочку,
  терминальные методы собирают. Предпочитай непоглощающие конструкторы (`&mut self -> &mut Self`,
  терминальный `&self`): `Command::new("cat").arg("f").spawn()`. Поглощающие — только когда
  терминальный метод должен переместить значение наружу.

## Надёжность

- **C-VALIDATE**: обеспечивай валидность в порядке предпочтения: статически (тип, исключающий
  неверный ввод, `fn foo(a: Ascii)` вместо `fn foo(a: u8)`), динамически (проверяй по ходу,
  `debug_assert!` для дорогих проверок), с возможностью отказа (собратья `_unchecked` или модуль
  `raw` для уверенных вызывающих).
- **C-DTOR-FAIL**: деструкторы никогда не отказывают; отказ во время раскрутки стека прерывает
  процесс. Давай `close(self) -> Result<..>`, а `Drop` пусть работает по мере сил.
- **C-DTOR-BLOCK**: деструкторы не блокируют. Предлагай отдельный метод, который готовит
  безотказное неблокирующее завершение.

## Отлаживаемость

- **C-DEBUG**: все публичные типы реализуют `Debug`. Исключения редки.
- **C-DEBUG-NONEMPTY**: даже пустые значения дают непустой вывод `Debug` (`""` -> `"\"\""`, пустой
  вектор -> `"[]"`).

## Задел на будущее

- **C-SEALED**: шаблон запечатанного трейта позволяет добавлять методы, не ломая пользователей:

  ```rust
  pub trait TheTrait: private::Sealed { /* ... */ }
  impl TheTrait for usize { /* ... */ }
  mod private {
      pub trait Sealed {}
      impl Sealed for usize {}
  }
  ```

  Документируй, что трейт запечатан.
- **C-STRUCT-PRIVATE**: поля приватны по умолчанию; публичное поле фиксирует представление и
  блокирует инварианты. Публичные поля только для пассивных данных в стиле C.
- **C-NEWTYPE-HIDE**: скрывай типы реализации за новым типом
  (`pub struct MyIter<I>(Enumerate<Skip<I>>)`), чтобы внутренний тип можно было менять. `impl Trait`
  короче, но неудобен для ограничений `Debug` и `Clone`; годится для внутренних API.
- **C-STRUCT-BOUNDS**: никаких выводимых ограничений в определениях структур.
  `#[derive(Clone, Debug, PartialEq)] struct Good<T>`, а не
  `struct Bad<T: Clone + Debug + PartialEq>`. Никогда не ограничивай структуру данных через
  `Clone`, `PartialEq`, `PartialOrd`, `Debug`, `Display`, `Default`, `Error`, `Serialize`,
  `Deserialize`. Исключения: ссылки на ассоциированные типы, `?Sized`, реализация `Drop`, которой
  нужно ограничение.

## Необходимое

- **C-STABLE**: пакету версии 1.0+ нужно, чтобы каждая публичная зависимость (любой пакет, чьи типы
  появляются в его API) тоже была стабильной. `From<other_crate::Error>` раскрывает
  `other_crate`.
- **C-PERMISSIVE**: `license = "MIT OR Apache-2.0"` с обоими файлами лицензий, как у самого Rust.
  Завись только от пакетов с разрешительными лицензиями.
