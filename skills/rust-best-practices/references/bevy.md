# Bevy (краткий пересказ)

Источники: документация API Bevy 0.20 (https://docs.rs/bevy/0.20.0 и
https://docs.rs/bevy_ecs/0.20.0), собственная конфигурация линтов Bevy в публикуемом
`Cargo.toml` и руководства по миграции на https://bevy.org/learn/migration-guides/.
Проверено на bevy 0.20.0 (октябрь 2026); каждое описанное ниже поведение подтверждено тестом
на этой версии. Читай это, когда `Cargo.toml` зависит от `bevy` или `bevy_ecs`.

Сначала проверь версию Bevy в проекте. Bevy ломает API в каждом выпуске (0.17 переименовал
события в сообщения, 0.20 изменил дженерики наблюдателей), поэтому, если они расходятся,
следуй версии из `Cargo.lock`, а не этому файлу.

Bevy вызывает твои системы и строит их аргументы, поэтому несколько общих правил не подходят
для системных функций. Исключения ниже заменяют их только для кода Bevy. Всё остальное в
навыке (ошибки, паники, именование, тесты, `unsafe`) по-прежнему действует.

## Сохраняй соглашения Bevy

**Параметры систем принимаются по значению.** `Res<T>`, `ResMut<T>`, `Query<D, F>`,
`Single<D, F>`, `Commands`, `Local<T>`, `MessageReader<M>` и `MessageWriter<M>` — это уже
заимствования, которые Bevy передаёт системе на один запуск. Не меняй их на `&Res<T>` и не
сообщай о них как о лишней передаче по значению. Обычные советы по заимствованию действуют
внутри системы и для вспомогательных функций, которые она вызывает: передавай `&Health`, а не
целый `Query`.

**Используй `use bevy::prelude::*`.** Prelude — документированный шаблон импорта Bevy, а
`wildcard_imports` в clippy уже исключает пути, содержащие `prelude`. Правило против
glob-импортов по-прежнему действует для твоих собственных модулей, поэтому не изобретай
prelude приложения.

**Компоненты и ресурсы с простыми данными могут иметь публичные поля.** `Health(pub u32)` и
`Velocity(pub Vec2)` — пассивные данные, которые многие системы читают и пишут, а это и есть
исключение для пассивных данных из раздела 4 в SKILL.md. Держи поля приватными, только когда
они должны вместе поддерживать инвариант, например список, который должен оставаться
отсортированным. Настройки вроде скорости регенерации и предела — простые данные: обеспечивай
предел в системе, которая его применяет, а не геттерами и паникующим конструктором.

**Сложные запросы и много параметров — это нормально.** Собственная рабочая область Bevy
разрешает `clippy::type_complexity` и `clippy::too_many_arguments`. Разрешай их на уровне
крейта или дай запросу, который переиспользуют несколько систем, псевдоним `type`. Не разделяй
систему и не оборачивай её запросы в собственный `SystemParam` только чтобы заглушить линт;
выводи `SystemParam`, когда группа параметров переиспользуется и заслуживает имени.

**Линты.** Линты BeautifulRust в `lints/lints.toml` включают `rust_2018_idioms` и педантичную
группу clippy, а они срабатывают на каждой идиоматичной сигнатуре системы. В крейте Bevy
добавь эти строки в существующие таблицы `[lints.rust]` и `[lints.clippy]`:

```toml
# under [lints.rust]
elided_lifetimes_in_paths = "allow"   # write Res<Time>, not Res<'_, Time>

# under [lints.clippy]
needless_pass_by_value = "allow"      # system parameters are passed by value
type_complexity = "allow"             # query types; Bevy's own workspace allows this
too_many_arguments = "allow"          # systems take many parameters; so does Bevy
```

## Проверки корректности

Это те баги Bevy, которые компилируются без ошибок. Проверяй на них каждую систему, когда
пишешь или проверяешь код.

**Конфликтующие запросы паникуют.** Два параметра одной системы, которые могли бы изменяемо
добраться до одного компонента, компилируются, но система паникует с ошибкой B0001 при первом
запуске. `Query<&mut Health, With<Player>>` и `Query<&mut Health, With<Enemy>>` конфликтуют,
потому что одна сущность может иметь оба маркера. `Res<T>` рядом с `ResMut<T>` того же типа
паникует так же (B0002). Сделай запросы непересекающимися через `Without` или помести их в
`ParamSet`, когда они действительно пересекаются и используются по одному. Выбирай фильтр,
который соответствует правилам игры, а не тот, который просто компилируется.

```rust
fn apply_hits(
    mut players: Query<&mut Health, (With<Player>, Without<Enemy>)>,
    mut enemies: Query<&mut Health, (With<Enemy>, Without<Player>)>,
) {
    // Each query now covers a separate set of entities.
}
```

**`Commands` отложены.** `spawn`, `insert` и `despawn` ставятся в очередь и вступают в силу на
следующей точке синхронизации (`ApplyDeferred`). Bevy вставляет её автоматически между двумя
системами с явным порядком (`.chain()`, `.before()`, `.after()`), когда у первой есть
`Commands`. Без порядка другая система может выполниться до применения поставленных изменений
и увидеть старый мир. Система, которой нужно увидеть `spawn` или `despawn` другой системы,
требует явного порядка.

**Упорядочивай системы, которые зависят друг от друга.** Системы, добавленные одним кортежем
без `.chain()`, не имеют порядка, и Bevy может запускать их в любом порядке от кадра к кадру.
Если одна система читает то, что пишет другая в том же кадре (ресурс, сообщение, компонент
или `spawn`), задай им порядок: `.chain()` для конвейера, `.after()` для одного ребра или
наборы систем для больших групп.

```rust
// check_wave_cleared must not run after spawn_wave's spawns are queued but not
// yet applied, or it sees no enemies and starts a second wave.
app.add_systems(Update, (check_wave_cleared, spawn_wave).chain());
```

**Не разворачивай запросы.** `Query::single()` и `get(entity)` возвращают `Result`, а
`.unwrap()` роняет игру, когда игрок умирает или появляется вторая камера. Используй
`Single<D, F>`, который пропускает систему, если не совпадает ровно одна сущность, или
`let Ok(..) = .. else { return };`. Система также может возвращать `Result` и использовать `?`,
но обработчик ошибок Bevy по умолчанию паникует. Установи более тихий, если хочешь именно
этого: `app.insert_resource(FallbackErrorHandler(warn))`.

```rust
fn contact_damage(player: Single<(Entity, &Position), With<Player>>) {
    let (player, position) = *player;
    // Runs only while exactly one player exists.
}
```

**Команды над сущностью, которой может уже не быть.** Команда над сущностью, удалённой ранее в
этом кадре, при применении даёт ошибку, и обработчик по умолчанию паникует. Защищайся от
двойного удаления (два попадания убивают одного врага в одном кадре) или используй
`try_insert` и `try_despawn`, когда сущности может уже не быть.

**Сообщения читаются по одному разу на читателя.** Каждый `MessageReader` видит сообщение один
раз. Читатель, который выполняется в кадре раньше писателя, увидит это сообщение в следующем
кадре, поэтому ставь читателя после его писателя, когда реакция нужна в том же кадре.

## Тестирование систем

Прогоняй системы через `App` без интерфейса и без `DefaultPlugins`. Вставь ресурсы, которые
нужны системам, и продвигай `Time` вручную, чтобы тест был детерминированным.

```rust
#[test]
fn units_move_by_velocity() {
    let mut app = App::new();
    app.init_resource::<Time>().add_systems(Update, move_units);
    let unit = app.world_mut().spawn((Position(Vec2::ZERO), Velocity(Vec2::X * 10.0))).id();
    app.world_mut().resource_mut::<Time>().advance_by(Duration::from_secs(2));

    app.update();

    assert_eq!(app.world().get::<Position>(unit), Some(&Position(Vec2::X * 20.0)));
}
```

Добавь ещё один дымовой тест, который подключает весь плагин и дважды вызывает `app.update()`.
Конфликтующие запросы и отсутствующие ресурсы проявляются только при первом запуске системы,
поэтому тесты, добавляющие системы по одной, могут все проходить, пока плагин паникует на
первом кадре.
