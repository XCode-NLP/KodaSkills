# Линты схем

Статические линты для `input_schema` возможности. Чистота схемы — это вопрос *читаемости
для агента*: оркестрирующие агенты читают схему, чтобы понять, как вызвать возможность.
Схема, которую трудно разобрать, которая неоднозначна или вводит в заблуждение, тратит ходы
даже когда сама возможность работает.

Эти линты — шесть небольших принципов. Применяй их, читая схему, а не механически прогоняя
grep: в большинстве плагинов достаточно разнообразия форматирования, чтобы рецепты с grep
устаревали.

## Линт 1 — `additionalProperties: false` для схем-объектов

Для схем верхнего уровня с `'type' => 'object'` объявляй `'additionalProperties' => false`,
если ты намеренно не принимаешь лишние поля. Без этого агент, передавший опечатку (`par_page`
вместо `per_page`), получит молчаливое принятие, и значение уйдёт в источник, который
проигнорирует неизвестный ключ.

- `additionalProperties: false` объявлен → OK.
- `additionalProperties: true` объявлен → WARN, если схема не описывает действительно
  свободные метаданные (пользовательские поля платежа, свободный текст формы); причину
  опиши прямо в коде.
- Не объявлен в схеме-объекте → WARN.
- Корень не объект (строка с перечислением, целое и т.п.) → не применимо. Линт действует
  только на объекты.

## Линт 2 — у каждого обязательного поля есть непустое описание

Для каждой записи в `required` соответствующая запись в `properties` должна объявлять
непустой `description`. Обязательные поля — там, где агентам особенно нужны подсказки;
непрозрачный обязательный ключ заставляет агента угадывать по одному имени поля. Пусто или
отсутствует → FAIL.

Описания необязательных полей желательны, но их отсутствие → WARN.

## Линт 3 — перечисления непусты

`'enum' => []` не принимает ни одного значения и отклоняет любой ввод. Почти всегда это
ошибка. → FAIL.

Перечисление из одного значения (`'enum' => [ 'pending' ]`) допустимо, но необычно; WARN с
просьбой проверить — часто это копипаста, потерявшая остальные значения.

## Линт 4 — никаких `$ref`

Агенты читают схему через самоописание REST. `$ref` заставляет агента переходить по ссылке,
чтобы увидеть форму поля: тратится ход и часто ломается, потому что упомянутая схема не в том
же документе. Вписывай форму прямо в схему.

Любой `'$ref'` в схеме → FAIL.

## Линт 5 — значения по умолчанию статически постоянны

Каждое значение `'default'` должно давать одинаковую форму при каждом вызове:

- Скалярные литералы — `true`, `false`, целое, число с плавающей точкой, строка в кавычках,
  `null` → OK.
- Пустые массивы или массивы только из литералов — `[]`, `array()`, `[ 'a', 'b' ]` → OK.
- Литерал, приведённый к пустому объекту, — `(object) array()`, `(object) []` → OK. Это
  рекомендуемое значение по умолчанию верхнего уровня для возможностей, допускающих вызов без
  аргументов; см. `../../wp-abilities-api/references/input-schema-gotchas.md`, §4.
- `new stdClass()` без аргументов → OK.
- Вызов функции (`gmdate('c')`, `wp_generate_uuid4()`, `time()`), ссылка на переменную или
  другое вычисляемое выражение → FAIL.

Принцип: значения по умолчанию, меняющиеся от вызова к вызову, и недетерминированы, и
неожиданны для агентов, которые ждут от них постоянства.

## Линт 6 — `reference_ability: true` означает отсутствие обязательного ввода

Если передан документ аудита и у возможности стоит `reference_ability: true`, её
`input_schema.required` должен быть пустым или отсутствовать. Эталонная возможность — самый
маленький и безопасный загрузочный вызов, который исполнитель реализует первым; она должна
работать при `execute([])`. Обязательный ввод у эталонной возможности → FAIL.

(Аудит не передан → линт пропускается: эталонная возможность не объявлена.)

## Сверка: ловушки 1–3 (укрепление колбэка) и ловушка 4 (структурное значение по умолчанию)

Статические линты ловят форму; четыре ловушки времени выполнения из
`../../wp-abilities-api/references/input-schema-gotchas.md` делятся на два вида.

Ловушки 1–3 требуют защитного кода в колбэке выполнения: `array_key_exists` вместо одного
`isset` для значений по умолчанию свойств, перевод ключей пагинации, проверка идентификатора,
принимающая `"0"`. Это поведение времени выполнения, и статические линты схемы его не
обеспечат.

Ловушка 4 — разная строгость прямого и косвенного вызова — как раз и мотивирует значение по
умолчанию верхнего уровня `(object) array()`, которое линт 5 явно допускает. Оно структурное,
и линт 5 его обеспечивает.

## Формат вывода

```markdown
## Schema lints

| Ability | Lint | Result | Detail |
|---|---|---|---|
| <ability> | additionalProperties (object schemas) | WARN | not declared on object schema |
| <ability> | required-field descriptions | OK | 3/3 required fields documented |
| <ability> | enum non-empty | OK | no enums |
| <ability> | no $ref | OK | inline |
| <ability> | static defaults | FAIL | `created_at` uses `gmdate('c')` |
| <ability> | reference_ability implies no required | N/A | not reference ability |
```

FAIL по любому линту переводит возможность в FAIL в сводке прогона. WARN видны, но не
блокируют.
