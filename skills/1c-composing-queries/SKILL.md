# Составление запросов 1С

Правила и приёмы написания корректных запросов на языке запросов 1С:Предприятие. Запросы выполняются через инструмент `execute_query` или соответствующий эндпоинт.

## КРИТИЧНО: проверь метаданные до запроса

**Никогда не угадывай и не придумывай имена объектов метаданных, реквизитов и табличных частей.** Конфигурации 1С сильно различаются: имена объектов и полей уникальны для каждой базы.

Перед составлением запроса, если ты не уверен в точных именах, **используй `get_metadata` или любой доступный инструмент получения метаданных конфигурации**, чтобы узнать:

- какие объекты метаданных есть (справочники, документы, регистры и так далее);
- реквизиты объектов и их типы;
- табличные части и их колонки;
- измерения, ресурсы и реквизиты регистров.

**Порядок работы:** получить метаданные, подтвердить имена, составить запрос, **проверить запрос**, выполнить запрос.

Запрос с неверным именем объекта или поля упадёт с ошибкой выполнения. Один вызов за метаданными всегда дешевле отладки упавшего запроса.

## Имена таблиц и полей из AI-EDT

Если сервер AI-EDT подключён, имена не угадываются, а берутся у него: `insights operation=describe_db_tables` (отдельное имя `describe_db_tables` тоже работает). Инструмент показывает, во что объект превращается в базе данных: основную таблицу, по одной на каждую табличную часть, виртуальные таблицы регистра (остатки, обороты, срезы) с их параметрами, таблицу изменений и перерасчёты регистра расчёта. Имена таблиц и полей отдаются сразу на двух языках, с типами полей, готовыми к подстановке после `ИЗ`.

Это дешевле, чем писать запрос по памяти и ловить ошибки имён по одной через `validate_query`: за один вызов видно всё, что вообще можно выбрать.

## Проверка запроса через AI-EDT

Если сервер AI-EDT подключён (инструменты `ai-edt` доступны), **обязательно проверяй запрос** перед выполнением через `validate_query`:

- проверяет синтаксис и семантику в контексте реального проекта;
- для запросов СКД передавай `dcsMode=true`;
- ловит ошибки имён таблиц, полей и типов до выполнения.

**Оформление:** текст запроса всегда многострочный — в исходниках, диагностических скриптах, примерах и ответах. Список полей, `ИЗ`, `ГДЕ`, соединения, группировка и сортировка — на отдельных строках; в BSL это многострочный строковый литерал со строками, начинающимися с `|`. Для передачи в `validate_query` или `execute_query` запрос в одну строку не сворачивай.

## Структура запроса

Канонический порядок секций (обязательная отмечена, остальные необязательны):

```
ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ <N>]
 <список полей>
ИЗ
 <источники данных>
[ГДЕ <условие>]
[СГРУППИРОВАТЬ ПО <поля>]
[ИМЕЮЩИЕ <условие>]

[ОБЪЕДИНИТЬ [ВСЕ]
ВЫБРАТЬ ...]

[УПОРЯДОЧИТЬ ПО <поля> [ВОЗР | УБЫВ]]
[АВТОУПОРЯДОЧИВАНИЕ]

[ИТОГИ <агрегатные выражения> ПО [ОБЩИЕ] <точки контроля>]
```

**Ключевые слова:**

| Ключевое слово | Значение |
|---------|---------|
| `ВЫБРАТЬ` | SELECT — обязательное, начинает запрос |
| `РАЗРЕШЕННЫЕ` | Учитывать ограничения доступа на уровне записей (RLS). Используй по умолчанию ради безопасности |
| `РАЗЛИЧНЫЕ` | DISTINCT — убрать повторяющиеся строки |
| `ПЕРВЫЕ N` | Вернуть только первые N строк (в 1С нет LIMIT — это единственный способ) |
| `ИЗ` | FROM — источники данных |
| `ГДЕ` | WHERE — фильтр строк |
| `СГРУППИРОВАТЬ ПО` | GROUP BY |
| `ИМЕЮЩИЕ` | HAVING — фильтр групп |
| `ОБЪЕДИНИТЬ [ВСЕ]` | UNION [ALL] |
| `УПОРЯДОЧИТЬ ПО` | ORDER BY. `ВОЗР` — по возрастанию, `УБЫВ` — по убыванию |
| `АВТОУПОРЯДОЧИВАНИЕ` | Автопорядок по представлению (используется редко) |
| `ИТОГИ` | TOTALS — вычисление промежуточных итогов |

Комментарии: `// только однострочные`.

Минимальный пример:

```
ВЫБРАТЬ Ссылка, Наименование
ИЗ Справочник.Контрагенты
ГДЕ НЕ ПометкаУдаления
```

## Имена таблиц и источники

У каждого объекта метаданных 1С есть фиксированный шаблон имени в запросе. Используй точные имена из `get_metadata`.

### Реальные таблицы

| Тип объекта | Шаблон имени в запросе | Пример |
|-------------|-------------------|---------|
| Справочник | `Справочник.<Имя>` | `Справочник.Номенклатура` |
| Документ | `Документ.<Имя>` | `Документ.РеализацияТоваровУслуг` |
| Табличная часть документа | `Документ.<Имя>.<Часть>` | `Документ.РеализацияТоваровУслуг.Товары` |
| Регистр накопления | `РегистрНакопления.<Имя>` | `РегистрНакопления.ОстаткиТоваров` |
| Регистр сведений | `РегистрСведений.<Имя>` | `РегистрСведений.КурсыВалют` |
| Регистр бухгалтерии | `РегистрБухгалтерии.<Имя>` | `РегистрБухгалтерии.Хозрасчетный` |
| План счетов | `ПланСчетов.<Имя>` | `ПланСчетов.Хозрасчетный` |

### Значения перечислений и предопределённые элементы

```
// Значение перечисления (в условиях, не как таблица):
ЗНАЧЕНИЕ(Перечисление.ТипыЦен.Оптовая)

// Предопределённый элемент справочника:
ЗНАЧЕНИЕ(Справочник.Валюты.USD)

// Пустая ссылка:
ЗНАЧЕНИЕ(Справочник.Контрагенты.ПустаяСсылка)
```

### Виртуальные таблицы

Виртуальные таблицы вычисляются на лету из реальных данных регистра. **Всегда передавай условия отбора параметрами виртуальной таблицы, а НЕ в ГДЕ** — это критично для производительности.

**Регистр накопления:**

```
// Текущие остатки (без даты — на последний момент):
РегистрНакопления.ОстаткиТоваров.Остатки(, Номенклатура = &Ном)

// Остатки на конкретную дату:
РегистрНакопления.ОстаткиТоваров.Остатки(&Дата, Склад = &Склад)

// Обороты за период:
РегистрНакопления.ОстаткиТоваров.Обороты(&НачДата, &КонДата, , Номенклатура = &Ном)

// Остатки и обороты:
РегистрНакопления.ОстаткиТоваров.ОстаткиИОбороты(&НачДата, &КонДата, , , Номенклатура = &Ном)
```

**Регистр сведений:**

```
// Последние значения (срез последних):
РегистрСведений.КурсыВалют.СрезПоследних(&Дата, Валюта = &Валюта)

// Первые значения (срез первых):
РегистрСведений.КурсыВалют.СрезПервых(&Дата, Валюта = &Валюта)
```

**Регистр бухгалтерии:**

Пять виртуальных таблиц: Остатки, Обороты, ОстаткиИОбороты, ОборотыДтКт, ДвиженияССубконто.

Сигнатуры ниже приведены для регистров с корреспонденцией (`КорреспондирующиеСчета = Истина`, например типовой `Хозрасчетный`). Для регистров без корреспонденции `.ОборотыДтКт` и `.ДвиженияССубконто` отсутствуют, у `.Обороты` нет `УсловиеКорСчета` и `КорСубконто`.

```
// Остатки на дату:
РегистрБухгалтерии.Хозрасчетный.Остатки(&Период, Счет = &Счет, , )

// Обороты за период:
РегистрБухгалтерии.Хозрасчетный.Обороты(&НачДата, &КонДата, Месяц, Счет В (&Счета), , , , )

// Остатки и обороты:
РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(&НачДата, &КонДата, Авто, , Счет = &Счет, , )

// Обороты дебет-кредит (детальная корреспонденция):
РегистрБухгалтерии.Хозрасчетный.ОборотыДтКт(&НачДата, &КонДата, , , , , , )

// Детальные записи с субконто:
РегистрБухгалтерии.Хозрасчетный.ДвиженияССубконто(&НачДата, &КонДата, , , )
```

Параметры виртуальных таблиц (позиционный порядок):

| Виртуальная таблица | Параметры |
|---------------|------------|
| `.Остатки` | Период, УсловиеСчета, Субконто, Условие |
| `.Обороты` | НачалоПериода, КонецПериода, Периодичность, УсловиеСчета, Субконто, Условие, УсловиеКорСчета, КорСубконто |
| `.ОстаткиИОбороты` | НачалоПериода, КонецПериода, Периодичность, МетодДополненияПериодов, УсловиеСчета, Субконто, Условие |
| `.ОборотыДтКт` | НачалоПериода, КонецПериода, Периодичность, УсловиеСчетаДт, СубконтоДт, УсловиеСчетаКт, СубконтоКт, Условие |
| `.ДвиженияССубконто` | НачалоПериода, КонецПериода, Условие, Порядок, Первые |

Замечание: справка платформы (синтакс-помощник) для регистра бухгалтерии часто опускает `УсловиеСчета`, `УсловиеКорСчета`, `УсловиеСчетаДт` и `УсловиеСчетаКт`. Эти параметры реально существуют и работают: без них смещается весь позиционный список, и `Счет = ...` попадает в позицию `Субконто` — тип не совпадёт, отбор не сработает.

**Ключевые отличия от регистра накопления:**

- **Параметр Субконто** принимает виды субконто (ссылки на план видов характеристик), а НЕ значения. Фильтруй по значениям субконто в `Условие`: `Субконто1 = &Контрагент`.
- **Счёт и КорСчёт** фильтруются отдельными параметрами `УсловиеСчета` и `УсловиеКорСчета`, а не в `Условие`: `Счет = &Счет`, `Счет В ИЕРАРХИИ(&Счет)`. Для `ОборотыДтКт` — `УсловиеСчетаДт` и `УсловиеСчетаКт`.
- **Периодичность**: Авто, Период, Год, Полугодие, Квартал, Месяц, Декада, Неделя, День, Регистратор, Запись.
- **МетодДополненияПериодов** (только для ОстаткиИОбороты): `Движения` или `ДвиженияИГраницыПериода` (по умолчанию).
- У ресурсов есть суффиксы Дт и Кт — см. таблицу ниже.

Синтаксис параметров внутри виртуальных таблиц: `Измерение = Значение` через запятую. Держи просто: никаких подзапросов и соединений внутри параметров.

**Суффиксы ресурсов регистра накопления:**

При использовании виртуальных таблиц поля ресурсов получают автоматические суффиксы:

| Виртуальная таблица | Формат суффикса | Пример |
|---------------|---------------|---------|
| `.Остатки` | `<Ресурс>Остаток` | `КоличествоОстаток` |
| `.Обороты` | `<Ресурс>Оборот` | `КоличествоОборот` |
| `.ОстаткиИОбороты` | `<Ресурс>НачальныйОстаток` | `КоличествоНачальныйОстаток` |
| `.ОстаткиИОбороты` | `<Ресурс>Приход` | `КоличествоПриход` |
| `.ОстаткиИОбороты` | `<Ресурс>Расход` | `КоличествоРасход` |
| `.ОстаткиИОбороты` | `<Ресурс>Оборот` | `КоличествоОборот` |
| `.ОстаткиИОбороты` | `<Ресурс>КонечныйОстаток` | `КоличествоКонечныйОстаток` |

```

 Об.Номенклатура,
```

### Псевдонимы таблиц

```
Справочник.Номенклатура КАК Товары
```

Всегда назначай **содержательные** псевдонимы: они должны быть понятны без контекста.

- **Не** используй однобуквенные (`Р`, `Т`, `С`) и загадочные сокращения (`ВТДок`, `ДокГР`).
- Для длинных имён таблиц сокращай осмысленно: `РасчетыНДФЛ`, `РезидентствоФЛ`, `ВедомостиЗП`.
- Для временных таблиц в качестве источника повторяй имя таблицы или сокращай его осмысленно.

```
// Плохо:
РегистрНакопления.РасчетыНалогоплательщиковСБюджетомПоНДФЛ КАК Р

// Хорошо:
РегистрНакопления.РасчетыНалогоплательщиковСБюджетомПоНДФЛ КАК РасчетыНДФЛ

// Плохо:
ВТДокументОснованияДляУвольнений КАК ВТУвольнения

// Хорошо:
ВТДокументОснованияДляУвольнений КАК ДокументыУвольнений
```

Псевдонимы обязательны при самосоединении и при использовании одной таблицы дважды.

### Иерархические справочники

Справочники с иерархией поддерживают вложенные группы:

```
// Непосредственные потомки (один уровень) — предпочтительно:
ВЫБРАТЬ Наименование
ИЗ Справочник.Номенклатура
ГДЕ Родитель = &Родитель

// Или по имени:
ГДЕ Родитель.Наименование = "Бытовая техника"

// Все элементы группы и подгрупп — предпочтительно:
ВЫБРАТЬ Наименование
ИЗ Справочник.Номенклатура
ГДЕ Ссылка В ИЕРАРХИИ (&Группа)

// Или по имени:
ГДЕ Ссылка В ИЕРАРХИИ (
 ВЫБРАТЬ Ссылка ИЗ Справочник.Номенклатура
 ГДЕ Наименование = "Бытовая техника"
)

// Только элементы, не группы:
ГДЕ ЭтоГруппа = ЛОЖЬ

// Только группы:
ГДЕ ЭтоГруппа = ИСТИНА
```

**Правила:**

- `Родитель = &Родитель` — только непосредственные потомки (один уровень);
- `Ссылка В ИЕРАРХИИ (&Группа)` — все вложенные уровни;
- `ЭтоГруппа` — `ИСТИНА` только группы, `ЛОЖЬ` только элементы;
- **ИЗБЕГАЙ** `В ИЕРАРХИИ (ПустаяСсылка)` — очень медленно.

## Выбор полей

- `*` выбирает все реальные поля (виртуальные поля НЕ включаются).
- Псевдонимы: `<выражение> КАК <Псевдоним>` — псевдонимы должны быть уникальны в пределах запроса.
- Доступ к вложенным полям через точку: `Товары.Номенклатура.Наименование`.

### КРИТИЧНО: разыменование поля составного типа

Когда поле может ссылаться на несколько типов таблиц (составной тип), обращение через точку создаёт неявные соединения со **ВСЕМИ** возможными таблицами. Это сильно снижает производительность.

**Всегда сужай тип через ВЫРАЗИТЬ:**

```
// ПЛОХО — соединение со всеми возможными таблицами регистраторов:
ВЫБРАТЬ Регистратор.Номер ИЗ РегистрНакопления.ОстаткиТоваров

// ХОРОШО — одно соединение:
ВЫБРАТЬ ВЫРАЗИТЬ(Регистратор КАК Документ.РеализацияТоваровУслуг).Номер
ИЗ РегистрНакопления.ОстаткиТоваров
ГДЕ Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
```

### Обработка NULL

- Используй `ЕСТЬNULL(поле, значение)` для полей, которые могут быть NULL (например, после ЛЕВОГО СОЕДИНЕНИЯ).
- Проверяй NULL через `ЕСТЬ NULL` и `НЕ ЕСТЬ NULL`, а не через `= NULL`.

### Пустая таблица для ОБЪЕДИНИТЬ

Когда объединяются запросы с разной структурой вложенных таблиц:

```
ПУСТАЯТАБЛИЦА.(Номенклатура, Количество, Цена)
```

## ГДЕ и ИМЕЮЩИЕ

### Операторы

| Оператор | Синтаксис 1С | Примечания |
|----------|-----------|------|
| Равно | `=` | |
| Не равно | `<>` | |
| Сравнение | `<`, `>`, `<=`, `>=` | |
| И | `И` | |
| Или | `ИЛИ` | Избегай в ГДЕ — см. оговорки |
| Не | `НЕ` | |
| Диапазон | `МЕЖДУ X И Y` | Включает обе границы |
| В списке | `В (знач1, знач2, ...)` | |
| В подзапросе | `В (ВЫБРАТЬ ...)` | |
| Проверка NULL | `ЕСТЬ NULL` / `НЕ ЕСТЬ NULL` | Никогда не используй `= NULL` |
| Проверка типа | `ССЫЛКА Документ.Реализация...` | Проверяет тип ссылки |
| Шаблон | `ПОДОБНО "шаблон"` | `%` — любая строка, `_` — один символ |
| ВЫБОР | `ВЫБОР КОГДА ... ТОГДА ... ИНАЧЕ ... КОНЕЦ` | Только в неиндексируемых условиях |

**Приоритет операторов:** `НЕ` выше `И`, `И` выше `ИЛИ`. Используй скобки для явного приоритета.

### Ключевые правила

- **ИЛИ ухудшает использование индексов.** Заменяй на `В (...)` где возможно или разбивай на `ОБЪЕДИНИТЬ ВСЕ`.
- **ВЫБОР в ГДЕ:** только в дополнительных (неиндексируемых) условиях.
- **Сравнение строк:** без учёта регистра, игнорирует хвостовые пробелы.
- **Арифметика в ГДЕ:** только в дополнительных условиях, иначе индекс не используется.
- **Шаблон ПОДОБНО:** не должен начинаться с `%` или `_` в индексируемом условии.

Стратегия оптимизации с учётом индексов — в [references/optimization-and-pitfalls.md](references/optimization-and-pitfalls.md).

## Соединения

```
ИЗ Документ.РеализацияТоваровУслуг КАК Док
 ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты КАК Конт
 ПО Док.Контрагент = Конт.Ссылка
```

| Тип | Синтаксис 1С |
|------|-----------|
| Внутреннее | `ВНУТРЕННЕЕ СОЕДИНЕНИЕ ... ПО` |
| Левое внешнее | `ЛЕВОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ ... ПО` |
| Правое внешнее | `ПРАВОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ ... ПО` |
| Полное внешнее | `ПОЛНОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ ... ПО` |

**Правила:**

- **Никогда не используй вложенные соединения** (соединение с подзапросом, внутри которого есть соединения). Заменяй временными таблицами или последовательными соединениями.
- Для ЛЕВОГО СОЕДИНЕНИЯ индексируй поля соединения правой таблицы.
- Для ВНУТРЕННЕГО СОЕДИНЕНИЯ индексируй поля соединения большей таблицы.

## Группировка и итоги

### СГРУППИРОВАТЬ ПО

```
ВЫБРАТЬ
 Контрагент,
 СУММА(СуммаДокумента) КАК Итого,
 КОЛИЧЕСТВО(РАЗЛИЧНЫЕ Ссылка) КАК КолДок
ИЗ Документ.РеализацияТоваровУслуг
СГРУППИРОВАТЬ ПО Контрагент
ИМЕЮЩИЕ СУММА(СуммаДокумента) > 1000
```

**Агрегатные функции:** `СУММА`, `СРЕДНЕЕ`, `МИНИМУМ`, `МАКСИМУМ`, `КОЛИЧЕСТВО`, `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ...)`.

Каждое неагрегированное поле в списке выборки должно присутствовать в группировке.

### ИТОГИ (кратко)

```
ИТОГИ СУММА(СуммаДокумента) ПО ОБЩИЕ, Контрагент
```

Вычисляет строки промежуточных итогов и чередует их со строками детализации. Полный синтаксис (`ПЕРИОДАМИ`, иерархические точки контроля, группирующие наборы) — в [references/query-syntax-reference.md](references/query-syntax-reference.md).

## Временные таблицы

Используй временные таблицы, чтобы разбить сложный запрос на шаги, избежать вложенных подзапросов и повысить производительность.

```
// Шаг 1: собрать элементы во временную таблицу
ВЫБРАТЬ Ссылка КАК Номенклатура
ПОМЕСТИТЬ ВТ_Товары
ИЗ Справочник.Номенклатура
ГДЕ Наименование ПОДОБНО &Маска
ИНДЕКСИРОВАТЬ ПО Номенклатура
;
// Шаг 2: получить остатки по этим элементам
ВЫБРАТЬ
 Ост.Номенклатура КАК Номенклатура,
 Ост.КоличествоОстаток КАК Остаток
ИЗ РегистрНакопления.ОстаткиТоваров.Остатки(
 ,
 Номенклатура В (ВЫБРАТЬ Номенклатура ИЗ ВТ_Товары)
 ) КАК Ост
```

**Правила:**

- разделяй запросы в пакете точкой с запятой `;`;
- `ПОМЕСТИТЬ <Имя>` создаёт временную таблицу (ставь сразу после полей выборки, до `ИЗ`);
- `ИНДЕКСИРОВАТЬ ПО <поле>` добавляй для временных таблиц больше 1000 строк, используемых в соединениях или подзапросах `В`;
- минимизируй объём данных и число полей во временных таблицах;
- **никогда** не создавай и не удаляй временные таблицы в цикле;
- предпочитай временные таблицы вложенным подзапросам в условиях соединения.

## Параметры

Параметры — внешние значения, передаваемые в запрос. Синтаксис: `&ИмяПараметра`.

```
ВЫБРАТЬ * ИЗ Справочник.Контрагенты ГДЕ Наименование ПОДОБНО &Маска
```

Передаются через параметры `execute_query`: `{"Маска": "%Рога%"}`.

**Правила:**

- всегда используй параметры для внешних значений, никогда не склеивай строки в текст запроса;
- значения перечислений — через `ЗНАЧЕНИЕ` в тексте запроса, а не параметром: `ГДЕ Тип = ЗНАЧЕНИЕ(Перечисление.ТипыЦен.Оптовая)`;
- формат даты в параметрах — ISO 8601 (`"2024-01-15"` или `"2024-01-15T10:30:00"`);
- булево: `ИСТИНА` и `ЛОЖЬ` в тексте запроса либо `true` и `false` параметром.

## Сравнение ссылочных полей

При сравнении ссылочных полей **передавай ссылку параметром**:

```
// ХОРОШО — ссылка передана параметром из результата предыдущего запроса:
ВЫБРАТЬ * ИЗ Документ.ПродажаТоваров
ГДЕ Контрагент = &Контрагент

// ТОЖЕ ХОРОШО — сравнение через примитивный реквизит:
ГДЕ Контрагент.Наименование = "ООО Ромашка"
ГДЕ Контрагент.Код = "000001"

// ИЗБЕГАЙ — прямое сравнение со ссылкой из другой таблицы:
ГДЕ Документ.Контрагент = Справочник.Контрагенты.Ссылка
```

**Правила:**

- **Первый выбор:** передать объект ссылки из результата предыдущего запроса как `&Параметр`.
- **Запасной вариант:** сравнение через примитивные поля (`Наименование`, `Код` и так далее).
- Никогда не сравнивай ссылочные поля напрямую из разных источников.

## Частые приёмы

**1. Поиск по имени (нечёткий):**

```
ВЫБРАТЬ Ссылка, Наименование ИЗ Справочник.Контрагенты ГДЕ Наименование ПОДОБНО &Маска
// параметры: {"Маска": "%рога%"}
```

**2. Последние N документов:**

```
ВЫБРАТЬ ПЕРВЫЕ 10 Ссылка, Дата, Номер, СуммаДокумента
ИЗ Документ.РеализацияТоваровУслуг
УПОРЯДОЧИТЬ ПО Дата УБЫВ
```

**3. Текущие остатки (виртуальная таблица, без даты — на сейчас):**

```
ВЫБРАТЬ Номенклатура, КоличествоОстаток
ИЗ РегистрНакопления.ОстаткиТоваров.Остатки(, Номенклатура = &Ном) КАК Ост
```

**4. Срез последних регистра сведений:**

```
ВЫБРАТЬ Валюта, Курс ИЗ РегистрСведений.КурсыВалют.СрезПоследних(&Дата,) КАК Курсы
```

**5. Количество по группам:**

```
ВЫБРАТЬ Контрагент, КОЛИЧЕСТВО(*) КАК Кол
ИЗ Документ.РеализацияТоваровУслуг
СГРУППИРОВАТЬ ПО Контрагент
УПОРЯДОЧИТЬ ПО Кол УБЫВ
```

**6. Проверка существования:**

```
ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка ИЗ Справочник.Контрагенты ГДЕ ИНН = &ИНН
```

**7. Исключить помеченные на удаление:**

```
ГДЕ НЕ ПометкаУдаления
```

**8. Изучить структуру таблицы (запрос без строк со схемой):**

```
ВЫБРАТЬ ПЕРВЫЕ 0 * ИЗ Справочник.Контрагенты
// использовать с include_schema: true в execute_query
```
