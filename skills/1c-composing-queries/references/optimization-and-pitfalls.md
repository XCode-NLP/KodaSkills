## Отбор с учётом индексов

Оптимизатор запросов 1С делит условия ГДЕ на две категории.

### Основное условие

- **Используется для поиска по индексу** — определяет, какой диапазон индекса просматривать.
- Должно быть самой ограничивающей частью отбора.
- Допустимые операторы: `=`, `>`, `<`, `>=`, `<=`, `ПОДОБНО`, `МЕЖДУ`, `В`.
- С другими основными условиями соединяется только через `И`.
- **Запрещено в основном условии:** `ИЛИ`, `ВЫБОР`, арифметические выражения, вызовы функций (например `ПОДСТРОКА`), `НЕ`.

### Дополнительное условие

- Применяется **после** просмотра индекса — фильтрует строки по одной.
- Может использовать любые операторы, `ИЛИ`, `ВЫБОР`, арифметику, функции.
- Соединяется с основным условием через `И`.

### Стратегия

Строй ГДЕ так: `<основное_условие> И <дополнительное_условие>`.

```
// Основное: индексируемое поле с =
// Дополнительное: сложная логика
ГДЕ Организация = &Орг                              // основное (индексируемое)
    И (Сумма > 1000 ИЛИ ПометкаУдаления = ИСТИНА)   // дополнительное
```

Если запрос медленный, проверь, не мешают ли условия использованию индекса. Исправляй так:

1. `ВЫРАЗИТЬ` — сузить составные типы.
2. Сложную логику вынести в дополнительное условие.
3. Переписать через временные таблицы.

## Ловушка ИЛИ

`ИЛИ` в основном условии **лишает индекса** все участвующие поля.

**Допустимо только когда:**

- применяется к **последнему или единственному** полю индекса;
- **и** может быть заменено на `В (...)`:

```
// ПЛОХО — ломает индекс и по Контрагент, и по Организация:
ГДЕ Контрагент = &К1 ИЛИ Организация = &Орг

// ХОРОШО — использовать В:
ГДЕ Контрагент В (&К1, &К2, &К3)

// ХОРОШО — разбить на ОБЪЕДИНИТЬ ВСЕ:
ВЫБРАТЬ ... ГДЕ Контрагент = &К1
ОБЪЕДИНИТЬ ВСЕ
ВЫБРАТЬ ... ГДЕ Организация = &Орг
```

Заменяя `ИЛИ` на `ОБЪЕДИНИТЬ ВСЕ`, проверь эквивалентность результата: не должно появиться пропущенных или лишних строк.

## Разыменование составного типа

Когда поле имеет составной ссылочный тип (может указывать на несколько таблиц), обращение к вложенным полям через точку создаёт неявные соединения со **всеми** возможными целевыми таблицами.

**Последствия:**

- сложность запроса резко растёт (много лишних соединений);
- производительность сильно падает, особенно при ограничениях доступа;
- поведение различается между СУБД.

**Решения:**

1. **ВЫРАЗИТЬ:** сузить до конкретного типа перед разыменованием:
   ```
   ВЫРАЗИТЬ(Регистратор КАК Документ.Реализация).Номер
   ```

2. **ССЫЛКА и ВЫБОР:** обработать несколько типов явно:
   ```
   ВЫБОР
       КОГДА Рег ССЫЛКА Документ.Реализация
           ТОГДА ВЫРАЗИТЬ(Рег КАК Документ.Реализация).Контрагент
       КОГДА Рег ССЫЛКА Документ.Поступление
           ТОГДА ВЫРАЗИТЬ(Рег КАК Документ.Поступление).Контрагент
   КОНЕЦ
   ```

3. **Временные таблицы:** сначала отфильтровать по типу, затем соединять:
   ```
   ВЫБРАТЬ Регистратор КАК Док ПОМЕСТИТЬ ВТ_Реализации
   ИЗ РегистрНакопления.Товары
   ГДЕ Регистратор ССЫЛКА Документ.Реализация;

   ВЫБРАТЬ ВЫРАЗИТЬ(ВТ.Док КАК Документ.Реализация).Контрагент
   ИЗ ВТ_Реализации КАК ВТ
   ```

4. **Денормализация:** для часто запрашиваемых связанных данных добавь отдельный реквизит в таблицу-источник (изменение на уровне конфигурации).

## Параметры виртуальных таблиц

Виртуальные таблицы (Остатки, Обороты, СрезПоследних и другие) принимают параметры, которые работают как **предварительный отбор** на уровне хранилища.

**КРИТИЧНО: всегда передавай условия в параметры виртуальной таблицы, а не в ГДЕ.**

```
// ПЛОХО — полный просмотр таблицы, потом фильтрация:
ВЫБРАТЬ * ИЗ РегистрНакопления.Товары.Остатки() КАК Ост
ГДЕ Ост.Склад = &Склад

// ХОРОШО — отбор на уровне хранилища:
ВЫБРАТЬ * ИЗ РегистрНакопления.Товары.Остатки(, Склад = &Склад) КАК Ост
```

**Правила параметров:**

- только простые выражения вида `Измерение = Значение`;
- несколько условий через запятую (неявное И);
- никаких подзапросов внутри параметров (используй временную таблицу и приём `В (ВЫБРАТЬ ... ИЗ ВТ)`);
- никаких соединений внутри параметров;
- для Остатки без параметра даты возвращаются текущие (последние) остатки.

**Исключение — `СрезПоследних` и `СрезПервых`:** условие в параметре отбирает записи регистра до вычисления среза. Условие на ресурс или реквизит, который меняется во времени (статус, состояние), ставится в `ГДЕ`, иначе вернутся ключи, у которых значение было когда-либо, а не последнее. Условие на измерение — в параметрах.

## Особенности виртуальных таблиц регистра бухгалтерии

У виртуальных таблиц регистра бухгалтерии другая семантика параметров, чем у регистров накопления.

### Параметр Субконто и Условие

Параметр `Субконто` принимает ссылки на виды субконто (типы из плана видов характеристик), а НЕ значения. Чтобы фильтровать по значениям субконто, используй параметр `Условие`:

```
// ПЛОХО — ЗНАЧЕНИЕ субконто в позиции параметра Субконто:
.Остатки(&Период, , &Контрагент, )

// ХОРОШО — виды субконто в Субконто (параметр 3), значение в Условие (параметр 4):
.Остатки(&Период, , &ВидыСубконто, Субконто1 = &Контрагент)
```

Параметры `.Остатки()` (4): Период, УсловиеСчета, Субконто, Условие. Не путай с регистром накопления, где у `.Остатки()` другая сигнатура.

### Условия по счёту — в УсловиеСчета, а не в ГДЕ

```
// ПЛОХО — полный просмотр таблицы, потом фильтрация:
ВЫБРАТЬ * ИЗ РегистрБухгалтерии.Хозрасчетный.Остатки() КАК Ост
ГДЕ Ост.Счет = &Счет

// ХОРОШО — отбор на уровне хранилища через УсловиеСчета (параметр 2):
ВЫБРАТЬ * ИЗ РегистрБухгалтерии.Хозрасчетный.Остатки(, Счет = &Счет, , ) КАК Ост
```

Используй `Счет В ИЕРАРХИИ(&Счет)`, чтобы включить все субсчета родительского счёта.

### Распределение параметров по виртуальным таблицам

У каждой виртуальной таблицы свой набор параметров. Не смешивай их. Параметры по счёту (`УсловиеСчета`, `УсловиеКорСчета`, `УсловиеСчетаДт`, `УсловиеСчетаКт`) — отдельные позиционные параметры, а не часть `Условие`:

- `Остатки` — 4 параметра, `УсловиеСчета` на позиции 2;
- `Обороты` — 8 параметров (`УсловиеСчета` на 4, `УсловиеКорСчета` на 7, `КорСубконто` на 8);
- `ОстаткиИОбороты` — 7 параметров, есть `МетодДополненияПериодов` (4) и `УсловиеСчета` (5);
- `ОборотыДтКт` — 8 параметров с раздельными `УсловиеСчетаДт` и `СубконтоДт`, `УсловиеСчетаКт` и `СубконтоКт`;
- `ДвиженияССубконто` — 5 параметров, отдельного `УсловиеСчета` нет: фильтр по счёту идёт через `Условие` (третий параметр).

Точный позиционный порядок — в таблице параметров основного файла навыка.

## Запрет вложенных соединений

**Никогда не вкладывай соединения**, то есть не соединяй с подзапросом, внутри которого уже есть соединения.

```
// ПЛОХО — вложенное соединение:
ЛЕВОЕ СОЕДИНЕНИЕ (
    ВЫБРАТЬ ... ИЗ Т1 ВНУТРЕННЕЕ СОЕДИНЕНИЕ Т2 ПО ...
) КАК Подзапрос
ПО ...

// ХОРОШО — использовать временную таблицу:
ВЫБРАТЬ ... ПОМЕСТИТЬ ВТ ИЗ Т1 ВНУТРЕННЕЕ СОЕДИНЕНИЕ Т2 ПО ...;
... ЛЕВОЕ СОЕДИНЕНИЕ ВТ ПО ...
```

**Также избегай:**

- соединения с подзапросами, содержащими `В` с соединениями;
- сложных условий в `ПО` (условии соединения), особенно подзапросов.

Все такие приёмы заменяй последовательными запросами с временными таблицами.

## Хорошие практики временных таблиц

**Когда использовать:**

- замена вложенных соединений и подзапросов в условиях;
- предварительный отбор больших наборов данных перед соединением;
- разбиение сложных запросов с множеством соединений на шаги;
- сохранение промежуточных результатов для повторного использования в пакете.

**Правила:**

- `ИНДЕКСИРОВАТЬ ПО <поле>` — всегда добавляй, если в таблице больше 1000 строк и она используется в соединении или подзапросе `В`;
- минимизируй объём данных: выбирай только нужные поля;
- минимизируй число строк: применяй фильтры как можно раньше;
- **никогда не создавай и не удаляй временные таблицы в цикле** — считай заранее или обрабатывай пакетами;
- не копируй временную таблицу только ради переименования — используй исходную;
- для очень больших наборов обрабатывай данные частями, а не загружай всё в одну временную таблицу.

## Влияние RLS

Ограничения доступа на уровне записей добавляют неявные условия в каждый запрос. Когда правила RLS содержат подзапросы или соединения:

- план запроса заметно усложняется;
- стоимость разыменования составных типов умножается;
- соединения становятся медленнее.

**Что делать:**

- избегай ролей с противоречивыми RLS на одном объекте;
- используй `РАЗРЕШЕННЫЕ` в списке выборки, чтобы применить RLS (без него возможны ошибки доступа);
- если RLS вызывает сильное замедление, перепиши запрос через временные таблицы в привилегированном режиме (на уровне конфигурации);
- держи условия RLS простыми: без подзапросов и соединений в шаблонах RLS.

---

## Ограничения подзапросов

Используя подзапросы (в `В`, `СУЩЕСТВУЕТ` или как источник), избегай:

- соединений внутри подзапроса;
- обращения к полям составного типа («любая ссылка»);
- доступа к реквизитам шапки документа из подзапроса по табличной части;
- сложных условий RLS, применяемых к таблицам подзапроса.

Всё это раздувает SQL, который генерирует движок 1С. Заменяй временными таблицами.

## Переносимость между СУБД

1С работает на нескольких СУБД (MS SQL, PostgreSQL, IBM DB2, Oracle). Часть поведения различается:

- **Сравнение строк:** в 1С обычно без учёта регистра, но пограничные случаи могут отличаться по СУБД.
- **Точность арифметики дат:** может различаться.
- **Точность вычислений:** возможны различия в округлении.
- **Оптимизация плана запроса:** разные СУБД могут выбрать разные планы для одного и того же запроса 1С.

**Рекомендация:** всегда используй `ВЫРАЗИТЬ` для явного приведения типов. Проверяй запросы на целевой СУБД. Не полагайся на поведение конкретной СУБД.
