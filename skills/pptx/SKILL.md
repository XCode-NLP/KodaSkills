# Создание, правка и разбор PPTX

`.pptx` — это ZIP-архив с XML-файлами. Выбирай подход по задаче:

| Задача                                                         | Подход                                                                                                                                                                                 |
|----------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Создать** новую презентацию                                  | Напиши скрипт на `pptxgenjs` — см. подводные камни ниже — и собирай её как [структурированную презентацию](#structured-decks), если пользователь не просит быстрый одноразовый вариант |
| **Отредактировать** готовую презентацию или собрать по шаблону | распаковать → править `ppt/slides/slideN.xml` → `zip`                                                                                                                                  |
| **Прочитать** содержимое                                       | `python scripts/slide_text.py deck.pptx` (по блоку на слайд под маркерами `<!-- Slide number: N -->`); визуальная сетка: `python scripts/thumbnail.py deck.pptx`                       |

## Скрипты

Пути указаны относительно директории этого навыка. Всё остальное — обычные Python, `node` или shell.

| Скрипт                                                            | Что делает                                                                                                                                                                                                                                                                                                                                                                                  |
|-------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `scripts/slide_text.py deck.pptx`                                 | Заголовок, текст, таблицы, данные диаграмм (для точечных и пузырьковых — только имена рядов), альтернативный текст изображений и заметки докладчика каждого слайда в виде markdown. Читает и `.potx`                                                                                                                                                                                        |
| `scripts/thumbnail.py deck.pptx [prefix]`                         | Размеченная сетка всех слайдов, чтобы выбрать макеты шаблона. Только `.pptx`. Передавай `prefix` — по умолчанию `thumbnails`, а это перезапишет сетки любой другой презентации, обработанной в той же директории                                                                                                                                                                            |
| `scripts/add_slide.py unpacked/ slide2.xml [--after slideN.xml]`  | Дублирует слайд (или `slideLayoutN.xml`) со всей служебной регистрацией. Принимает и `.pptx` напрямую с `-o out.pptx`                                                                                                                                                                                                                                                                       |
| `scripts/clean.py unpacked/`                                      | Удаляет слайды, медиа и связи, на которые больше нет ссылок. Запускай **после** того, как `<p:sldIdLst>` окончательно сформирован                                                                                                                                                                                                                                                           |
| `scripts/apply_theme.js`                                          | Модуль Node: `const { applyTheme } = require("<директория этого навыка>/scripts/apply_theme.js")`. `await applyTheme("deck.pptx", THEME)` после `pres.writeFile()` записывает цвета и имя `THEME` (с экранированием для XML) в тему презентации — для [структурированных презентаций](#structured-decks). Есть и режим командной строки: `node scripts/apply_theme.js deck.pptx theme.json` |
| `scripts/office/validate.py deck.pptx [--original src.pptx]`      | Проверки схемы, связей, типов содержимого, диаграмм и слайдов; для каждой ошибки указано, как её исправить. Передавай `--original` для любой презентации, собранной по шаблону — тогда проверки схемы сравниваются с шаблоном и его собственные ошибки XSD не выглядят как ваши                                                                                                             |
| `scripts/office/soffice.py --headless --convert-to pdf deck.pptx` | Обёртка LibreOffice — в этой песочнице `soffice` напрямую зависает                                                                                                                                                                                                                                                                                                                          |

## Создание через pptxgenjs — подводные камни

`pptxgenjs` уже установлен — не запускай `npm install` заранее; пиши скрипт и сразу подключай через `require('pptxgenjs')`. Ставь пакет, только если этот `require` падает. API модель знает; ниже — места, где легко ошибиться:

- **Задай `pres.layout` до добавления слайдов.** Холст по умолчанию — `LAYOUT_16x9` = **10″ × 5.625″**, а не 13.3″ в ширину. Координаты за границей холста записываются, а не обрезаются — фигура просто не попадает на слайд. (`LAYOUT_WIDE` — это 13.3″ × 7.5″.)
- **Шестнадцатеричные цвета: никогда `#`, никогда 8 цифр.** `color: "FF0000"`. И `"#FF0000"`, и альфа, вписанная в hex (`"00000020"`), **портят файл**. Для полупрозрачности: `transparency: 0-100` у заливок и изображений, `opacity: 0.0-1.0` у теней — каждый параметр молча игнорируется в чужом месте.
- **pptxgenjs изменяет объекты опций на месте** (преобразует значения в EMU при первом использовании). Никогда не используй один объект `shadow`/опций в двух вызовах `add*` — создавай свежий объект каждый раз.
- **`offset` тени должен быть ≥ 0** — отрицательное значение портит файл. Чтобы тень падала вверх, используй `angle: 270` с положительным смещением.
- **`letterSpacing` молча игнорируется** — настоящая опция называется `charSpacing`.
- **Списки:** `bullet: true` у каждого элемента, никогда литеральный `•` (отрисуется двойными маркерами). Задавай `breakLine: true` у каждого элемента массива, кроме последнего. Разделяй абзацы списка через `paraSpaceAfter`, а не `lineSpacing` (огромные промежутки).
- **Один `new pptxgen()` на выходной файл** — никогда не переиспользуй экземпляр.
- **`rectRadius` работает только с `ROUNDED_RECTANGLE`**, не с `RECTANGLE`.
- **Градиентные заливки не поддерживаются** — используй градиентное изображение как фон.
- **Каждому вызову `addText` без `placeholder` нужен `isTextBox: true`** — иначе у фигуры нет `txBox="1"`, и программы экранного доступа объявляют текст как «графику», а не как текстовое поле. Визуально ничего не меняется.
- **У текстовых полей есть внутренние отступы** — ставь `margin: 0`, когда текст должен выровняться с фигурой, линией или значком по той же координате x.
- **Заметки докладчика идут в `slide.addNotes("...")`** (простой текст, один раз на слайд), а не в текстовое поле на слайде.
- **Диаграммы оставляй нативными.** Используй `addChart()` для всего, что PowerPoint умеет строить (для комбинированных передавай массив `{type, data, options}`). Для нативных возможностей PowerPoint, которых нет в библиотеке (линии тренда, планки погрешностей), досчитывай дополнительные ряды сам или правь сгенерированный OOXML — не переходи на отрисованное изображение. В виде изображений — только те типы диаграмм, для которых у PowerPoint нет нативной формы (Sankey, сетевая, хордовая).
- **Диаграммы по умолчанию выглядят голыми** — без заголовка, без подписей данных, с устаревшей палитрой. Задай `showTitle` + `title`, `showValue: true` + `dataLabelPosition`, `chartColors: [...]` из своей палитры и приглуши рамку (`catAxisLabelColor`/`valAxisLabelColor`, `valGridLine: { color, size }`, `catGridLine: { style: "none" }`, `showLegend: false` для одного ряда).
- **На линейчатой диаграмме с накоплением `dataLabelPosition` должен быть `ctr`, `inEnd` или `inBase`.** `outEnd` **портит файл**.
- **Комбинированному ряду с `secondaryValAxis`/`secondaryCatAxis` нужны оба параметра `valAxes` и `catAxes` в опциях диаграммы, по две записи в каждом.** Без них pptxgenjs пишет *идентификаторы* осей, которые не объявляет, и PowerPoint **отбрасывает такую диаграмму**, сообщая о повреждении файла. Одного `valAxes` недостаточно.
- **После `writeFile()` запусти `python scripts/office/validate.py deck.pptx`.** Скрипт сообщает о многих дефектах диаграмм и XML слайдов, из-за которых PowerPoint отказывается открывать файл или предлагает его исправить, — в том числе о двух случаях выше, — и указывает, как исправить каждый. Исправляй в генераторе, а не ручной правкой упакованного XML.
- **Никогда не меняй порядок дочерних элементов `<p:presentation>`.** pptxgenjs пишет `<p:notesMasterIdLst>` сразу после `<p:sldIdLst>` и указывает оба мастера на одну часть темы. PowerPoint это спокойно читает — сдвинь элемент, и та же презентация перестанет открываться.
- **Значки:** отрисовывай `react-icons` в SVG (`ReactDOMServer.renderToStaticMarkup`), растеризуй через `sharp` при ≥256px и вставляй через `addImage({ data: "image/png;base64," + buf.toString("base64") })` — префикс `image/png;base64,` обязателен (`react-icons`, `react`, `react-dom` и `sharp` уже установлены — `npm install react-icons react react-dom sharp` только если `require` падает).
- **`defineSlideMaster()` создаёт *макет* слайда, а не мастер** — один `slideLayoutN.xml` на вызов, внутри одного мастера, который нельзя изменить. Называй их макетами и в разговоре с пользователем.
- **`pres.company` и `title` из `defineSlideMaster()` записываются в XML без экранирования** — символ `&` в любом из них (`"Harrow & Sons"`) делает `docProps/app.xml` или макет неразбираемым, и `validate.py` падает. Пиши там `&amp;`, в том числе в соответствующем `masterName`. `title`, `subject`, `author`, заголовки разделов, `objectName`, заметки и текст слайдов экранируются автоматически.

### Структурированные презентации { id="structured-decks" }

Презентация, построенная на теме, макетах, местозаполнителях и разделах, перекрашивается в одном месте и спокойно правится в PowerPoint. Собирай так каждую новую презентацию, если пользователь не просит быстрый одноразовый вариант.

1. **Сначала тема:** `const THEME = { name, headFontFace, bodyFontFace, colors: { dk1, lt1, dk2, lt2, accent1 … accent6, hlink, folHlink } }`, цвета в hex. `pres.theme` принимает только два шрифта и больше ничего. После этого не называй шрифты явно — заголовки получают шрифт заголовков, остальной текст шрифт основного текста, — кроме текста диаграмм, где жёстко зашит Arial: задай в его опциях `*FontFace` значение `"+mn-lt"` (основной шрифт темы; `"+mj-lt"` — шрифт заголовков).
2. **`const C = pres.SchemeColor` для каждого цвета** — `C.text1`/`C.text2` это `dk1`/`dk2`, `C.background1`/`C.background2` это `lt1`/`lt2`. В эти места принимается только hex, взятый из `THEME`: `valGridLine.color`, `catGridLine.color`, `shadow.color`, а на линейчатой диаграмме с одним рядом — `invertedColors` или несколько значений `chartColors`. Цвет схемы там записывается как `<a:srgbClr val="bg2"/>` без предупреждений, а будучи hex, такие значения не подхватят последующую смену темы.
3. **Разделы:** `pres.addSection({ title })` непосредственно перед первым слайдом раздела, затем `sectionTitle` в каждом `addSlide`. Слайд без него — или, когда разделы объявлены заранее, слайды автоматической разбивки таблицы — попадает в посторонний раздел «Default-N».
4. **Один макет на тип кадра слайда** (`defineSlideMaster()`): титульный, разделитель раздела, только заголовок, диаграмма с комментарием, таблица; тёмный и светлый варианты, если дизайн чередуется. Текстовые области — именованные местозаполнители с позицией, размером, начертанием и `color` — местозаполнителям диаграмм, изображений и таблиц тоже нужен `color`, иначе подсказки и массивы прогонов выходят жёстко чёрными (`000000`). Текст колонтитула, логотип и `slideNumber` размещай на макете, никогда на слайде.
5. **Заполняй по имени:** `addSlide({ masterName, sectionTitle })`, затем `addText("…", { placeholder: "title" })` без позиции, размера и цвета — побеждают опции самого местозаполнителя, а всё, что он не задаёт (курсив, `align`, `fontFace`), продолжает действовать; отдельный прогон оформляй через `[{ text, options }]`. Опечатка в `placeholder` или `masterName` приводит к молчаливому сбою (постороннее текстовое поле в 0,0; пустой макет). Только местозаполнители `title`, `body` и `chart` заполняются по одному имени: `addImage({ placeholder })` берёт x и y местозаполнителя, но не его размер (картинка 1″ × 1″) — передавай ещё `w`/`h`. `addTable({ placeholder })` берёт только x и y — всегда передавай `w`; при автоматической разбивке на страницы таблица игнорирует местозаполнитель и вылезает за слайд, поэтому передавай также `x`, `y` и `autoPageSlideStartY` (тот же, что `y`, иначе страницы продолжения раскладываются от верхнего поля), задай макету `margin`, нижняя граница которого не заходит на колонтитул, и заполняй заголовки страниц продолжения через `slide.newAutoPagedSlides`.
6. **Макет — это рамка, а не «макет» из Design Ideas.** Карточки, значки, акценты с цифрами и изображения всё равно собираются послайдово поверх него, в цветах схемы, каждый с `objectName` — применимы любые идеи оформления, и большинство содержательных слайдов сидит на макете «только заголовок».
7. **Сначала запись, потом тема:** `await pres.writeFile({ fileName: "deck.pptx" })`, затем `await applyTheme("deck.pptx", THEME)`. pptxgenjs не умеет писать цвета темы: пока это не выполнено, цвета схемы разрешаются в стандартную палитру Office. Если в опции, принимающей только hex, попадёт цвет схемы, функция выбросит исключение, ничего не изменив, — исправь то, что она назвала, и пересобери.

## Правка готовых презентаций и шаблонов { id="editing-existing-decks" }

Сначала выбери макеты: `python scripts/thumbnail.py template.pptx template-thumbs` создаёт размеченную сетку всех слайдов и печатает имена созданных файлов — `template-thumbs.jpg`, а начиная с 13-го слайда разбивается на `template-thumbs-N.jpg`. **Всегда передавай этот второй аргумент, названный по имени презентации.** По умолчанию он `thumbnails`, поэтому две презентации, обработанные в одной директории, молча перезаписывают сетки друг друга — сетки первой просто исчезают (это только для анализа шаблона — для визуальной проверки нужны полноразмерные рендеры из раздела [«Преобразование в изображения»](#converting-to-images); скрипт принимает только `.pptx`, поэтому сначала скопируй `.potx` под именем `.pptx`). Используй его вместе с `slide_text.py`, чтобы разложить каждый содержательный раздел по слайду шаблона, и чередуй макеты — не ставь все разделы на один и тот же слайд «заголовок и маркеры».

```bash
python3 -c "import sys,zipfile; zipfile.ZipFile(sys.argv[1]).extractall('unpacked')" deck.pptx
python scripts/add_slide.py unpacked/ slide2.xml --after slide2.xml   # дублирует слайд (или slideLayoutN.xml); печатает путь нового слайда
# порядок и удаление слайдов = правка <p:sldIdLst> в ppt/presentation.xml
python scripts/clean.py unpacked/                                     # после удалений: убирает осиротевшие слайды, медиа, связи
# содержимое слайда правится в ppt/slides/slideN.xml
(cd unpacked && rm -f ../out.pptx && zip -XrDy ../out.pptx .)         # упаковывай ИЗНУТРИ директории; сначала rm, иначе удалённые части останутся
python scripts/office/validate.py out.pptx --original deck.pptx
```

- **Всю структурную работу — добавление, удаление, перестановку — делай до правки содержимого слайдов.** `add_slide.py` копирует файл слайда дословно, поэтому дублирование после правок клонирует уже изменённое содержимое; а `clean.py` удаляет любой слайд, отсутствующий в `<p:sldIdLst>`, в том числе только что записанный.
- **Никогда не копируй файл слайда вручную** — `add_slide.py` выполняет всю регистрацию, нужную новому слайду, и сообщает, что создал (`Created ppt/slides/slide17.xml from slide2.xml`). Он работает и напрямую с файлом: `add_slide.py deck.pptx slide2.xml -o out.pptx` — **обязательно передавай `-o`, иначе он перезапишет входную презентацию на месте.** Дублированный слайд по-прежнему *ссылается* на части диаграмм, SmartArt и встроенных объектов исходного, а не клонирует их, поэтому правка диаграммы на одном слайде изменит её и на другом.
- **Если используешь `python-pptx`**, три вещи он не умеет: дублировать слайд (единственная точка входа — `add_slide(layout)`), сохранять оформление при `text_frame.text = "..."` (абзац схлопывается в один прогон без стилей — присваивай `run.text`), читать SVG/EMF, на которых построена большая часть графики шаблонов (`add_picture` выбрасывает `UnidentifiedImageError`).
- Старые `.ppt` сначала нужно конвертировать: `python scripts/office/soffice.py --headless --convert-to pptx file.ppt`. Шаблоны `.potx` распаковываются и упаковываются так же — сохраняй расширение `.potx` у результата.
- Чтобы переиспользовать значок или изображение из шаблона, дублируй слайд или макет, где оно уже есть.

При заполнении шаблона:

- Если пишешь скрипт преобразования XML, разбирай через `defusedxml.minidom` — круговой проход OOXML через `xml.etree.ElementTree` переписывает префиксы пространств имён и портит презентацию.
- **Слоты шаблона ≠ элементы источника.** Если в шаблоне четыре участника команды, а у тебя три, удаляй всю группу четвёртого (изображение и текстовые поля), а не только текст, — затем проверь на визуальной проверке, не осталось ли осиротевшей графики.
- Один `<a:p>` на элемент списка — никогда не склеивай элементы в один абзац. Копируй соседний `<a:pPr>`, чтобы сохранить отступы, и ставь `b="1"` в `<a:rPr>` заголовков, заголовков разделов и встроенных подписей (`Status:`, `Owner:`).
- Маркеры пусть наследуются от макета; добавляй `<a:buChar>`, `<a:buAutoNum>` (нумерованный) или `<a:buNone>` только для переопределения — никогда литеральный `•` в тексте.
- Текст с ведущими или замыкающими пробелами требует `xml:space="preserve"` в его `<a:t>`.

## Содержание и логика презентации

- **Одна мысль на слайд.** Презентация идёт от темы к теме, от мысли к мысли.
- **Частая структура — пирамида:** главная мысль вперёд, краткое резюме, которое предваряет разделы, сами разделы, затем вывод, обычно с дальнейшими шагами по результатам.
- **Согласуй структуру с размером презентации.** Короткой может не понадобиться вступление и вывод; длинной могут понадобиться разделители между темами.
- **Строй под цель презентации:** решение, согласие, празднование, разрешение разногласия или начало обсуждения.
- **Строй под способ использования.** Живой доклад получает рассказ и, возможно, обсуждение; материал для предварительного чтения должен нести весь рассказ сам. Руководителям на живой встрече нужно мало слов и очень наглядные слайды. Подробные, насыщенные текстом слайды иногда уместны для профильных специалистов или для чтения офлайн. Аналитические отчёты опираются на диаграммы и таблицы.
- **Рассчитывай живой доклад по времени:** примерно 1.5–2 минуты на слайд, с запасом на вопросы, если они предполагаются.

## Идеи оформления

**Не создавай скучные слайды.** Простые маркеры на белом фоне никого не впечатлят. Для каждого слайда рассмотри идеи из этого списка.

### До начала работы

- **Выбери смелую палитру, связанную с содержанием**: палитра должна ощущаться сделанной для ЭТОЙ темы. Если твои цвета, подставленные в совершенно другую презентацию, всё ещё «работают», выбор недостаточно конкретный.
- **Доминирование вместо равенства**: один цвет должен доминировать (60-70% визуального веса), с 1-2 поддерживающими тонами и одним резким акцентом. Никогда не давай всем цветам равный вес.
- **Тёмный и светлый контраст**: тёмные фоны для титульного слайда и вывода, светлые для содержания («сэндвич»). Или сознательно сделай всю презентацию тёмной ради премиального вида.
- **Держись одного визуального мотива**: выбери ОДИН отличительный элемент и повторяй его — скруглённые рамки изображений, значки в цветных кругах. Проведи его через все слайды. **Не используй цветную полосу или акцентную линию как мотив** (см. список запретов).

### Для каждого слайда

**Каждому слайду нужен визуальный элемент** — изображение, диаграмма, значок или фигура. Слайды только с текстом забываются.

**Варианты компоновки:**

- две колонки (текст слева, иллюстрация справа);
- строки «значок + текст» (значок в цветном круге, жирный заголовок, описание ниже);
- сетка 2x2 или 2x3 (изображение с одной стороны, сетка блоков содержания с другой);
- изображение на половину слайда (вся левая или правая сторона) с наложенным содержанием.

**Подача данных:**

- крупные акценты с цифрами (большие числа 60-72pt с мелкими подписями ниже);
- колонки сравнения (до и после, плюсы и минусы, варианты рядом);
- таймлайн или схема процесса (нумерованные шаги, стрелки).

**Визуальная отделка:**

- значки в небольших цветных кругах рядом с заголовками разделов;
- курсивный акцентный текст для ключевых цифр или слоганов.

### Типографика

**Имена шрифтов, записанные в `.pptx`, отрисовывает PowerPoint пользователя, а не это окружение.** Твоя визуальная проверка идёт через LibreOffice, который подменяет отсутствующие шрифты — а у некоторых шрифтов замена имеет другую ширину, поэтому предпросмотр может показать переполнение текста (или его отсутствие), которого в реальной презентации не будет. Чтобы проверке можно было доверять:

- **Безопасные шрифты** (отрисовываются в проверке с настоящей шириной *и* поставляются с Office): **Arial, Calibri, Cambria, Times New Roman, Courier New, Bookman Old Style, Century Schoolbook**. Используй их для основного текста и везде, где важен подгон размера.
- **Заголовки с характером без риска для проверки**: сочетай серифный заголовок из безопасного списка (Cambria, Bookman Old Style, Century Schoolbook) с основным текстом без засечек из того же списка (Calibri или Arial). Получаешь визуальный контраст, не теряя надёжных проверок переполнения.
- **Если пользователь просит шрифт вне безопасного списка** (например, Georgia или Trebuchet MS): используй его там, где просили, но задавай контейнерам дополнительный запас (~10%) и не доверяй проверке подгона текста на этих элементах — предпросмотр такого шрифта приблизителен. Если пользователь не указал шрифт, предпочитай безопасный список для основного текста.
- **Шрифты, ненадёжные для проверки** (замена имеет другую ширину — проверки переполнения могут ошибаться): Georgia, Trebuchet MS, Impact, Arial Black, Garamond, Consolas, Palatino Linotype. Подмена Calibri Light зависит от окружения; считай его ненадёжным. Годятся для заголовков и акцентов с запасом; не доверяй проверке подгона текста на них.
- **Никогда не используй Aptos по умолчанию** — шрифт Office по умолчанию после 2023 года не имеет здесь метрически совместимой замены *и* отсутствует в старых установках Office, поэтому ненадёжен с обеих сторон.

| Элемент           | Размер                |
|-------------------|-----------------------|
| Заголовок слайда  | 36-44pt, жирный       |
| Заголовок раздела | 20-24pt, жирный       |
| Основной текст    | 14-16pt               |
| Подписи           | 10-12pt, приглушённые |

### Отступы

- минимум 0.5″ от краёв;
- 0.3-0.5″ между блоками содержания;
- оставляй воздух — не заполняй каждый дюйм.

### Чего избегать (частые ошибки)

- **Не повторяй одну и ту же компоновку** — чередуй колонки, карточки и акценты по слайдам.
- **Не заканчивай заголовок слайда точкой.**
- **Не допускай, чтобы заголовки «плавали» между слайдами одного типа** — на содержательных слайдах заголовок сверху стоит в одном и том же месте, одним шрифтом, размером и выравниванием на каждом слайде; другой тип слайда (разделитель с заголовком посередине) может располагать его иначе.
- **Не меняй вид подписей диаграмм от диаграммы к диаграмме** — подписи осей и данных используют один цвет, шрифт и размер на всех диаграммах презентации; меняй что-то только там, где это нужно конкретной диаграмме (вторая ось, выделенный ряд, подпись на тёмной полосе).
- **Не выравнивай основной текст по центру** — абзацы и списки по левому краю; по центру только заголовки.
- **Не экономь на контрасте размеров** — заголовкам нужно 36pt и больше, чтобы отличаться от основного текста 14-16pt.
- **Не скатывайся к синему по умолчанию** — выбирай цвета, отражающие конкретную тему.
- **Не смешивай отступы случайно** — выбери 0.3″ или 0.5″ и используй последовательно.
- **Не оформляй один слайд, оставляя остальные простыми** — либо доводи до конца, либо держи простой стиль по всей презентации.
- **Не создавай слайды только с текстом** — добавляй изображения, значки, диаграммы или визуальные элементы; избегай простого «заголовок и маркеры».
- **Не забывай про внутренние отступы текстовых полей** — когда выравниваешь линии или фигуры по краям текста, ставь `margin: 0` у текстового поля или смещай фигуру с учётом отступа.
- **Не используй низкоконтрастные элементы** — и значки, и текст должны иметь сильный контраст с фоном; избегай светлого текста на светлом фоне и тёмного на тёмном.
- **НИКОГДА не используй акцентные линии под заголовками** — это признак слайдов, сгенерированных ИИ; используй пустое пространство или цвет фона.
- **НИКОГДА не добавляй декоративные цветные полосы и акцентные линии** — это касается полос в шапке и подвале на всю ширину слайда, вертикальных полос вдоль одного края слайда, тонких акцентных линий вдоль края карточки или блока содержания и «односторонних границ» у прямоугольников. Они читаются как сгенерированный ИИ наполнитель. Если нужно выделить карточку, используй мягкий оттенок фона, тень или значок, а не полосу по краю.
- **Не используй кремовые и бежевые фоны по умолчанию** — если фон не задан, используй белый (`FFFFFF`) или фирменную палитру пользователя; избегай тёплых нейтральных значений вроде `F5F5DC`, `FAF0E6`, `FAEBD7`, `FFF8E1`.
- **Не выпускай текст, выходящий за пределы фигуры** — если текст не влезает, уменьши шрифт, разбей на слайды или увеличь контейнер; никогда не оставляй обрезанное или вылезающее содержимое. **Не опускайся ниже размеров из таблицы типографики** (основной текст 14pt, подписи 10pt) в презентации, которую создаёшь, — когда дошёл до этого предела, сокращай слова, увеличивай контейнер или разбивай слайд; при правке готовой презентации или шаблона подстраивайся под его размеры.

## Проверка качества (обязательна) { id="qa" }

Первый рендер обычно содержит несколько настоящих дефектов — наложения, переполнение, смещения. Найди и исправь их, перерисуй только изменённые слайды и остановись.

### Проверка содержимого (обязательна)

```bash
python scripts/slide_text.py output.pptx
```

Проверь пропавшее содержимое, опечатки, неверный порядок.

**При работе с шаблонами проверь остатки текста-заглушки:**

```bash
python scripts/slide_text.py output.pptx | grep -iE "\bx{3,}\b|lorem|ipsum|\bTODO|\[insert|this.*(page|slide).*layout"
```

Если `grep` что-то нашёл, исправь это до того, как объявлять успех.

### Проверка файла (обязательна)

```bash
python scripts/office/validate.py output.pptx                      # собрано с нуля
python scripts/office/validate.py output.pptx --original src.pptx  # собрано по шаблону
```

**Если презентация собрана по шаблону, всегда передавай `--original`.** Сам шаблон может содержать части, которые XSD отвергает, поэтому запуск без него сообщит об ошибках, которых ты не вызывал, — и настоящая регрессия может спрятаться среди них. `--original` сравнивает проверки схемы и слайдов с шаблоном и подавляет ошибки, которые в нём уже были. Структурные проверки — связи, типы содержимого, диаграммы — игнорируют `--original` и сообщают унаследованные от шаблона проблемы в любом случае, поэтому оценивай их по существу.

pptxgenjs выдаёт XML диаграмм, который PowerPoint отказывается открывать, а все остальные инструменты принимают: python-pptx такие презентации открывает, LibreOffice их рисует, XSD их пропускает. Для каждой ошибки указано, как её исправить. Исправляй в генераторе и пересобирай.

**Успешная проверка не доказывает, что файл корректен:** `validate.py` ловит не всё, что PowerPoint исправляет (повторённый сверх предела элемент диаграммы проходит); когда удаляешь анимированную фигуру из слайда шаблона, удаляй и элемент `<p:timing>` этого слайда (его анимации уходят вместе с ним), иначе PowerPoint предложит исправить презентацию.

### Визуальная проверка (обязательна)

Преобразуй слайды в изображения (см. [«Преобразование в изображения»](#converting-to-images)) и просмотри каждое. После долгого взгляда на генерирующий код видишь то, что ожидаешь, а не то, что отрисовалось, поэтому смотри изображения свежим взглядом (для этого хорошо подходит субагент, если он у тебя есть). Дефекты, заметные пользователю:

- **Переполнение или обрезка текста на границе поля или слайда — проверяй это первым.** Это самый частый дефект, и он всегда виден пользователю. (Для шрифта, который предпросмотр отрисовывает ненадёжно по разделу типографики, предпросмотр приблизителен: доверяй оставленному запасу ~10%, а не видимому подгону.)
- Наложение элементов (текст поверх фигур, линии поверх слов, наложение блоков).
- Источники или колонтитулы, сталкивающиеся с содержимым выше.
- Слишком близкие элементы (зазоры меньше 0.3″) или почти соприкасающиеся карточки и разделы.
- Неравномерные зазоры (большая пустая область в одном месте, теснота в другом).
- Недостаточное поле от края слайда (меньше 0.5″).
- Колонки и подобные элементы, выровненные непоследовательно.
- Низкоконтрастный текст (например, светло-серый на кремовом фоне).
- Декор шаблона, сместившийся после замены текста — например, подчёркивание заголовка рассчитано на одну строку, а заменённый заголовок перенёсся на две.
- Низкоконтрастные значки (например, тёмные на тёмном фоне без контрастного круга).
- Слишком узкие текстовые поля, из-за которых текст переносится чрезмерно.
- Заголовки на разной высоте или подписи диаграмм, выглядящие по-разному от диаграммы к диаграмме, на слайдах одного типа — сравнивай слайды между собой, а не только каждый слайд с самим собой.
- Слово или число, разорванное на две строки, — слово, разбитое посередине, или число, отделённое от единицы измерения («26» на одной строке, «M» на следующей).
- Оставшийся текст-заглушка.

## Преобразование в изображения { id="converting-to-images" }

Преобразуй презентацию в отдельные изображения слайдов для визуальной проверки:

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 150 output.pdf slide
ls -1 "$PWD"/slide-*.jpg
```

**Передавай абсолютные пути, напечатанные выше, прямо в инструмент просмотра.** `rm` убирает устаревшие изображения прошлых запусков. `pdftoppm` дополняет номера нулями в зависимости от числа страниц: `slide-1.jpg` для презентаций до 10 страниц, `slide-01.jpg` для 10-99, `slide-001.jpg` для 100 и больше.

**После исправлений перезапусти все четыре команды выше** — PDF нужно заново собрать из изменённого `.pptx`, иначе `pdftoppm` не отразит правки.
