# Дисциплина хуков React

## Чистота рендера — это главное

Рендер компонента должен быть чистой функцией от props, состояния и контекста. Всё остальное место — в эффектах и обработчиках событий.

- Никогда не изменяй ref во время рендера (в рендере только чтение; запись — в эффектах и обработчиках).
- Никогда не вызывай `setState` безусловно в рендере или в теле другого компонента.
- Производные данные — через `useMemo` или обычное вычисление, а **не** вторым `useState`, который синхронизируют:

```tsx
// ❌ duplicated state to keep in sync
const [fullName, setFullName] = useState('')
useEffect(() => setFullName(`${first} ${last}`), [first, last])

// ✅ derived
const fullName = `${first} ${last}`
```

## Массивы зависимостей: будь полным, а потом честным

1. Включи `exhaustive-deps` из `eslint-plugin-react-hooks` и считай предупреждения ошибками.
2. Если зависимость *необходимо* опустить, напиши в комментарии почему и предпочти перестройку:

```tsx
// ❌ lie: latest always wins, silently breaks subscription
useEffect(() => {
  const id = setInterval(() => poll(url), 5_000)
  return () => clearInterval(id)
}, []) // url "won't change" — until it does

// ✅ restructure: keep it fresh via ref, or include it
const urlRef = useRef(url)
useEffect(() => { urlRef.current = url }, [url])
useEffect(() => {
  const id = setInterval(() => poll(urlRef.current), 5_000)
  return () => clearInterval(id)
}, [])
```

3. Объекты, массивы и функции в зависимостях срабатывают на каждом рендере — стабилизируй их у источника (`useMemo` и `useCallback` у *производителя* либо вынеси константы наружу).

## Собственные хуки: те же правила, что у компонентов

- Каждый собственный хук возвращает **стабильную форму** (кортеж или объект — выбери по кодбазе и держись этого).
- Эффекты в собственных хуках всё равно убирают за собой. Если хук подписывается, он и отписывается — без исключений.
- Одно поведение на хук. `useUserWithPostsAndComments` — это три хука в одном плаще.

## Приёмы, которые предотвращают 90% багов

- **Ref с последним значением** для подписок и интервалов, которые не должны перезапускаться (см. выше).
- **Отмена при размонтировании** для запросов:

```tsx
useEffect(() => {
  const ac = new AbortController()
  fetch(url, { signal: ac.signal })
    .then(setData)
    .catch((e) => e.name !== 'AbortError' && setError(e))
  return () => ac.abort()
}, [url])
```

- **Разделение события и эффекта**: если логика выполняется «когда пользователь нажал», она живёт в обработчике, а не в эффекте, следящем за флагом состояния.

## Антипаттерны

- Условные хуки и хуки в циклах или условиях (правило хуков — не обсуждается).
- Цепочки `useEffect`, повторяющие императивный поток (a → b → c). Моделируй состояние, а не шаги.
- Значение контекста пересоздаётся на каждом рендере без мемоизации — мемоизируй объект `value` или раздели контексты.
- Хранение функций в состоянии; храни данные, а поведение выводи.

## Критерий готовности (чек-лист агента)

- [ ] `exhaustive-deps` чист, отклонения задокументированы с причиной
- [ ] У каждого эффекта с подпиской, таймером или запросом есть очистка
- [ ] Нет состояния, выводимого из props или другого состояния
- [ ] Ключи в списках — стабильные идентификаторы
- [ ] Нет записи в ref во время рендера
