# Справочник по форматированию

Формат текста задаётся через `NewMessageBody.format` (а также `NewCommentBody.format`): `"markdown"` или `"html"`. Не указывай — будет простой текст. Действует только на `text` сообщения или комментария, но не на подписи кнопок и не на названия чатов.

## Markdown («Max flavored Markdown», на основе CommonMark 0.29)

| Эффект | Синтаксис |
|---|---|
| Курсив | `*emphasized*` или `_emphasized_` |
| Жирный | `**strong**` или `__strong__` |
| Зачёркивание | `~~strikethrough~~` |
| Подчёркивание | `++underline++` |
| Моноширинный (инлайн) | `` `code` `` |
| Моноширинный (блок) | ` ```code``` ` — переводы строк внутри схлопываются в пробелы, а не сохраняются |
| Выделение (по умолчанию красным) | `^^highlighted^^` |
| Цитата | `> quote` |
| Заголовок | `# Header` (уровни от `#` до `######`) |
| Инлайн-ссылка | `[Inline URL](https://dev.max.ru/)` |
| Упоминание пользователя | `[Имя Фамилия](max://user/user_id)` |

Правило упоминания: в тексте ссылки ставь полное отображаемое имя пользователя (имя и фамилия из его профиля MAX), а не заглушку вроде «User mention». Если фамилии нет, используй только имя.

```bash
curl -X POST "https://platform-api2.max.ru/messages?chat_id=$CHAT_ID" \
  -H "Authorization: $MAX_BOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "Привет, [Иван Петров](max://user/123456)!", "format": "markdown"}'
```

## HTML

Отрисовываются только эти теги, остальное вырезается:

| Эффект | Тег |
|---|---|
| Курсив | `<i>` или `<em>` |
| Жирный | `<b>` или `<strong>` |
| Зачёркивание | `<del>` или `<s>` |
| Подчёркивание | `<ins>` или `<u>` |
| Моноширинный | `<pre>` или `<code>` |
| Ссылка | `<a href="...">text</a>` |
| Выделение | `<mark>` |
| Цитата | `<blockquote>` |
| Заголовок | `<h1>` … `<h6>` — все уровни отрисовываются одинаково (без разницы в размере и начертании) |
| Упоминание пользователя | `<a href="max://user/user_id">Имя Фамилия</a>` |

Правило упоминания то же, что в markdown: текст ссылки — полное имя из профиля, только имя, если фамилии нет.

```json
{
  "text": "<b>Заказ подтверждён</b>. Связаться с <a href=\"max://user/123456\">Иваном Петровым</a>.",
  "format": "html"
}
```

## Что не поддерживается

- У списков (нумерованных и маркированных), горизонтальных линеек и таблиц нет синтаксиса ни в markdown, ни в HTML — их нет в таблицах тегов и синтаксиса схемы. Вывод сделан из отсутствия, явного заявления «не поддерживается» в DOCS нет.
- Инлайн-изображения через разметку markdown или HTML текста — медиа прикрепляй через `attachments`, а не через поле `text`.
- Вложенность и смешанная вложенность глубже одного уровня на элемент не документированы — не предполагай, что правила вложенности CommonMark работают за пределами перечисленных элементов.
- Блоки моноширинного работают с тройными обратными кавычками, но переводы строк внутри превращаются в пробелы — считай это ухудшенным поведением, а не отсутствием.

## Комментарии (`NewCommentBody.text`) — урезанное подмножество

Текст комментария **не** поддерживает гиперссылки и упоминания пользователей ни в Markdown, ни в HTML, независимо от `format`. Это ограничение есть только в DOCS (отдельного поля схемы для него нет — `NewCommentBody` просто не содержит `attachments`). Все остальные элементы markdown и HTML выше (жирный, курсив, зачёркивание, подчёркивание, моноширинный, выделение, цитата, заголовки) работают так же, как в сообщениях.

## Требования к версиям клиентов

- Форматирование текста (отрисовка markdown и HTML) требует **iOS ≥ 3.1** и **Android ≥ 2.20.0**. Старые клиенты показывают разметку и теги как есть.
- Диплинки (упоминания `max://user/...` используют тот же механизм) требуют **iOS ≥ 2.7.0** и **Android ≥ 2.9.0**.

## Практические советы

- Выбирай один формат на сообщение или комментарий: смешивать markdown-синтаксис в строке с `format: "html"` (и наоборот) нельзя — он отрисуется буквальным текстом.
- Обезвреживай пользовательский контент, прежде чем подставлять его в форматированный `text`: литеральные `*`, `_`, `` ` ``, `<`, `>` из пользовательского ввода могут разобраться как разметка. Синтаксиса экранирования документация не определяет — удаляй или заменяй эти символы либо отправляй пользовательский контент отдельным сообщением без `format`.
- `Message.body.markup` (разобранное представление в ответе) состоит из объектов `MarkupElement`, различаемых по `type`. Значения: `strong`, `emphasized`, `monospaced`, `strikethrough`, `underline`, `highlighted`, `quote`, `link`, `user_mention`, `heading`. У каждого есть `from` (начальный индекс с нуля) и `length`.
  - Заметка: свободное описание `MarkupElement.type` в самой схеме называет это значение «header», но фактический ключ в отображающем словаре — `heading` (`HeadingMarkup`). Используй `heading` — именно его API и присылает.
  - `LinkMarkup` добавляет `url` (1–2048 символов). `UserMentionMarkup` добавляет `user_link` (nullable, `@username`) и `user_id` (nullable) — упоминание разрешается по имени пользователя ИЛИ по `user_id`, когда имени нет.
- Поле `text` сообщения и комментария ограничено 4000 символами всего (см. таблицу лимитов в `bot-api.md`) — символы разметки тоже входят в лимит.
