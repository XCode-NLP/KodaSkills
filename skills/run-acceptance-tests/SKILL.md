Приёмочный тест — это функция Go-теста с префиксом `TestAcc`.

Перед запуском: приёмочные тесты создают **настоящую инфраструктуру** через живой
API провайдера, что может стоить денег. Убедись, что настроенные учётные данные
указывают на тестовый аккаунт, прежде чем продолжать.

Чтобы запустить отдельный приёмочный тест `TestAccFeatureHappyPath`:

1. Выполни `go test -run=TestAccFeatureHappyPath -timeout 60m` со следующими
   переменными окружения:
   - `TF_ACC=1`

   По умолчанию используй вывод теста без подробностей. Всегда передавай явный
   `-timeout`: `go test` по умолчанию убивает любой тест через 10 минут, а приёмочные
   тесты регулярно выходят за этот предел.
1. Приёмочным тестам могут понадобиться дополнительные переменные окружения для
   конкретных провайдеров. Чтобы узнать какие:
   - Прочитай функцию `PreCheck` / `testAccPreCheck` теста и поищи по тестовым
     файлам: `grep -rn "os.Getenv" --include="*_test.go"`.
   - Посмотри README, CONTRIBUTING или `.env.example` репозитория — там может быть
     описанная настройка тестов.
   - Метод `Configure` провайдера показывает, как находятся учётные данные;
     используй навык `provider-configuration` (если доступен), чтобы понять цепочку
     источников учётных данных.

   Задавай переменные для одного запуска теста
   (`EXAMPLE_API_KEY=... TF_ACC=1 go test ...`), а не экспортируй их
   в профиль оболочки, и никогда не записывай значения секретов в файлы внутри
   репозитория.

Чтобы разобрать падающий приёмочный тест, используй эти варианты по порядку. Они
накопительные: каждый включает все предыдущие.

1. Запусти тест снова. Используй опцию `-count=1`, чтобы `go test` не взял
   результат из кэша.
1. Включи подробный вывод `go test`. Используй опцию `-v`.
1. Включи журналирование уровня отладки. Включается переменной окружения
   `TF_LOG=debug`.
1. Предложи сохранить рабочую область Terraform приёмочного теста. Включается
   переменной окружения `TF_ACC_WORKING_DIR_PERSIST=1`.

Проходящий приёмочный тест может быть ложным результатом. Чтобы «перевернуть»
проходящий приёмочный тест `TestAccFeatureHappyPath`:

1. Измени значение одного из TestCheckFunc в одном из TestSteps внутри
   TestCase.
1. Запусти приёмочный тест. Ожидай, что тест упадёт.
1. Если тест упал, отмени правку и сообщи об успешном перевороте. Иначе
   оставь правку и сообщи о неудачном перевороте.

Если запуск теста прерван, настоящие ресурсы могут остаться; запусти
уборщики (sweepers) провайдера, если он их регистрирует (см. справочник по уборщикам
в навыке `provider-test-patterns`, если доступен). Для написания и перестройки
тестов используй навык `provider-test-patterns`.
