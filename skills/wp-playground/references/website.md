## Работа с сайтом Playground

Используй этот справочник для настройки и публикации на `https://playground.wordpress.net/`,
а также для выбора способа взаимодействия с уже открытым сайтом в браузере.

## Сначала маршрутизация

- Для структуры JSON Blueprint, схемы, ресурсов, шагов и наборов используй навык
  `blueprint`: он источник истины по деталям Blueprint.
- Для локальных примонтированных путей, снимков, Xdebug и проверки без интерфейса
  вернись к процедуре маршрутизации `wp-playground` и выбери локальный CLI или процесс
  отладки.
- Для нового сайта или ссылки для публикации используй Query API и настройку URL
  Blueprint ниже. Настроечные URL применяются при загрузке страницы: не перезагружай
  существующий сайт только чтобы выполнить операцию во время работы.

## Выбор способа взаимодействия

Уважай способ подключения, который пользователь явно попросил. Иначе предпочитай
доступные инструменты WebMCP для поддерживаемых операций. Доступность означает, что
инструменты предоставлены и вызываемы в этой сессии, а не просто что браузер может
открыть Playground.

Читай только справочник, нужный для выбранного способа:

| Способ | Когда использовать | Справочник |
| --- | --- | --- |
| WebMCP | По умолчанию для поддерживаемых операций через инструменты сайта на открытой странице. | [WebMCP](webmcp.md) |
| Playground MCP | Пользователь просит его, либо WebMCP недоступен или не умеет операцию, а подходящее подключение MCP есть. | [Playground MCP](mcp.md) |
| Sites API и клиент активного сайта | Пользователь просит браузерные JavaScript-API, либо доступные инструменты сайта и MCP не поддерживают операцию. | [Sites API](sites-api.md) |

Переключайся по операциям и загружай запасной справочник только когда нужно. При смене
способа сохраняй тот же сайт: не создавай замену и не перезагружай страницу, теряя
текущую работу пользователя. Перед изменениями подтверди цель безвредной операцией
чтения и проверь результат на том же сайте.

## Создание или открытие сайта по URL

Для пустого одноразового сайта Playground используй `https://playground.wordpress.net/`
без параметров запроса.

Используй URL Query API, когда настройку просто выразить параметрами:

```text
https://playground.wordpress.net/?php=8.4&wp=latest&plugin=gutenberg&networking=yes&url=/wp-admin/post-new.php
```

Практичные параметры URL для агентов:

- `php=<version>` и `wp=<version>`: выбрать версии среды выполнения.
- `plugin=<slug>` и `theme=<slug>`: установить ресурсы с WordPress.org; повторяй
  параметр для нескольких ресурсов, например
  `?plugin=gutenberg&plugin=woocommerce&networking=yes`.
- `networking=yes|no`: разрешить или запретить загрузку плагинов, тем, переводов,
  импортов и сборок PR. Используй `networking=no` или не указывай сеть для офлайн- и
  простых проверок.
- `login=yes|no`: управлять автоматическим входом в админку. `login=no` отключает
  автовход; страницы админки потребуют ручного входа.
- `multisite=yes|no`: выбрать режим одиночного сайта или мультисайта при загрузке.
- `url=/path/`: выбрать первую отображаемую страницу. Используй `/wp-admin/` для
  панели управления или `/wp-admin/site-editor.php` для редактора сайта.
- `language=<locale>`: задать локаль WordPress, например `de_DE`; сочетать с
  `networking=yes`, чтобы переводы могли загрузиться.
- `import-site=<zip-url>`: импортировать публичный ZIP сайта с поддержкой CORS (URL
  закодирован).
- `import-wxr=<wxr-url>`: импортировать публичный файл экспорта WordPress (XML/WXR) с
  поддержкой CORS (URL закодирован).
- `site-slug=<slug>`: выбрать сохранённый сайт в браузере по слагу. Сначала найди
  существующие слаги выбранным способом взаимодействия.
- `if-stored-site-missing=prompt`: спросить пользователя, сохранять ли новый сайт, если
  `site-slug` не найден.
- `blueprint-url=<url>`: загрузить публичный JSON Blueprint или ZIP-набор Blueprint.
- `lazy`: показать кнопку запуска и отложить загрузку до нажатия — полезно для
  обучающих материалов и демонстраций «нажми и запусти».
- `mode=browser-full-screen|seamless`: выбрать интерфейс браузера или WordPress на всю
  ширину.
- `page-title=<title>`: задать заголовок вкладки браузера, когда сравниваешь
  экземпляры.
- `can-save=no`: убрать из интерфейса возможности сохранения.
- `overlay=blueprints`: открыть галерею Blueprint при загрузке.

Придерживайся правил:

- Используй ссылки Query API для простой переносимой настройки.
- Используй URL Blueprint и фрагменты для многошаговой настройки, файлов, создания
  содержимого, собственного кода и упакованных ресурсов.
- Не объясняй здесь схему Blueprint: содержимое Blueprint передавай навыку `blueprint`.
- Размещённые JSON Blueprint, ZIP-наборы, импорты и упоминаемые ресурсы должны быть
  публичными и отдаваться с заголовком `Access-Control-Allow-Origin: *`.
- URL в браузере не читают произвольные локальные файлы и локальные наборы-директории.
  Для локальных путей используй размещённые ресурсы или CLI.
- Если появился запрос о недостающем `site-slug`, подтверди намерение пользователя
  прежде чем создавать или сохранять новый сайт в браузере.

Небольшие Blueprint можно публиковать фрагментом URL:

```text
https://playground.wordpress.net/#<encodeURIComponent(JSON.stringify(blueprint))>
```

Для больших Blueprint и наборов используй:

```text
https://playground.wordpress.net/?blueprint-url=<public-json-or-zip-url>
```

Фрагменты Blueprint в кодировке base64 тоже поддерживаются, когда канал искажает
символы JSON.

Другие возможности URL, которые могут понадобиться агенту:

- Экспериментальные сборки: `core-pr=<number>` для PR ядра WordPress,
  `gutenberg-pr=<number>` для PR Gutenberg, `gutenberg-branch=<branch>`, например
  `trunk`.
- Расширение среды выполнения: `php-extension=<manifest-url>`; принимает URL HTTP(S) и
  может повторяться.
- Предзаполнение формы экспорта в GitHub: `gh-ensure-auth=yes`,
  `ghexport-repo-url=<repo-url>`, `ghexport-pr-action=create|update`,
  `ghexport-playground-root=<path>`, `ghexport-repo-root=<path>`,
  `ghexport-content-type=plugin|theme|wp-content|custom-paths`,
  `ghexport-plugin=<plugin-path>`, `ghexport-theme=<theme-dir>`, повторяемый
  `ghexport-path` (`ghexport-path=<relative-path>`),
  `ghexport-commit-message=<message>`, `ghexport-allow-include-zip=yes|no`.

## Проверка и ограничения браузера

- Сгенерированный URL открой в новой сессии браузера и проверь версии, состояние входа,
  установленные ресурсы и целевую страницу.
- Если размещённый Blueprint или импорт не работает, проверь, что URL публичный и
  отдаётся с поддержкой CORS.
- Для операций с существующим сайтом следуй указаниям по проверке из выбранного
  справочника по взаимодействию.
- Считай `playground.wordpress.net` браузерной демонстрацией и песочницей, а не рабочим
  хостингом и не гарантированно надёжной инфраструктурой.
- Переходи к CLI или полному стеку WordPress, когда задаче нужны локальные
  примонтированные пути, снимки, проверка без интерфейса, долговременное хранение в
  духе рабочего окружения, прямой доступ к базе, серверная интеграция или гарантии
  доступности.
