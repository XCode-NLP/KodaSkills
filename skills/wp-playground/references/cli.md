## Работа с Playground CLI

Используй этот справочник для локальных запусков WordPress Playground через
`@wp-playground/cli`: одноразовые и сохраняемые локальные серверы, примонтированные
плагины и темы, выполнение Blueprint, снимки, переключение версий и локальные дымовые
проверки.

## Требования

- Node.js 20.18+ с доступными `npm` и `npx`.
- Локальный проект, плагин, тема, файл Blueprint или путь к набору Blueprint.
- Свободный локальный порт при использовании `server`; по умолчанию `9400`.

Когда важны точные флаги, смотри справку установленного CLI:

```bash
npx @wp-playground/cli@latest --help
npx @wp-playground/cli@latest start --help
npx @wp-playground/cli@latest server --help
```

## Быстрая локальная разработка

Используй `start` для обычной работы с локальным плагином или темой. Он определяет тип
проекта, монтирует его, открывает браузер, включает автоматический вход в админку и
сохраняет сайт между сессиями.

```bash
cd <plugin-or-theme-root>
node -v
npx @wp-playground/cli@latest start
```

- Используй `npx @wp-playground/cli@latest start --reset`, когда сохранённый сайт нужно
  создать заново.
- Используй `server` с явными `--wp=<version>` и `--php=<version>`, когда нужно
  воспроизвести проблемы совместимости, а не полагаться на меняющиеся умолчания.

## Расширенный локальный сервер

Используй `server`, когда нужен полный ручной контроль, одноразовый сайт, поведение как
в CI, собственные примонтированные пути или сервер на основе Blueprint:

```bash
npx @wp-playground/cli@latest server --auto-mount
```

- `--auto-mount[=<path>]` определяет директорию WordPress, плагин, тему, директорию
  wp-content или директорию с PHP и HTML.
- Добавляй `--port=<free-port>`, если стандартный порт занят.
- Для существующих файлов WordPress предпочитай
  `--wordpress-install-mode=install-from-existing-files-if-needed`, чтобы пропустить
  установку, когда сайт уже есть.
- Используй `--wordpress-install-mode=do-not-attempt-installing`, только когда файлы
  WordPress и работа с базой уже обеспечены примонтированным деревом.

## Ручное монтирование

Используй явные примонтированные пути, когда автоматического мало:

```bash
npx @wp-playground/cli@latest server \
  --mount=/absolute/host/path:/wordpress/wp-content/plugins/my-plugin
```

- Указывай абсолютные пути хоста.
- Повторяй `--mount=` для нескольких плагинов, mu-плагинов, тем или своего содержимого.
- Используй `--mount-before-install`, когда установщику или шагам Blueprint нужны
  смонтированные файлы до завершения установки WordPress.
- В Windows или когда отображения через двоеточие неудобны, используй
  `--mount-dir "/host/path" "/vfs/path"` или
  `--mount-dir-before-install "/host/path" "/vfs/path"`.

## Запуск Blueprint

Для установки без интерфейса или проверки в стиле CI:

```bash
npx @wp-playground/cli@latest run-blueprint --blueprint=<file-or-url>
```

- Для структуры JSON Blueprint и подробностей схемы используй навык `blueprint`.
- Добавляй `--blueprint-may-read-adjacent-files`, когда локальная директория или набор
  Blueprint ссылается на соседние файлы.
- Добавляй `--verbosity=debug`, когда нужно разобрать выполнение шагов.

## Сервер из Blueprint

```bash
npx @wp-playground/cli@latest server --blueprint=<file-or-url>
```

Для локальных наборов-директорий:

```bash
npx @wp-playground/cli@latest server \
  --blueprint=./my-bundle/ \
  --blueprint-may-read-adjacent-files
```

ZIP-наборы самодостаточны и не требуют доступа к соседним файлам.

## Сборка снимка

```bash
npx @wp-playground/cli@latest build-snapshot \
  --blueprint=<file-or-url> \
  --outfile=./site.zip
```

- Используй снимки для воспроизводимых случаев и артефактов CI.
- Перезапусти с `--verbosity=debug`, если созданный сайт не содержит ожидаемого
  состояния.

## Переключение версий

- Используй `--wp=<version>`, чтобы зафиксировать WordPress.
- Используй `--php=<version>`, чтобы зафиксировать PHP.
- Для воспроизведения ошибок и проверки совместимости предпочитай явные версии.
- Поддерживаемые значения версий и умолчания уточняй в справке CLI или в актуальной
  документации Playground.

## Проверка

- Убедись, что плагин появился в списке плагинов админки и активен, когда это
  ожидается.
- При проверке тем убедись, что выбрана нужная тема.
- Для Blueprint после запуска проверь ожидаемые параметры, страницы, плагины, темы и
  файлы.
- Для снимков загрузи ZIP в свежий экземпляр Playground, прежде чем передавать его как
  воспроизводимый артефакт.

## Сбои

- **Ошибка версии Node**: обнови до Node.js 20.18+.
- **Примонтированный путь не применился**: используй абсолютный путь, проверь
  виртуальный путь и перезапусти с `--verbosity=debug`.
- **Blueprint не может прочитать локальные ресурсы**: добавь
  `--blueprint-may-read-adjacent-files` для локальных наборов-директорий.
- **Порт уже занят**: передай `--port=<free-port>`.
- **Нужен свежий сохранённый сайт `start`**: перезапусти с `start --reset`.
- **Нужны точки останова или журналы среды выполнения**: вернись к процедуре
  маршрутизации `wp-playground` и выбери процесс отладки.
