# Разрешение недостающих типов GraphQL

Используй эти инструкции, когда нужного типа нет в накопленном SDL или он попал в `unresolvedTypeNames`.

## Определение нужных типов

Считай `schemaTruncated: true` указанием на то, что часть достижимых типов не попала в SDL из-за ограничения `typeDepth`. Это не мешает сборке документа, если все типы на путях, которые действительно использует документ, уже описаны.

До сборки документа определи типы, которые используются:

- в аргументах корневой операции и переданных входных объектах
- в выбранных полях ответа
- в наборах выборки составных типов
- во встроенных фрагментах для интерфейсов и объединений

Не разрешай автоматически все значения из `unresolvedTypeNames`. Тип, который не встречается на используемом пути, в дополнительном описании не нуждается.

## Накопление и переиспользование SDL

Считай успешные результаты описания неизменяемыми в пределах одного `schemaRef` и переиспользуй их на протяжении текущей задачи. Веди накопленный SDL отдельно для каждого `schemaRef`; не переноси определения между версиями схемы.

После успешного вызова `GqlDescribeOperations` не повторяй вызов с теми же:

- `schemaRef`
- `operationType`
- набором `operationNames`, независимо от порядка имён
- `typeDepth`

Нормализуй набор имён при проверке на дубли: убери повторы и сравни отсортированные значения. Если нужна ещё одна операция, передавай только те `operationNames`, которые ещё не описаны; не включай имена, уже полученные для того же `schemaRef` и `operationType`.

Не повторяй успешный вызов `GqlDescribeTypes` с теми же `schemaRef`, контекстом исходной операции, набором `typeNames` независимо от порядка и `typeDepth`. Нормализуй `typeNames` так же, как `operationNames`.

Вызов описания можно повторить только если предыдущий вызов технически упал и не вернул результат, если изменился `schemaRef` или если запрашивается новая операция либо новый нужный тип.

## Получение недостающих типов

Собирай нужную схему постепенно: сначала получи определения типов результата и аргументов через `GqlDescribeOperations`, затем запрашивай только недостающие типы на путях, которые действительно использует документ.

Перед вызовом `GqlDescribeTypes` исключи из `typeNames`:

- типы, точные определения которых уже есть в накопленном SDL
- типы, которых нет на используемых путях
- типы, добавленные только потому, что они есть в общем списке `unresolvedTypeNames`

Если нужный нестандартный тип есть в `unresolvedTypeNames` или у него нет точного определения в накопленном SDL:

1. Вызови `GqlDescribeTypes`.
2. Передай тот же `schemaRef` и имя с типом исходной корневой операции.
3. В `typeNames` передай точные имена только тех нужных типов, определения которых всё ещё отсутствуют в накопленном SDL.
4. Используй `typeDepth: 1`. Если нужный дочерний тип остался в `unresolvedTypeNames`, опиши этот дочерний тип напрямую следующим вызовом, а не повторяй уже описанный родитель с большей глубиной.
5. Слей полученный SDL с исходным описанием операции и перепроверь используемые пути.

`GqlDescribeTypes` возвращает один общий SDL для всех переданных `typeNames`; общие типы и пересекающиеся поддеревья дедуплицируются. Если один запрошенный тип достижим из другого, всё равно передай оба имени, когда оба нужны как независимые корни обхода: глубина применяется к каждому независимо.

Если в новом результате снова есть `unresolvedTypeNames`, опиши только ещё не полученные дочерние типы, которые встречаются на используемых путях. Если определение родителя уже известно, запрашивай тип его нужного поля, а не родитель заново.

Не используй `GqlSearchOperations` для поиска типов и не ищи другую корневую операцию только ради определения вложенного типа.

## Проверка полноты определений

Считай тип описанным только когда нужное имя точно совпадает с именем объявления в накопленном SDL. Не используй совпадения по префиксу или подстроке. Считай определёнными без отдельного объявления только встроенные скалярные типы GraphQL: `Int`, `Float`, `String`, `Boolean` и `ID`.

Если определение нужного типа получить не удалось:

- пропусти соответствующий блок, когда он необязателен для задачи
- если блок обязателен, сообщи об ограничении и не выполняй документ
- не угадывай вид типа, его поля, значения перечислений, структуру входа и сериализацию
