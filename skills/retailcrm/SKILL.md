# Работа с RetailCRM

Общайся с пользователем на языке его запроса.

Работай с RetailCRM только через `retailcrm_mcp`. Не обходи `retailcrm_mcp` прямыми HTTP-запросами и не используй угаданные методы API.

Не запрашивай, не раскрывай и не сохраняй токены доступа.

Если `retailcrm_mcp` недоступен или возвращает `401` или `403`, объясни, что его подключение или авторизацию нужно настроить вне этого навыка, и остановись. Не проси токен и не обходи MCP прямыми HTTP-запросами.

## Работа с запросами

1. Найди подходящие корневые операции через `GqlSearchOperations`.
2. Получи контракты выбранных операций через `GqlDescribeOperations`.
3. При необходимости вызови `GqlDescribeTypes`, чтобы доопределить только недостающие типы на путях, которые действительно использует документ.
4. Собери минимальный GraphQL-документ, используя только полученный SDL.
5. Проверь весь документ по накопленному SDL.
6. Выполни документ через `GqlExecuteOperation` с тем же `schemaRef`; мутацию выполняй только после отдельного явного подтверждения пользователя.

### 1. Поиск подходящих корневых операций

Вызови `GqlSearchOperations` с коротким поисковым запросом по устойчивому термину сущности или действия, который соответствует бизнес-цели пользователя.

- Используй `operationType = query` для чтения и `operationType = mutation` для изменений.
- Строй короткий поисковый запрос из самого устойчивого термина сущности или действия.
- Используй поиск только для корневых операций. Не ищи им вложенные поля и типы.
- Для чатов, переписки, сообщений, быстрых ответов и ботов предпочитай найденную операцию, у которой `schemaRef` начинается с `node`. Если совместимой операции Node нет, выбери найденную альтернативу и объясни выбор; не выдумывай операцию Node.
- Сохраняй имена и сигнатуры подходящих операций и полученный `schemaRef`.
- Если результат пустой или неоднозначный, уточни поисковый запрос терминами предметной области и повтори поиск. Не выбирай метод по памяти.

### 2. Получение контрактов выбранных операций

Вызови `GqlDescribeOperations` до сборки документа.

- Передай имена операций, найденные на предыдущем шаге.
- Передай тот же `operationType` и соответствующий `schemaRef`, которые вернул поиск.
- Начинай `GqlDescribeOperations` с минимальной глубины, `typeDepth: 1`. Недостающие типы добирай выборочно через `GqlDescribeTypes`.
- Изучи аргументы, обязательные поля, входные типы, перечисления, пагинацию и доступные поля ответа.
- Если нужного типа нет в SDL или он попал в `unresolvedTypeNames`, переходи к шагу 3. Не ищи другую корневую операцию ради получения вложенного типа.
- Не объединяй в одном документе операции с разными значениями `schemaRef`.
- Переиспользуй успешный результат `GqlDescribeOperations` в пределах одного `schemaRef`; не повторяй идентичный вызов.

### 3. Доопределение недостающих типов

Пропусти шаг, если накопленный SDL уже содержит точные определения всех типов на путях, которые действительно использует документ.

Если нужного типа нет в SDL или он попал в `unresolvedTypeNames`, используй `GqlDescribeTypes`. Перед вызовом прочитай [инструкции по разрешению типов](references/schema-resolution.md).

Запрашивай только недостающие типы на путях, которые действительно использует документ, и сливай полученный SDL с описанием операции в пределах одного `schemaRef`. Не запрашивай описания неизвестных или угаданных имён типов.

Если определение нужного типа получить не удалось, не угадывай его структуру — вернись к поиску.

### 4. Сборка GraphQL-документа

Собирай полный GraphQL-документ только по результатам поиска и описания.

Если операция возвращает список или соединение, перед сборкой документа прочитай [инструкции по списочным операциям](references/list-operations.md).

- Используй только найденные имена операций, аргументы, типы и поля; не добавляй угаданные элементы.
- Дай операции имя и вынеси значения от пользователя в переменные GraphQL, если инструмент поддерживает отдельный параметр `variables`.
- Выбирай только минимально нужные поля для каждого объекта GraphQL. Запрашивай только те вложенные объекты и коллекции, которые будут использованы.
- Сложную задачу разбей на независимые блоки данных. Проверяй каждый блок отдельно по накопленному SDL.
- Объединяй блоки в один документ только если у них один `schemaRef`, один тип операции и они не зависят от результатов друг друга.
- У каждого поля составного типа (объект, интерфейс, объединение) должен быть непустой набор выборки с нужными вложенными полями. Применяй это рекурсивно ко всем вложенным составным полям; не запрашивай объект как скаляр.
- Не включай `__typename`, `__schema`, `__type` и любые другие служебные поля интроспекции. Не выполняй запросы интроспекции.

### 5. Проверка документа перед выполнением

Перед каждым вызовом `GqlExecuteOperation` проверь итоговый документ по накопленному SDL. Не вызывай выполнение, пока не подтверждён каждый пункт:

- корневая операция и все переданные аргументы есть в SDL, а все обязательные аргументы переданы
- типы переменных и использованные значения перечислений соответствуют SDL
- каждое выбранное поле есть у его непосредственного родительского типа
- у каждого поля типа объекта, интерфейса, объединения или списка таких объектов есть непустой набор выборки
- у скалярных полей и полей перечислений нет набора выборки
- в документе нет полей, имена которых начинаются с `__`
- у каждого использованного нестандартного типа есть точное определение, без пропущенных и неразрешённых типов на используемых путях
- в документе нет угаданных операций, аргументов, полей, типов и значений перечислений

Если какой-то пункт подтвердить нельзя, не вызывай выполнение. Исправь документ по накопленному SDL; если не хватает определения типа, вернись к шагу 3. Если нужную часть документа подтвердить нельзя, сообщи об ограничении. Перепроверяй весь документ после каждого изменения.

### 6. Выполнение документа

После шага 5 выполни запрос через `GqlExecuteOperation`, передав `document`, переменные и тот же `schemaRef`.

Если один и тот же документ нужно выполнить несколько раз с разными переменными, перед повтором прочитай [инструкции по повторным запросам](references/repeated-queries.md).

Мутация требует отдельного явного подтверждения пользователя. Не считай подтверждением исходную просьбу изменить данные. До сборки документа, запроса подтверждения и выполнения мутации прочитай [инструкции по мутациям](references/mutations.md).

Если `GqlExecuteOperation` вернул ошибку проверки, не повторяй тот же документ — вернись к шагу 5.

## Работа с результатом

- Отличай ошибки документа, прав и бизнес-проверок от успешного пустого результата.
- Не заявляй об успехе, если ответ содержит ошибки GraphQL.
- После мутации сообщи, что изменилось, и указывай устойчивые идентификаторы только когда ответ подтверждает изменение.
