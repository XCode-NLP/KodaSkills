# SDK Wildberries

API продавца Wildberries — около 350 операций на десятке хостов, и каждую защищает своя категория токена. Клиенты `wildberries-sdk` генерируют типизированный метод для каждой операции на пяти языках из официальных OpenAPI-спецификаций, которые перепубликуются в течение суток после изменения спецификации.

Работать с этим хорошо — значит в основном две вещи: найти нужную операцию и правильно настроить авторизацию. Угадывать имена методов бесполезно: они генерируются из HTTP-маршрута, а не из человеческого названия действия.

## 1. Сначала найди операцию

Никогда не выдумывай имя метода. Ищи по сводке всех операций, где для каждой указаны маршрут, обязательные параметры и точное имя метода во всех пяти клиентах:

```bash
python scripts/find_operation.py "остатки"            # поиск по смыслу, по-русски или по-английски
python scripts/find_operation.py "/api/v3/orders"     # или по маршруту
python scripts/find_operation.py "отзыв" --lang python
```

Скрипт читает <https://eslazarev.github.io/wildberries-sdk/llms-full.txt> и кэширует его на сутки. Каждый результат выглядит так:

```
### Обновить остатки товаров
route: PUT /api/v3/stocks/{warehouseId}
host: https://marketplace-api.wildberries.ru
sandbox: https://marketplace-api-sandbox.wildberries.ru
required: warehouseId
body: object — python put_v3_stocks_warehouse_id_request, node putV3StocksWarehouseIdRequest, go .PutV3StocksWarehouseIdRequest()
python: wildberries_sdk.items.DefaultApi.put_v3_stocks_warehouse_id(warehouse_id, put_v3_stocks_warehouse_id_request)
node: DefaultApi.putV3StocksWarehouseId
go: client.DefaultApi.PutV3StocksWarehouseId
php: Wildberries\Sdk\Items\Api\DefaultApi::putV3StocksWarehouseId
rust: wildberries_sdk_items::apis::default_api::put_v3_stocks_warehouse_id
docs: https://eslazarev.github.io/wildberries-sdk/reference/items/put_api_v3_stocks_warehouseid/
```

Страница из строки `docs:` содержит полное описание от WB, все параметры и запускаемый пример на каждом языке. Открывай её, когда однострочного описания не хватает: в частности, именно там WB указывает, **какая категория токена** нужна методу.

Если поиск ничего не нашёл, расширь запрос (один русский корень вроде `постав` лучше целой фразы) или посмотри список модулей в `references/modules.md`.

## 2. Выбери модуль и установи только его

API разбит на модули, повторяющие спецификации: `items`, `orders_fbs`, `orders_fbw`, `orders_dbw`, `orders_dbs`, `dbs`, `in_store_pickup`, `promotion`, `communications`, `rates`, `analytics`, `reports`, `finances`, `general`, `wbd`. Модуль операции назван в строке `python:`.

`references/modules.md` описывает, что лежит в каждом модуле и с каким хостом WB он работает. Установка по языкам:

| Язык | Установка | Импорт |
| --- | --- | --- |
| Python | `pip install wildberries-sdk` | `from wildberries_sdk import finances` |
| Node.js | `npm install wildberries-sdk` | `import { DefaultApi } from 'wildberries-sdk'` |
| Go | `go get github.com/eslazarev/wildberries-sdk/clients/go/finances` | один модуль на область |
| PHP | `composer require eslazarev/wildberries-sdk` | `Wildberries\Sdk\Finances\...` |
| Rust | `cargo add wildberries_sdk_finances` | один крейт на область |

Python и Node поставляют все модули одним пакетом; Go и Rust публикуют по модулю или крейту на область, так что ставь тот, к которому относится операция.

## 3. Авторизация: токен передаёт вызывающая сторона

Каждый метод авторизуется токеном API продавца в заголовке `Authorization`. Бери его из окружения (`WB_API_TOKEN` — соглашение в примерах самого SDK) или из хранилища секретов, которое уже использует проект, и никогда не зашивай его в код и не выводи пользователю — он даёт полный доступ к аккаунту продавца.

```python
import os
from wildberries_sdk import finances

api = finances.DefaultApi(
    finances.ApiClient(
        finances.Configuration(api_key={"HeaderApiKey": os.environ["WB_API_TOKEN"]})
    )
)
balance = api.get_v1_account_balance()
```

Остальные четыре языка отличаются только синтаксисом — точное создание клиента, тип ошибки и работа с асинхронностью описаны в `references/<язык>.md`.

WB выдаёт токены **по категориям** (Контент, Маркетплейс, Статистика, Продвижение, Вопросы и отзывы, Цены и скидки, Аналитика, Поставки, Финансы, Возвраты и т. д.), плюс различает персональный и сервисный токен. Токен не из той категории вернёт 401 или 403 при любом правильном вызове, поэтому когда запрос отклонён, проверь категорию на странице `docs:` операции, прежде чем отлаживать код.

## 4. Хост задаётся операцией, и трём клиентам его надо указывать явно

WB разносит API по десятку доменов — `content-api`, `marketplace-api`, `advert-api`, `finance-api` и так далее, — и хост относится к операции, а не к модулю. Его даёт строка `host:` в сводке.

| Клиент | Хост |
| --- | --- |
| Python | вшит в каждый метод; не трогай |
| Go | разрешается из сгенерированной карты `OperationServers`; не трогай |
| Node.js | **обязательно задать** — по умолчанию рантайм берёт `http://localhost` |
| PHP | **обязательно задать** через `setHost()` — тот же умолчание |
| Rust | **обязательно задать** через `configuration.base_path` — тот же умолчание |

Для Node, PHP и Rust вызов без базового адреса не падает громко с ошибкой «неверный хост» — он идёт на localhost и умирает с ошибкой соединения, которая выглядит как сетевая проблема и уводит отладку не туда. Ставь его из строки `host:` каждый раз.

Поскольку хост следует за операцией, а не за модулем, один модуль может охватывать несколько сервисов: `communications` покрывает отзывы, чат с покупателем и возвраты на трёх разных доменах. Строй по клиенту на хост.

Где в сводке есть строка `sandbox:`, такое окружение существует. Используй его всегда, когда задача иначе запишет реальные данные — создание заказов, изменение цен, ответы покупателям, — а пользователь явно не сказал работать в продакшене. В Python передавай `_host_index=1`; в остальных случаях направь базовый адрес на песочницу.

## 5. Имена: параметры и тело запроса

Не выводи их из спецификации — в сводке лежат реальные, считанные из опубликованных клиентов.

Строка `python:` заканчивается сигнатурой вызова в написании самого клиента: `isAnswered` из спецификации там `is_answered`, и передача имени из спецификации вызывает `TypeError`.

Строка `body:` называет параметр тела на каждом языке, потому что он никогда не называется `body`: генератор называет его по модели, придумывая имя из идентификатора операции, когда WB объявляет тело внутри описания. Node и Go принимают его как `putV3StocksWarehouseIdRequest` и `.PutV3StocksWarehouseIdRequest(...)` соответственно; PHP и Rust — позиционно.

Передача тела под угаданным ключом на WB тихо опасна: несколько методов записи не проверяют имена полей и отвечают `204`, ничего не изменив. Если запись «успешна», а ничего не сдвинулось, подозревай ключ раньше логики и перечитай состояние, чтобы убедиться.

## 6. Код, который переживёт следующий релиз

- **Клиенты сгенерированы.** Никогда не правь ничего внутри пакета клиента ради обхода бага: следующее изменение спецификации это перезапишет. Сообщай о проблеме в спецификации.
- **Операции появляются и исчезают каждую неделю.** Закрепляй версию в продакшен-коде и перезапускай поиск, а не доверяй имени метода из памяти.
- **Лимиты запросов — на профиль продавца и группу методов.** WB отвечает 429 с окном повтора; сделай паузу и повтори, а не ускоряй цикл.
- **Пагинация явная.** Большинство списочных методов принимают `limit` и `skip` или курсор в теле запроса — страница операции показывает что именно, а строка `required:` в сводке — что обязательно передать.
- **Ответы — типизированные модели**, а не словари. Обращайся к атрибутам (`result.data.feedbacks`), и пусть IDE или компилятор ловит переименования полей.
