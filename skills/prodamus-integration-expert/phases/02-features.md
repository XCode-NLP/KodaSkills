# Фаза 2 — Features (функции и порядок)

Цель: вместе с пользователем выбрать, какие функции Prodamus войдут в
интеграцию, и в каком порядке их реализовывать. Выбор ложится в основу
дизайна (фаза 3) и плана (фаза 5).

Если в STATE выбран путь «готовая интеграция из каталога» — эта фаза не
нужна: функции определяет готовое решение, вернись к его инструкции.

При точечном входе (брифа нет) собери минимум: что продаётся, сумма
фиксированная или свободная, разовая оплата или подписка, где живёт
продажа (сайт/CRM/бот).

## Шаг 0. Свежесть каталога функций

Проверь дату «Последняя сверка» в `references/features.md`. Старше 7 дней
и есть сеть — сначала сверь каталог с живой документацией и обнови его
(правило — SKILL.md, «Свежесть данных»).

## Шаг 1. Предложи функции

Возьми `references/features.md` и собери предложение под бриф — не весь
каталог, а релевантное. Формат — нумерованный список с пометками:

1. Оплата с фиксированной суммой — **рекомендую: база вашего сценария**
2. Оплата по свободной сумме (клиент сам вводит сумму)
3. Подписки / автоплатежи
4. Рассрочка (включена по умолчанию — можно отключить)
5. Работа с маркировкой
6. …

Что в списке обязательно проверь по брифу: свободная vs фиксированная
сумма (или обе), подписки, рассрочка, скидки, методы оплаты, срок
действия ссылки, маркировка (если товары маркируемые), 54-ФЗ,
сквозные параметры. Для мерчанта — формулировки из блока «Подсказки»
в `features.md`.

## Шаг 2. Спроси выбор и порядок

Два вопроса (по одному — `references/dev-practices.md` §1):

1. Какие функции нужны? (мультивыбор по списку; предложи свой набор
   «рекомендую» как вариант по умолчанию)
2. В каком порядке делать? Что должно заработать в первую очередь
   (MVP), что можно позже? Предложи свой порядок: сначала базовая
   оплата + webhook, затем остальное по убыванию ценности.

## Шаг 3. Уточни детали выбранного

Только по выбранным функциям, по одному вопросу: подписки — период и
сумма; маркировка — какие товары; методы оплаты — какие разрешить;
свободная сумма — есть ли минимум/максимум; и т.п.

## Шаг 4. Зафиксируй

В STATE — раздел «Функции» (таблица: № по порядку, функция, детали,
статус: запланирована/реализована/проверена). Покажи пользователю,
подтверди.

Обнови STATE → в марафоне переходи к `phases/03-design.md`; при точечном
входе — остановись.
