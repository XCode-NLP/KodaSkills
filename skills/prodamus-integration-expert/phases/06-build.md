# Фаза 6 — Build (разработка)

Цель: реализовать интеграцию по плану, на стеке пользователя, с тестами.

## Дисциплина

- Иди по `.prodamus/PLAN.md`, отмечай чекбоксы; по мере готовности
  функций обновляй их статус в STATE (раздел «Функции»).
- TDD-цикл на каждый шаг: падающий тест → УВИДЕТЬ падение → минимальный
  код до зелёного → прогон всех тестов → коммит. Полная дисциплина и ответы
  на рационализации — `references/dev-practices.md` §3. В чат-режиме (без
  терминала) выдавай тест и код парой с командой запуска и ожидаемым
  выводом, проси пользователя подтверждать падение/прохождение.
- Внешние HTTP-вызовы в тестах — только моки/фейки, реальных запросов нет.
- Коммиты частые и атомарные (шаг плана = коммит).

## Порядок и контрольные точки

### 1. HMAC-модуль

Возьми алгоритм и референсный код своего языка из `references/hmac.md`.
Тесты: оба тест-вектора + негативный (чужой секрет → verify false).
Пока вектора не сходятся — дальше не идти (раздел «Типичные причины
расхождения» там же).

### 2. Генерация ссылки

По режиму из спеки (`references/payform-protocol.md`):

- do=link: серверный GET, тело ответа — URL; сохранить в mapping.
- do=pay: собрать payload, подписать полем `signature`, RFC3986-кодирование.
- Виджет: по живой документации (`references/help-prodamus-map.md`).

Всегда: `demo_mode=1` до боевого запуска; деньги — строки; `urlNotification`
указывает на webhook-эндпоинт из шага 3; сквозные `_param_*` — если нужна
маршрутизация в webhook.

### 3. Приём webhook об оплате

Контракт — `references/payform-protocol.md` (раздел Webhook). Обязательно:

- проверка подписи из заголовка `Sign` в точке входа;
- маппинг по `order_num` (не по `order_id` webhook'а!);
- запись в журнал обмена на каждом шаге;
- неизвестный `payment_status` → ответ OK, статус «skipped»;
- ответ `200 {"message":"OK"}` / ошибка → 400 (Prodamus ретраит).

### 4. Отражение оплаты

Идемпотентно (`references/architecture-patterns.md`): статус уже «оплачен» →
ранний выход; побочные действия — только на первом переходе.

### 5. UX подтверждения

Если по спеке покупатель возвращается в браузере — страница ожидания
с опросом статуса; «оплачено» показываем только после webhook.

## Постоянно сверяйся

- `references/security-checklist.md` — при каждом шаге, где есть секреты,
  подписи или публичные эндпоинты.
- Не изобретай параметры протокола — только справочники и живая
  документация.

Все шаги плана выполнены → обнови STATE → переходи к `phases/07-verify.md`.
