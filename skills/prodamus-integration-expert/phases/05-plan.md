# Фаза 5 — Plan (план работ)

Цель: превратить спеку в пошаговый план, где каждый шаг проверяем.

Дисциплина плана — `references/dev-practices.md` §2 (шаги 2–5 минут,
запрещённые плейсхолдеры, самопроверка).

## Правила плана

- Шаги маленькие: один шаг — одно действие с ясным критерием «сделано»
  (тест проходит, команда выводит ожидаемое, файл создан).
- Порядок реализации фиксированный (обоснование — меньше всего риска
  расхождения подписи, ядро проверяется первым):
  1. Модуль подписи HMAC + тесты на векторах из `references/hmac.md`.
  2. Генерация платёжной ссылки (do=link / do=pay / виджет — по спеке).
  3. Приём webhook об оплате с проверкой подписи.
  4. Отражение оплаты в системе пользователя (+ идемпотентность).
  5. Страница ожидания / UX подтверждения (если по спеке нужна).
  6. Остальные выбранные функции — по порядку приоритета из STATE
     (раздел «Функции», фаза 2).
- Для каждого шага укажи: какие файлы создаются/меняются, как проверить,
  что коммитить.
- Тесты пишутся вместе с кодом шага, не «потом» (TDD: сначала падающий
  тест, затем код до зелёного).
- DRY и YAGNI: ничего «на вырост», только то, что есть в спеке.

## Результат

План с чекбоксами сохрани в `.prodamus/PLAN.md` (в чат-режиме — блоком).
Покажи пользователю, согласуй. В ходе Build отмечай выполненные шаги —
это часть трекинга состояния.

Обнови STATE → переходи к `phases/06-build.md`.
