# Фаза 7 — Verify (проверка готовности)

Цель: доказать, что интеграция готова. Вердикт «готов» — только с
доказательствами: вывод тестов, журнал webhook, скриншоты. Не со слов.
Порядок «команда → вывод → только потом заявление» и таблица «заявление →
доказательство» — `references/dev-practices.md` §4.

Нужны реквизиты из фазы 4 (sys, тестовый payform, secret_key в env).
Их нет — фаза блокирована, напомни пользователю про ответ поддержки.

## Чек-лист (каждый пункт — с доказательством)

- [ ] HMAC: тест-вектора из `references/hmac.md` проходят, негативный тест
      проходит (вывод тестов).
- [ ] Подпись входящего webhook Prodamus проверяется в точке входа;
      запрос с неверной подписью отклоняется (тест или ручной запрос).
- [ ] Подпись/аутентификация webhook платформы проверяется (если есть).
- [ ] Идемпотентность: повторный webhook об оплате не дублирует эффекты
      (тест: два одинаковых запроса → один результат).
- [ ] Идемпотентность ссылок: неизменённый документ не пересоздаёт ссылку.
- [ ] Оплата подтверждается только по webhook (в коде нет пути «оплачено»
      от urlSuccess).
- [ ] 54-ФЗ: номенклатура уходит по решению из спеки (name/price/quantity
      + tax/payment_object/payment_method, если решено).
- [ ] Секреты: в репозитории нет боевых значений; в БД — шифрованно;
      в логах/журнале не появляются (grep по журналу тестового прогона).
- [ ] Неизвестный payment_status → ответ OK, запись «skipped».
- [ ] Ответы webhook: принят → 200 {"message":"OK"}, ошибка → 400.
- [ ] Каждая выбранная функция (STATE, раздел «Функции») реализована и
      проверена — тест или прогон на функцию.
- [ ] Captured-фикстура: реальный webhook (сырое тело + заголовок Sign)
      из сквозного прогона снят и закреплён регрессионным тестом
      (см. `references/hmac.md`).

## Ручная проверка webhook (пример)

Сымитируй webhook Prodamus локально: возьми пример payload из
`references/payform-protocol.md`, подпиши его секретом через свой
HMAC-модуль, отправь POST form-urlencoded с заголовком `Sign` на свой
эндпоинт. Проверь: 200, запись в журнале, статус документа изменился.
Отправь повторно — эффект не задвоился. Испорти подпись — 4xx и запись
«rejected» в журнале.

В чат-режиме (нет терминала у ассистента): подготовь пользователю готовый
скрипт или команду curl с уже подписанным payload и попроси прислать
вывод — по нему и делай выводы.

## Сквозной прогон в demo_mode

1. Создай оплату в тестовом режиме (`demo_mode=1`) на реальном тестовом
   payform из фазы 4.
2. Пройди оплату как покупатель.
3. Проверь: webhook пришёл, подпись прошла, статус в системе пользователя
   обновился, журнал полный (received → processed).
4. Если есть страница ожидания — проверь её поведение до/после webhook.

Как тестировать — см. также живую документацию, раздел «Тестирование
интеграции» (`references/help-prodamus-map.md`).

## Вердикт

Собери доказательства по каждому пункту в `.prodamus/STATE.md` (раздел
Verify). Всё зелёное → вердикт «готов», переходи к `phases/08-launch.md`.
Есть красное → вернись в `phases/06-build.md`, почини, повтори проверку.
