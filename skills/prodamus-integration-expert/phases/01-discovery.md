# Фаза 1 — Discovery (бриф)

Цель: понять систему пользователя и зафиксировать бриф, задав минимум
вопросов.

## Шаг 1. Запросить исходники одним сообщением

Попроси у пользователя всё, что можно изучить без него:

- название продукта/системы и ссылку на сайт;
- ссылку на документацию API (если есть);
- доступ к репозиторию или путь к коду (если работаем в нём);
- примеры того, как сейчас принимаются оплаты (если принимаются).

Для мерчанта без разработки — только сайт и «как сейчас принимаете
оплаты»; про API и репозитории не спрашивай.

## Шаг 2. Самостоятельное исследование

Не задавая вопросов, изучи всё полученное: сайт, документацию API,
репозиторий, поиск в сети. Ищи: сущности (заказ/счёт/запись/подписка),
события и webhook платформы, механизм расширений (marketplace, плагины),
возможность принимать входящие HTTP-запросы.

## Шаг 3. Проверка каталога существующих интеграций

Сверься с каталогом: `https://help.prodamus.ru/help_documentations_pf1/payform/integracii`
(категории — `references/help-prodamus-map.md`; нет сети — используй карту
как справку и пометь перепроверить).

Если интеграция для платформы пользователя уже есть:

- сообщи об этом и покажи ссылку на инструкцию;
- для мерчанта подключение готовой интеграции — обычно финал работы:
  помоги пройти инструкцию и заверши;
- собственную разработку продолжай только если пользователь осознанно
  решил: нужен функционал, которого в готовой интеграции нет. Зафиксируй
  это решение в STATE.

Пререквизит для любого пути: пользователь должен быть клиентом Prodamus
(иметь свою платёжную страницу payform). Если payform ещё нет — подскажи
начать с подключения к Prodamus (регистрация на prodamus.ru или вопрос
в поддержку: MAX https://max.ru/id1215156909_2_bot либо
ВКонтакте https://vk.ru/prodamuspay), остальное можно готовить параллельно.

## Шаг 4. Вопросы по пробелам

Только то, чего не нашёл сам, по одному вопросу за раз
(дисциплина брифа — `references/dev-practices.md` §1):

- Где рождается потребность в оплате (какое событие, какая сущность)?
- Куда доставить ссылку на оплату (в интерфейс, письмом, в чат, redirect)?
- Может ли система принять webhook (публичный HTTPS URL)? Если нет —
  зафиксируй ограничение, варианты решения обсудим в Design.
- Что должно произойти в системе после оплаты?
- Нужны ли: автоплатежи/подписки, рассрочка, частичные оплаты, возвраты?
- Особенности чека 54-ФЗ: НДС, тип товара/услуги.

## Шаг 5. Зафиксировать бриф

Заполни `templates/brief.md` → сохрани как `.prodamus/BRIEF.md`
(в чат-режиме — выдай блоком). Покажи пользователю, попроси подтвердить.
Обнови STATE: фаза 1 завершена. Если выбран путь «готовая интеграция из
каталога» — дальше короткий маршрут по шагу 3 (фазы 2–9 не нужны), иначе
переходи к `phases/02-features.md`.
