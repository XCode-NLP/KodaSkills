# Фаза 8 — Launch (боевой запуск)

Цель: перевести интеграцию с тестового режима на боевой без сюрпризов.

## Чек-лист перед переключением

- [ ] Фаза 7 завершена с вердиктом «готов» (см. STATE).
- [ ] Боевые реквизиты (payform, secret_key) получены и лежат в
      env/секрет-хранилище (не в коде, не в STATE).
- [ ] `demo_mode` выключен в боевой конфигурации.
- [ ] `urlNotification` — публичный HTTPS боевого окружения.
- [ ] Журнал обмена пишется и доступен для разбора инцидентов.
- [ ] План отката: как быстро отключить интеграцию (фича-флаг, деактивация
      тенанта, отключение плагина), не ломая систему пользователя.

## Smoke-тест в бою

1. Проведи одну реальную оплату минимальной суммой (согласуй с
   пользователем).
2. Проверь всю цепочку: ссылка → оплата → webhook (подпись прошла) →
   статус в системе → чек покупателю.
3. Зафиксируй результат в STATE (номер заказа, ссылки на записи журнала).

Если smoke не прошёл — откат по плану, разбор по журналу обмена
(`references/architecture-patterns.md`, раздел «Журнал обмена»), возврат
в фазу 6.

## После запуска

- Договоритесь, кто смотрит журнал первые дни.
- Типовой инцидент «оплата прошла, заказ не закрылся» разбирается
  систематически (причина до фикса!): порядок — `references/dev-practices.md`
  §5, данные — журнал обмена (пришёл ли webhook, прошла ли подпись, на чём
  упала обработка).

Обнови STATE → если нужна публикация в каталоге (см. онбординг) —
переходи к `phases/09-catalog.md`, иначе интеграция завершена:
поздравь пользователя и предложи передать наработки в каталог позже.
