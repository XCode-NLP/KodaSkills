# Ограничения безопасности при работе с плагином

Используй этот файл при исправлении безопасности и при работе с любым вводом и
выводом.

## Nonce и права

- nonce помогают против CSRF, но не дают авторизации;
- всегда сочетай nonce с проверкой прав (`current_user_can()` или более
  конкретной возможности).

Источник:

- https://developer.wordpress.org/apis/security/nonces/

## Очистка и экранирование

Золотое правило:

- очищай и проверяй на входе, экранируй на выходе.

Практические правила:

- никогда не обрабатывай весь массив `$_POST` или `$_GET`; читай конкретные ключи;
- при необходимости применяй `wp_unslash()` перед очисткой;
- для SQL используй подготовленные выражения; не подставляй пользовательский ввод
  в запросы.

## Контексты экранирования при выводе

Экранируй при выводе функцией, подходящей контексту:

- текст HTML: `esc_html()`;
- атрибут HTML: `esc_attr()`;
- адрес: `esc_url()`;
- textarea: `esc_textarea()`;
- строки JavaScript: `esc_js()`.

Для данных JSON предпочитай `wp_json_encode()` и передавай данные через API
скриптов WordPress, например `wp_add_inline_script()` или `wp_localize_script()`.

Для HTML, предоставленного пользователем, ограничь допустимую разметку через
`wp_kses_post()` или `wp_kses()` перед выводом.

## Обработчики AJAX

- для `wp_ajax_*` проверяй nonce и права;
- для `wp_ajax_nopriv_*` считай трафик неаутентифицированным и подконтрольным
  злоумышленнику;
- возвращай JSON через `wp_send_json_success()` или `wp_send_json_error()`;
- не раскрывай приватные данные в ответах AJAX.

Общие рекомендации при проверке:

- https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/
