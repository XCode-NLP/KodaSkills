# Справочник по API: измерения и метрики

## Эндпоинты

| Эндпоинт | Описание |
|----------|-------------|
| `/stat/v1/data` | Табличный отчёт |
| `/stat/v1/data/bytime` | Отчёт по времени (используется с `group`) |
| `/stat/v1/data/drilldown` | Иерархическая детализация |
| `/stat/v1/data/comparison` | Сравнение сегментов |

Добавьте `.csv` для формата CSV: `/stat/v1/data.csv`

## Метрики визитов (префикс: ym:s:)

| Метрика | Описание |
|--------|-------------|
| `ym:s:visits` | Всего визитов |
| `ym:s:users` | Уникальные посетители |

| `ym:s:crossDeviceUsers` | Уникальные посетители по кросс-девайсам |

## Метрики просмотров (префикс: ym:pv:)

ВАЖНО: метрики и измерения `ym:pv:` нельзя смешивать с `ym:s:` в одном запросе.

| Метрика или измерение | Описание |
|---------------------|-------------|
| `ym:pv:pageviews` | Просмотры страниц |
| `ym:pv:users` | Уникальные посетители |
| `ym:pv:URLPathLevel1` | Уровень пути URL 1, обычно только домен |
| `ym:pv:URLPathLevel2..N` | Более глубокие уровни пути URL |

## Метрики расходов на рекламу (префикс: ym:ad:)

## Общие параметры

| Параметр | Описание | Значение по умолчанию |
|-----------|-------------|---------|
| `ids` | Идентификатор счётчика или нескольких через запятую | обязателен |
| `date1` | Начальная дата в формате ГГГГ-ММ-ДД | обязателен |
| `date2` | Конечная дата в формате ГГГГ-ММ-ДД | сегодня |
| `metrics` | Метрики через запятую | обязателен |
| `dimensions` | Измерения через запятую | нет |
| `filters` | Выражение фильтра | нет |
| `accuracy` | От 0 до 1, где 1 означает без сэмплирования | 0.5 |
| `group` | day, week или month, только для bytime | нет |
| `limit` | Максимум строк | 100 |
| `offset` | Смещение строк для пагинации | 1 |
| `sort` | Поле сортировки, префикс `-` для убывания | нет |

## Синтаксис фильтров

```
ym:s:isRobot=='No'
ym:s:deviceCategory=='desktop'
ym:s:lastsignTrafficSource=='organic'
ym:s:regionCountry=='Россия' AND ym:s:deviceCategory=='mobile'
```

Операторы: `==`, `!=`, `=@` (содержит), `!@` (не содержит), `=~` (регулярное выражение), `!~` (не соответствует регулярному выражению).
Объединяйте через `AND` и `OR`.

## Известные ограничения API

- **Детализация не поддерживает CSV**: запрос `/stat/v1/data/drilldown.csv`, то есть вариант `.csv` для эндпоинта детализации, возвращает HTTP 406 «Unsupported format», проверено тестом. Используйте `/stat/v1/data/drilldown` в JSON через `metrika_get`.
- **Ограничение числа метрик**: не более 20 метрик на запрос. `conversions.sh` запрашивает по шесть целей на пакет, это 18 метрик, плюс до двух вспомогательных, а затем объединяет пакеты CSV.
- **Ограничение источников в bytime**: `/stat/v1/data/bytime` по умолчанию выбирает 7 значений измерения; `top_keys` позволяет до 30. `conversions.sh` по умолчанию использует 30 и одинаковую сортировку источников для каждого пакета. Остальные скрипты отчётов используют значение API по умолчанию, если не задают `top_keys` явно.
- **searchPhrase и startURL вместе дают пустой результат**: сочетание измерений `lastsignSearchPhrase` и `startURL` возвращает 0 строк. Запрашивайте их отдельно и сопоставляйте.
- **Уровни пути URL**: `startURLPathLevel1` возвращает только домен. Более глубокие уровни требуют детализации, а она не поддерживает CSV. Для анализа разделов используйте `startURL` с фильтром `=@`.
- **Области просмотров и визитов**: нельзя смешивать префиксы `ym:pv:` и `ym:s:` в одном запросе.
- **Область расходов на рекламу**: `ym:ad:*` — отдельная область, требующая `direct_client_logins`. Её нельзя смешивать с `ym:s:` и `ym:pv:` в одном запросе. Логины получайте через `/management/v1/clients?counters=<id>`.
- **Поисковые запросы**: Яндекс скрывает около 70 процентов реальных поисковых фраз. Через API доступно только около 30 процентов.
