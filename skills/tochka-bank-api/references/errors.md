# API Точка Банка — ошибка и как её исправить

Точная строка ошибки, причина и исправление. Если твоей ошибки в списке нет, иди по порядку:

1. Живой ReDoc https://enter.tochka.com/doc/v2/redoc (источник истины по формам).
2. Документация для разработчиков https://developers.tochka.com/docs/tochka-api/.
3. Поддержка в Telegram (ссылка есть на портале разработчиков) — Точка отвечает быстро; их документация иногда отстаёт от API.

| Точная ошибка или симптом | Причина | Исправление |
|---|---|---|
| HTTP 501 на `/invoice/...`, `/open-banking/.../statements`, `/closing-documents` | Личный JWT не достаёт до этого уровня | Переходи на OAuth (`init --oauth`) |
| HTTP 401 на OAuth-эндпоинтах после паузы | `refresh_token` истёк (окно 30 дней) | Запусти `init --oauth` заново — тихого восстановления после смерти refresh-токена нет |
| HTTP 403 со свежим токеном | Не хватает области прав или согласие истекло | `list-consents` / `get-consent --consent-id …` покажет выданные области; `init --oauth`, если согласие истекло |
| HTTP 403 со старым токеном | Истёк TTL JWT | Перегенерируй JWT в интернет-банке → Интеграции и API → новый ключ → снова `init` |
| `404 Not found statement under account` | Незакодированный `/` в пути `accountId` | Кодируй как `%2F` (в телах запросов оставляй слэш как есть) |
| `"Datetimes provided to dates should have zero time"` | В поле даты выписки полный ISO с временем | Передавай только `YYYY-MM-DD` |
| `"should be less than today or equal"` на платеже | `paymentDate` в будущем | Сегодня или раньше; для отложенной отправки создай черновик, чтобы человек подписал его в нужную дату |
| `"forbidden symbols: —"` в `paymentPurpose` | Длинное тире U+2014 в строке | Замени дефисом `-` или запятой |
| `Field …-Positions-0-unitCode : Input should be 'шт.', …` в счёте или закрывающем документе | `unitCode` вне закрытого белого списка (например, `мес.`, `год.`, код ОКЕИ, нет точки на конце) | Выбери из белого списка — для подписок используй `услуга.` или `шт.`, а период укажи в названии позиции. `tochka_client.py` проверяет это на стороне клиента через `choices` в argparse. |
| ЭДО не подписывает закрывающий документ: `"Не получилось подписать документ. Проверьте ИНН или КПП контрагента."` | `cmd_create_closing_doc` вызван с формой счёта v2.0 (`KPP` / `legalName`); Точка молча отбрасывает её для закрывающих документов → в PDF у покупателя нет КПП | В закрывающем документе `SecondSide` требует строчных `kpp` и `secondSideName`. Пересоздай с формой v1.0; хелпер делает это правильно с 21.04.2026. |
| `"Проверьте номер счёта — в выбранном банке такого счёта нет"` | Несуществующий счёт контрагента или опечатка | Счёт контрагента проверяется по реестру Банка России — используй настоящие номера |
| `"Field X: Field required"` по каждому полю платежа | Вложенная `Data.Payment` вместо плоской `Data.{…}` | Разверни тело — схема v2.0 плоская, без массива и вложенности |
| Счёт создан, но в ответе нет `documentUid` | Смотришь не в то поле | Используй `Data.documentId` (псевдоним `documentUid` удалён) |
| `error: init needs a real terminal…` или мастер зависает | Нет TTY (запуск через инструмент Bash агента) | Пользователь должен запустить с префиксом `!`: `! python3 .../tochka_client.py init` |
| Счета и платежи «проходят», но не появляются в интернет-банке | В окружении застрял `TOCHKA_SANDBOX=1`, вызовы идут в песочницу | `unset TOCHKA_SANDBOX`; проверь цель по метке в запросе хука или запусти `list-accounts` с известным продакшен-`customerCode` |
| Колбэк OAuth не приходит (таймаут 5 минут) | Зарегистрированный Redirect URL не равен умолчанию мастера | `init --oauth --redirect-url <точный URL из интернет-банка>` |
| OAuth: браузер показывает предупреждение о сертификате при авторизации | `mkcert` не установлен, используется самоподписанный | `brew install mkcert && mkcert -install`, затем снова `init --oauth` (либо один раз подтверди предупреждение) |
| `OSError: [Errno 48] Address already in use` при `init --oauth` | Порт 8443 занят прошлым запуском мастера | `lsof -i :8443` → заверши процесс либо передай `--redirect-url https://127.0.0.1:<другой-порт>/callback` (должен совпадать с регистрацией в интернет-банке) |
| `security: SecKeychainSearchCopyNext` или Keychain отказал | Доступ к Keychain в macOS запрещён или он заблокирован | Разблокируй Keychain и повтори; либо `init --storage file`, чтобы перейти на файл с chmod 600 |
| Скачивание PDF висит или падает по таймауту | Первый рендер на сервере занимает около 30 с | Клиент уже использует таймаут 90 с — если всё равно не выходит, повтори один раз |
| Платёж подписан, но его больше нет в `list-for-sign` | После подписания и отправки платёж уходит из очереди «На подпись» | Смотри исполненные платежи через `list-statement` (OAuth) |
