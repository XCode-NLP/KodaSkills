# Краткое руководство по регистрации в PHP

Ключевые понятия и точки входа WordPress Abilities API:

- регистрируй категории возможностей и сами возможности в PHP;
- используй хуки инициализации Abilities API, чтобы регистрация происходила на нужном
  этапе жизненного цикла.

## Порядок хуков (критично)

**Категории должны быть зарегистрированы до возможностей.** Используй правильные хуки:

1. `wp_abilities_api_categories_init` — здесь сначала регистрируй категории.
2. `wp_abilities_api_init` — здесь регистрируй возможности (после того как категории
   существуют).

**Предупреждение:** регистрация возможностей вне `wp_abilities_api_init` вызывает
`_doing_it_wrong()`, и регистрация завершается неудачей.

```php
// 1. Сначала регистрируем категорию
add_action( 'wp_abilities_api_categories_init', function() {
    wp_register_ability_category( 'my-plugin', [
        'label' => __( 'My Plugin', 'my-plugin' ),
    ] );
} );

// 2. Затем регистрируем возможности
add_action( 'wp_abilities_api_init', function() {
    wp_register_ability( 'my-plugin/get-info', [
        'label'               => __( 'Get Site Info', 'my-plugin' ),
        'description'         => __( 'Returns basic site information.', 'my-plugin' ),
        'category'            => 'my-plugin',
        'execute_callback'    => 'my_plugin_get_info_callback',
        'permission_callback' => 'my_plugin_get_info_permissions',
        'meta'                => [
            'show_in_rest' => true,
            'mcp'          => [
                'public' => true, // Публикация через встроенный адаптер WordPress MCP.
            ],
            'annotations'  => [
                'readonly'    => true,
                'destructive' => false,
                'idempotent'  => true,
            ],
        ],
    ] );
} );
```

## Основные функции

- `wp_register_ability_category( $category_id, $args )`
- `wp_register_ability( $ability_id, $args )`

## Ключевые аргументы `wp_register_ability()`

| Аргумент | Обязателен? | Описание |
|----------|-----------|-------------|
| `label` | **Обязателен** | Понятное человеку имя для интерфейса (например, палитры команд). |
| `description` | **Обязателен** | Что делает возможность. |
| `category` | **Обязателен** | Идентификатор категории (её нужно зарегистрировать раньше через `wp_abilities_api_categories_init`). |
| `execute_callback` | **Обязателен** | Функция, которая выполняется при вызове возможности. Получает ввод согласно `input_schema`, возвращает результат или `WP_Error`. |
| `permission_callback` | **Обязателен** | Функция, проверяющая, может ли текущий пользователь выполнить возможность. Получает тот же ввод, что и `execute_callback`; возвращает `bool` или `WP_Error`. Ядро WP выбрасывает `InvalidArgumentException`, если её нет, — неявного значения по умолчанию не существует. |
| `input_schema` | Необязателен | JSON-схема ожидаемого ввода (включает проверку). Обязательна, когда возможность принимает ввод. |
| `output_schema` | Необязателен | JSON-схема возвращаемого результата (включает проверку результата). |
| `meta.show_in_rest` | Необязателен (по умолчанию `false`) | Поставь `true`, чтобы опубликовать возможность в пространстве имён REST `wp-abilities/v1`. |
| `meta.mcp.public` | Необязателен (по умолчанию `false`) | Поставь `true`, чтобы опубликовать возможность как инструмент через встроенный адаптер WordPress MCP. Не зависит от `show_in_rest`. |
| `meta.mcp.type` | Необязателен (по умолчанию `'tool'`) | Одно из `'tool'`, `'resource'`, `'prompt'`. Управляет тем, как встроенный адаптер MCP проецирует возможность. Значения вне этого перечисления молча приводятся к `'tool'`. |
| `meta.annotations.readonly` | **Настоятельно рекомендуется** (по умолчанию `null`) | `true`, если возможность не меняет своё окружение. |
| `meta.annotations.destructive` | **Настоятельно рекомендуется** (по умолчанию `null`) | `true`, если возможность может выполнять разрушительные обновления. `false` для обновлений, которые только добавляют данные. |
| `meta.annotations.idempotent` | **Настоятельно рекомендуется** (по умолчанию `null`) | `true`, если повторный вызов с теми же аргументами не даёт дополнительного эффекта. |

Три аннотации в `meta.annotations` — это *подсказки* для инструментов и документации:
ядро не проверяет их во время выполнения, поэтому отсутствующее или `null`-значение
формально допустимо. Именно из-за этой снисходительности каждая регистрация должна
заполнять их явно: поверхности MCP, палитры команд и агентов, а также инструменты ревью
судят о безопасности возможности по этим значениям, *не* вызывая колбэк. Возможность с
`readonly: null` считается «поведение неизвестно», а это худший сигнал, чем `true` или
`false`. Считай отсутствие аннотации ошибкой, а не умолчанием.

### `show_in_rest` и `mcp.public` — они нацелены на разные поверхности

Эти два ключа метаданных отвечают на разные вопросы и не подразумевают друг друга:

- `show_in_rest` управляет видимостью в пространстве имён REST ядра WordPress
  `wp-abilities/v1` (REST API возможностей). Клиенты, работающие с этим пространством,
  видят возможность тогда и только тогда, когда значение `true`.
- `mcp.public` читает встроенный пакет адаптера WordPress MCP. Сервер MCP этого
  адаптера по умолчанию показывает только возможности, у которых `meta.mcp.public`
  строго `true`. Без этого возможность зарегистрирована, но невидима клиентам MCP,
  подключающимся через адаптер.

Плагин может задать оба ключа, любой один или ни одного. Если нужно, чтобы агенты
находили возможность через MCP, ставь `mcp.public => true`. Если она также нужна в
пространстве имён REST возможностей (для инструментов, работающих с `wp-abilities/v1`
напрямую), ставь `show_in_rest => true`. Эти поверхности независимы.

## Рекомендуемые шаблоны

- Задавай идентификаторы возможностей в виде `<plugin-slug>/<verb-noun>` (например,
  `my-plugin/get-info`, `my-plugin/update-thing`). Через косую черту.
- Считай идентификаторы стабильным API: изменение идентификатора ломает любого
  потребителя, который на него ссылается.
- Используй `input_schema` и `output_schema` для проверки и чтобы помочь ИИ-агентам
  понять использование.
- **Всегда указывай `permission_callback`.** Он обязателен при каждой регистрации —
  неявного значения по умолчанию нет.
- **Всегда задавай все три ключа `meta.annotations` (`readonly`, `destructive`,
  `idempotent`) явно.** Оставляя их на `null` по умолчанию, ты сообщаешь «поведение
  неизвестно» каждому потребителю, который читает эти метаданные перед вызовом
  возможности. Цена их записи — три строки, цена их отсутствия — непрозрачная
  поверхность безопасности.
