# Защита от отравленных сообщений и очередь недоставленных

## 1. Осторожно: бесконечный цикл из-за отравленного сообщения

```python
# Смертельная ошибка: при любом исключении бездумно requeue=True
except Exception:
    channel.basic_nack(delivery_tag, requeue=True)
```

Если сообщение содержит неисправимые грязные данные (отравленное), бизнес-код на нём падает всегда. После отказа сообщение сразу возвращается в начало очереди, снова отправляется, снова падает: процессор загружен на 100%, а логи пишут десятки тысяч строк в секунду.

---

## 2. Стандартная схема лечения: очередь недоставленных

1. **Ограничение числа попыток** — через счётчик в Redis или заголовок `x-death`, не больше трёх попыток.
2. **Отказ с отправкой в очередь недоставленных** — после превышения лимита явно вызывай:
   ```python
   # Отказ без возврата в исходную очередь: сообщение уходит в обменник недоставленных
   channel.basic_nack(delivery_tag=tag, requeue=False)
   ```
3. **Объявление обменника недоставленных** — у очереди задаются `x-dead-letter-exchange` и `x-dead-letter-routing-key`, недоставленные сообщения попадают в отдельную очередь, где их разбирает человек.
