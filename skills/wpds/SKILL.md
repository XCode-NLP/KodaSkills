# Дизайн-система WordPress (WPDS)

## Требования

Этот навык лучше всего работает с установленным **MCP-сервером WPDS**. MCP даёт
доступ к документации и ресурсам дизайн-системы WordPress: компонентам, спискам
токенов и т.п.

Следующие термины считаются синонимами:

- «WordPress» и «WP»;
- «дизайн-система» и «DS»;
- «дизайн-система WordPress» и «WPDS».

## Когда использовать

Используй этот навык, когда пользователь упоминает:

- создание и/или проверку любого интерфейса в контексте WordPress (например,
  Gutenberg, WooCommerce, WordPress.com, Jetpack и т.п.);
- дизайн-систему WordPress, WPDS, дизайн-систему;
- компоненты интерфейса, дизайн-токены, цветовые примитивы, шкалы отступов,
  переменные и пресеты типографики;
- конкретные пакеты компонентов, например `@wordpress/components` или `@wordpress/ui`.

## Правила

### Бери документацию по WPDS из MCP-сервера

- Используй MCP-сервер WPDS, чтобы получить каноническую, авторитетную
  документацию:
  - справочный сайт (`wpds://pages`);
  - список доступных компонентов (`wpds://components`) и сведения о конкретном
    компоненте (`wpds://components/:name`);
  - список доступных токенов (`wpds://design-tokens`).
- НЕ ищи в интернете каноническую документацию по дизайн-системе WordPress. Если
  пользователь просит об этом, возрази и попроси подтверждения, предупредив, что
  MCP-сервер — лучшее место для таких сведений.

### Обязательная документация

Перед любой задачей, связанной с WPDS, прочитай соответствующую документацию на
справочном сайте. При выборе лучшего решения для задачи эта документация имеет
абсолютный приоритет.

### Границы

- Пропускай аспекты ответа, не связанные с интерфейсом (например, получение данных
  из хранилищ или локализацию строк).
- Сосредоточься на интерфейсе, который максимально следует лучшим практикам WPDS и
  использует наиболее подходящие компоненты, токены и паттерны WPDS.

### Технологический стек

- Если не сказано иное и в локальном контексте запроса нет конкретных сведений,
  считай стек таким: TypeScript, React, CSS.

### Проверка

- Если в локальном контексте задачи есть скрипты линтера, используй их для проверки
  предложенного кода, когда это возможно.

## Вывод

- В конце ответа кратко и понятно объясни, что делает решение, и добавь контекст,
  почему принято каждое решение.
- Явно обозначь границы: что намеренно осталось за рамками задачи как нерелевантное
  (например, всё, что не связано с интерфейсом).
- Приводи работающие фрагменты кода.
