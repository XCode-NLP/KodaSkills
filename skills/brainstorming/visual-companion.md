# Руководство по визуальному компаньону

Браузерный компаньон для визуального мозгового штурма: показывает макеты, схемы и варианты.

## Когда использовать

Решай по каждому вопросу, а не по сессии целиком. Проверка: **понял бы пользователь это лучше,
увидев, чем прочитав?**

**Используй браузер**, когда само содержимое визуально:

- **макеты интерфейса** — каркасы, раскладки, структуры навигации, дизайн компонентов;
- **схемы архитектуры** — компоненты системы, поток данных, карты связей;
- **визуальные сравнения рядом** — сравнение двух раскладок, двух цветовых схем, двух направлений
  дизайна;
- **доводка дизайна** — когда вопрос о внешнем виде и ощущении, отступах, визуальной иерархии;
- **пространственные связи** — конечные автоматы, блок-схемы, связи сущностей в виде схем.

**Используй терминал**, когда содержимое текстовое или табличное:

- **вопросы о требованиях и объёме** — «что значит X?», «какие функции входят в объём?»;
- **концептуальный выбор A/B/C** — выбор между подходами, описанными словами;
- **списки компромиссов** — плюсы и минусы, таблицы сравнения;
- **технические решения** — дизайн API, моделирование данных, выбор архитектурного подхода;
- **уточняющие вопросы** — всё, где ответ словами, а не визуальным предпочтением.

Вопрос *о* теме интерфейса не становится визуальным автоматически. «Какой мастер вы хотите?» —
концептуально, используй терминал. «Какая из этих раскладок мастера ощущается правильной?» —
визуально, используй браузер.

## Как это работает

Сервер следит за директорией HTML-файлов и отдаёт браузеру самый новый. Ты пишешь HTML в
`screen_dir`, пользователь видит его в браузере и может кликать для выбора вариантов. Выборы
записываются в `state_dir/events`, которые ты читаешь на следующем ходе.

**Фрагменты содержимого и полные документы:** если твой HTML-файл начинается с `<!DOCTYPE` или
`<html`, сервер отдаёт его как есть (только подставляет вспомогательный скрипт). Иначе сервер сам
оборачивает содержимое в шаблон рамки — добавляет заголовок, тему CSS, состояние подключения и всю
интерактивную инфраструктуру. **По умолчанию пиши фрагменты содержимого.** Пиши полные документы,
только когда нужен полный контроль над страницей.

## Начало сессии

```bash
# Запускай ПОСЛЕ того, как пользователь одобрил компаньона. --open сам открывает его
# браузер на первом экране; --project-dir сохраняет макеты и позволяет перезапуск
# на том же порту.
bash scripts/start-server.sh --project-dir /path/to/project --open

# Возвращает: {"type":"server-started","port":52341,
#           "url":"http://localhost:52341/?key=ab12…",
#           "screen_dir":"/path/to/project/.superpowers/brainstorm/12345-1706000000/content",
#           "state_dir":"/path/to/project/.superpowers/brainstorm/12345-1706000000/state"}
```

Сохрани `screen_dir` и `state_dir` из ответа. С `--open` браузер откроется сам, когда ты
отправишь первый экран: просить пользователя открыть его не нужно, но URL всё равно сообщи как
запасной вариант (в headless- и удалённых конфигурациях автозапуск не сработает).

**URL содержит ключ сессии (`?key=…`).** Сервер отклоняет любой запрос без него, поэтому всегда давай
пользователю **полный** URL из поля `url`: никогда не отбрасывай строку запроса и не выдавай голый
`http://host:port`. Ключ закрывает доступ по HTTP и WebSocket, чтобы посторонняя вкладка браузера или
другая машина в сети не могли прочитать экраны или подбросить события. После первой загрузки браузер
запоминает ключ в cookie, поэтому перезагрузки и ресурсы `/files/*` работают без его повторения.

**Как узнать параметры подключения:** сервер пишет свой стартовый JSON в `$STATE_DIR/server-info`.
Если ты запустил сервер в фоне и не перехватил stdout, прочитай этот файл, чтобы получить URL и порт.
При использовании `--project-dir` ищи директорию сессии в `<project>/.superpowers/brainstorm/`.

**Замечание:** передавай корень проекта в `--project-dir`, чтобы макеты сохранялись в
`.superpowers/brainstorm/` и переживали перезапуски сервера. Без него файлы попадают в `/tmp` и
удаляются. Напомни пользователю добавить `.superpowers/` в `.gitignore`, если этого ещё нет.

**Запуск сервера по платформам:**

**Claude Code:**

```bash
# Режим по умолчанию работает — скрипт сам уводит сервер в фон.
bash scripts/start-server.sh --project-dir /path/to/project --open
```

В Windows скрипт сам определяет ситуацию и переключается в режим переднего плана (это блокирует
вызов инструмента). Используй `run_in_background: true` в вызове инструмента Bash, чтобы сервер
пережил ходы диалога, затем на следующем ходе прочитай `$STATE_DIR/server-info`, чтобы получить URL
и порт.

**Codex:**

```bash
# Codex прибирает фоновые процессы. Скрипт сам определяет CODEX_CI и
# переключается в режим переднего плана. Запускай как обычно — лишние флаги не нужны.
bash scripts/start-server.sh --project-dir /path/to/project --open
```

**Gemini CLI:**

```bash
# Используй --foreground и поставь is_background: true в вызове инструмента оболочки,
# чтобы процесс пережил ходы диалога
bash scripts/start-server.sh --project-dir /path/to/project --open --foreground
```

**Copilot CLI:**

```bash
# Запускай через неблокирующий фоновый механизм оболочки Copilot CLI, чтобы сервер
# пережил ходы диалога. Оставь --foreground, чтобы фоновый режим держала обвязка, а не
# скрипт. Запускающий файл — .sh, поэтому вызывай его через bash (в Windows вызывай
# bash.exe из Git Bash через инструмент PowerShell).
bash scripts/start-server.sh --project-dir /path/to/project --open --foreground
```

**Другие окружения:** сервер должен продолжать работать в фоне между ходами диалога. Если твоё
окружение прибирает отсоединённые процессы, используй `--foreground` и запускай команду фоновым
механизмом своей платформы.

Если URL недоступен из твоего браузера (часто в удалённых и контейнерных конфигурациях), привяжи
хост не из loopback:

```bash
bash scripts/start-server.sh \
  --project-dir /path/to/project \
  --host 0.0.0.0 \
  --url-host localhost
```

Используй `--url-host`, чтобы задать, какое имя хоста попадёт в возвращаемый JSON с URL.

## Цикл работы

1. **Проверь, что сервер жив**, затем **запиши HTML** в новый файл в `screen_dir`:
   - **Обязательно: убедись, что сервер жив, прежде чем ссылаться на URL или отправлять экран.**
     Проверь, что `$STATE_DIR/server-info` существует, а `$STATE_DIR/server-stopped` — нет. Если
     сервер остановился, перезапусти его через `start-server.sh` с **тем же `--project-dir`**: он
     займёт тот же порт, так что открытая вкладка пользователя переподключится сама (пока сервер
     лежит, она показывает наложение «пауза»), и новый URL отправлять не нужно. Сервер сам
     завершается после 4 часов простоя (настраивается через `--idle-timeout-minutes`).
   - Используй осмысленные имена файлов: `platform.html`, `visual-style.html`, `layout.html`.
   - **Никогда не переиспользуй имена файлов** — каждый экран получает свежий файл.
   - Используй свой инструмент создания файлов — **никогда не используй cat и heredoc** (они
     выбрасывают шум в терминал).
   - Сервер сам отдаёт самый новый файл.

2. **Скажи пользователю, чего ждать, и закончи ход:**
   - напомни URL (на каждом шаге, а не только на первом);
   - дай краткое текстовое описание того, что на экране (например, «Показываю 3 варианта раскладки
     главной страницы»);
   - попроси ответить в терминале: «Посмотри и скажи, что думаешь. Если хочешь, кликни, чтобы
     выбрать вариант.»

3. **На следующем ходе** — после того как пользователь ответил в терминале:
   - прочитай `$STATE_DIR/events`, если файл существует: там взаимодействия пользователя в браузере
     (клики, выборы) в виде строк JSON;
   - соедини это с текстом пользователя в терминале, чтобы получить полную картину;
   - сообщение в терминале — основная обратная связь; `state_dir/events` даёт структурированные
     данные о взаимодействии.

4. **Повторяй или двигайся дальше** — если обратная связь меняет текущий экран, запиши новый файл
   (например, `layout-v2.html`). Переходи к следующему вопросу, только когда текущий шаг подтверждён.

5. **Разгружай экран при возврате в терминал** — когда следующий шаг не требует браузера (например,
   уточняющий вопрос или обсуждение компромиссов), отправь экран ожидания, чтобы очистить устаревшее
   содержимое:

   ```html
   <!-- filename: waiting.html (or waiting-2.html, etc.) -->
   <div style="display:flex;align-items:center;justify-content:center;min-height:60vh">
     <p class="subtitle">Continuing in terminal...</p>
   </div>
   ```

   Это не даёт пользователю смотреть на уже решённый выбор, когда разговор ушёл дальше. Когда
   появится следующий визуальный вопрос, отправь новый файл содержимого как обычно.

6. Повторяй, пока не закончишь.

## Как писать фрагменты содержимого

Пиши только то содержимое, которое идёт внутрь страницы. Сервер сам оборачивает его в шаблон рамки
(заголовок, CSS темы, состояние подключения и вся интерактивная инфраструктура).

**Минимальный пример:**

```html
<h2>Which layout works better?</h2>
<p class="subtitle">Consider readability and visual hierarchy</p>

<div class="options">
  <div class="option" data-choice="a" onclick="toggleSelect(this)">
    <div class="letter">A</div>
    <div class="content">
      <h3>Single Column</h3>
      <p>Clean, focused reading experience</p>
    </div>
  </div>
  <div class="option" data-choice="b" onclick="toggleSelect(this)">
    <div class="letter">B</div>
    <div class="content">
      <h3>Two Column</h3>
      <p>Sidebar navigation with main content</p>
    </div>
  </div>
</div>
```

И всё. Ни `<html>`, ни CSS, ни тегов `<script>` не нужно. Всё это даёт сервер.

## Доступные CSS-классы

Шаблон рамки даёт эти CSS-классы для твоего содержимого.

### Варианты (выбор A/B/C)

```html
<div class="options">
  <div class="option" data-choice="a" onclick="toggleSelect(this)">
    <div class="letter">A</div>
    <div class="content">
      <h3>Title</h3>
      <p>Description</p>
    </div>
  </div>
</div>
```

**Множественный выбор:** добавь `data-multiselect` контейнеру, чтобы пользователь мог выбрать
несколько вариантов. Каждый клик переключает оформление выбранного элемента.

```html
<div class="options" data-multiselect>
  <!-- same option markup — users can select/deselect multiple -->
</div>
```

### Карточки (визуальные дизайны)

```html
<div class="cards">
  <div class="card" data-choice="design1" onclick="toggleSelect(this)">
    <div class="card-image"><!-- mockup content --></div>
    <div class="card-body">
      <h3>Name</h3>
      <p>Description</p>
    </div>
  </div>
</div>
```

### Контейнер макета

```html
<div class="mockup">
  <div class="mockup-header">Preview: Dashboard Layout</div>
  <div class="mockup-body"><!-- your mockup HTML --></div>
</div>
```

### Разделённый вид (рядом)

```html
<div class="split">
  <div class="mockup"><!-- left --></div>
  <div class="mockup"><!-- right --></div>
</div>
```

### Плюсы и минусы

```html
<div class="pros-cons">
  <div class="pros"><h4>Pros</h4><ul><li>Benefit</li></ul></div>
  <div class="cons"><h4>Cons</h4><ul><li>Drawback</li></ul></div>
</div>
```

### Макетные элементы (кирпичики каркаса)

```html
<div class="mock-nav">Logo | Home | About | Contact</div>
<div style="display: flex;">
  <div class="mock-sidebar">Navigation</div>
  <div class="mock-content">Main content area</div>
</div>
<button class="mock-button">Action Button</button>
<input class="mock-input" placeholder="Input field">
<div class="placeholder">Placeholder area</div>
```

### Типографика и секции

- `h2` — заголовок страницы;
- `h3` — заголовок секции;
- `.subtitle` — второстепенный текст под заголовком;
- `.section` — блок содержимого с отступом снизу;
- `.label` — мелкая метка заглавными.

## Формат событий браузера

Когда пользователь кликает по вариантам в браузере, его действия записываются в `$STATE_DIR/events`
(по одному объекту JSON на строку). Файл автоматически очищается, когда ты отправляешь новый экран.

```jsonl
{"type":"click","choice":"a","text":"Option A - Simple Layout","timestamp":1706000101}
{"type":"click","choice":"c","text":"Option C - Complex Grid","timestamp":1706000108}
{"type":"click","choice":"b","text":"Option B - Hybrid","timestamp":1706000115}
```

Полный поток событий показывает путь исследования пользователя: он может кликнуть несколько
вариантов, прежде чем остановиться. Последнее событие `choice` обычно и есть окончательный выбор, но
картина кликов может выдать колебания или предпочтения, о которых стоит спросить.

Если `$STATE_DIR/events` не существует, пользователь не взаимодействовал с браузером — используй
только его текст в терминале.

## Советы по дизайну

- **Соразмеряй точность с вопросом** — каркасы для раскладки, доводку для вопросов о доводке.
- **Объясняй вопрос на каждой странице** — «Какая раскладка ощущается профессиональнее?», а не
  просто «Выбери одну».
- **Повторяй до продвижения** — если обратная связь меняет текущий экран, напиши новую версию.
- **Не больше 2–4 вариантов** на экран.
- **Используй настоящее содержимое, когда это важно** — для портфолио фотографа бери реальные
  изображения (Unsplash). Заполнитель скрывает проблемы дизайна.
- **Держи макеты простыми** — сосредоточься на раскладке и структуре, а не на попиксельном дизайне.

## Именование файлов

- используй осмысленные имена: `platform.html`, `visual-style.html`, `layout.html`;
- никогда не переиспользуй имена файлов — каждый экран должен быть новым файлом;
- для итераций добавляй суффикс версии: `layout-v2.html`, `layout-v3.html`;
- сервер отдаёт самый новый файл по времени изменения.

## Завершение работы

```bash
bash scripts/stop-server.sh $SESSION_DIR
```

Если сессия использовала `--project-dir`, файлы макетов остаются в `.superpowers/brainstorm/` для
последующего просмотра. Удаляются при остановке только сессии в `/tmp`.

## Справочник

- шаблон рамки (справочник по CSS): `scripts/frame-template.html`;
- вспомогательный скрипт (на стороне клиента): `scripts/helper.js`.
