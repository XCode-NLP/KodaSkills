# Тяжёлые данные в kaiten-cli

Этот навык нужен, когда задача пахнет массовыми чтениями, выгрузками, аудитами, миграциями, сканированием нескольких досок или повторяющимися выборками карточек и истории.

## Язык общения

Перед каждой командой, включая поиск инструментов и чтение JSON, передавай `--locale ru` для разговора на русском или `--locale en` для английского и других языков. Меняй его, когда пользователь меняет язык. Явный флаг перекрывает `KAITEN_CLI_LOCALE`; без того и другого CLI использует английский. Добавляй флаг в примеры ниже. Имена команд, ключи JSON и данные пользователей не меняй.

## Основные правила

- Начинай с поиска инструментов: `kaiten search-tools ...` и `kaiten describe ...`.
- Предпочитай один массовый вызов CLI многим одиночным процессам CLI.
- Если один и тот же набор понадобится больше одного раза, предпочитай один `snapshot build`, а затем локальные `query cards` и `query metrics`.
- Держи локальные чтения карточек в `query cards --view summary` по умолчанию; переходи к `detail` или `evidence` только после сужения набора кандидатов.
- Считай инструменты `aggregated` и `synthetic` дороже `direct_http`.
- Уменьшай размер ответа до того, как просить модель его изучать.
- Когда известно два и более идентификатора сущностей и `describe` сообщает о `bulk_alternative`, используй пакетную команду.
- Когда один и тот же набор нужен второй раз, построй снимок и запрашивай его локально.

## Чего избегать

- Не запускай `kaiten` по одной карточке, когда есть пакетный инструмент.
- Не строй цикл по `card-children list` или `comments list` для каждой карточки в исследовании.
- Не тяни полные объекты карточек для метрик или аудита, если достаточно `--fields`.
- Не повторяй одинаковые безопасные GET-чтения в разных вызовах CLI, не подумав о кэше.
- Не считай `cards.list`, что правильный массовый путь; проверяй `cards.list-all`.
- Не пересобирай тот же рабочий набор пространства или доски из API Kaiten, если на следующие вопросы ответит локальный снимок.

## Предпочтительные команды

### Повторяющиеся сценарии с преобладанием чтения

Используй:

```bash
kaiten --json snapshot build --name team-basic --space-id 10 --preset basic
kaiten --json query cards --snapshot team-basic --view summary --filter '{"board_ids":[10]}' --fields id,title,state
```

Заметки:

- Строй снимок один раз, когда отчёт, аудит или выгрузка задаст несколько последующих вопросов про один рабочий набор.
- `query cards` не вызывает API Kaiten.
- `summary` — вид карточки по умолчанию для локальных чтений; `detail` и `evidence` бери только для суженных кандидатов.
- Переходи на `query metrics`, когда последующие вопросы в основном агрегатные, а не по отдельным карточкам.
- Этот путь явный; обычные транспортные команды не переписываются молча в чтения из снимка.

### Массовая выборка карточек

Используй:

```bash
kaiten --json cards list-all --board-id 10 --selection active_only --fields id,title,state --compact
```

Заметки:

- `selection=all|active_only|archived_only` — предпочтительный массовый интерфейс.
- Добавляй `relations none` только когда действительно нужно подавить вложенные объекты на уровне API.
- `cards.list-all` падает на границе `max_pages`, а не возвращает частичный набор; увеличивай `--max-pages` только после проверки ожидаемого размера.

### Массовая история перемещений

Используй:

```bash
kaiten --json card-location-history batch-get --card-ids '[101,102,103]' --workers 2 --fields changed,column_id,subcolumn_id
```

Заметки:

- Предпочитай это повторению `card-location-history get`.
- Пакетный путь сохраняет частичные сбои по отдельным карточкам в самом ответе.
- Повторяющиеся значения `card_id` убираются до сетевого запроса.

### Массовые детали карточек и журналы работ

Используй:

```bash
kaiten --json cards batch-get --card-ids '[101,102,103]' --workers 2 --fields id,title,description
kaiten --json time-logs batch-list --card-ids '[101,102,103]' --workers 2 --fields id,time_spent,for_date
```

Заметки:

- Предпочитай `cards.batch-get` повторению `cards.get` после локального сужения.
- Предпочитай `time-logs.batch-list` повторению `time-logs.list`, когда аналитика учёта времени охватывает много карточек.
- `time-logs.batch-list` листает каждую карточку до конца; подстраивай `--page-size` и `--max-pages` только когда значения по умолчанию не подходят.

### Подтверждения по связям и комментариям

Используй:

```bash
kaiten --json card-children batch-list --card-ids '[101,102,103]' --workers 2 --compact --fields id,title
kaiten --json comments batch-list --card-ids '[101,102,103]' --workers 2 --compact --fields id,text
```

Заметки:

- Предпочитай это `card-children list` и `comments list` по каждой карточке.
- Оба пакетных пути сохраняют частичные сбои по карточкам в самом ответе.
- Оба листают каждую карточку до конца и сообщают об ошибке по карточке, а не возвращают обрезанную коллекцию на пределе защиты.

### Привязки дополнений по многим карточкам

Массового чтения данных дополнений нет: `card-addon-data get` и `github-addon ... list` работают по одной карточке и делают по одному HTTP-запросу, а `describe` не сообщает о `bulk_alternative`. Сначала сузь набор, затем читай привязки только у выживших карточек:

```bash
kaiten --json query cards --snapshot team-basic --view summary --fields id,title
kaiten --json --trace-file ./kaiten-trace.jsonl github-addon pulls list --card-id 101 --fields number,htmlUrl,state
```

Заметки:

- Цикл по карточкам здесь неизбежен, и это ровно тот случай, для которого написано правило о трассировке ниже: запиши трассировку и проверь реальное число запросов.
- Привязки дополнений не входят в сущность карточки и не хранятся в снимке; `cards list-all` и `query cards` их никогда не возвращают.
- Карточка может ссылаться на PR и через `external-links list`. Читай оба источника, когда вопрос — «все PR, на которые ссылается карточка».
- Определи UUID дополнения один раз через `space-addons list` и передавай `--addon-uid` в цикле. Без него каждая карточка стоит лишнего чтения — самой карточки. Ничего не амортизируется: чтение карточки идёт на карточку, а запись сбрасывает область кэша всего профиля.
- Карточка, у которой дополнение не определяется, валит вызов вместо возврата пустого списка, так что обрабатывай эту ошибку, а не считай её «привязок нет».

### Структура пространства

Используй:

```bash
kaiten --json space-topology get --space-id 10
```

Заметки:

- Предпочитай это скрипту, который отдельно вызывает `boards list`, `columns list` и `lanes list`.
- Используй в начале построения отчёта, чтобы зафиксировать идентификаторы досок, колонок и дорожек один раз.

## Формирование ответа

Порядок формирования по умолчанию:

1. `--fields`, чтобы оставить только нужные поля
2. `--compact`, чтобы убрать тяжёлые поля и упростить объекты пользователей
3. `--json` для машинного разбора

Пример:

```bash
kaiten --json cards get --card-id 123 --compact --fields id,title,state
```

## Кэш

Безопасные GET-чтения уже используют кэш в пределах вызова CLI, а CLI по умолчанию берёт `--cache-mode auto` для кэшируемого повторного использования между процессами.

Для тяжёлой аналитики модели или скрипта оставляй `auto`, если свежесть не критична. Пакетные и агрегированные чтения хранят куски кэша дольше, а плотные циклы по сущностям одного семейства вроде множества чтений `/cards/<id>` продлеваются после достаточного числа свежих записей.

```bash
kaiten --json card-location-history batch-get --card-ids '[101,102,103]' --workers 2 --fields changed,column_id
```

Держи все четыре режима и выбирай осознанно:

- `--cache-mode auto`: значение по умолчанию для обычной, пакетной, тяжёлой и агентской работы; флаг можно не указывать.
- `--cache-mode refresh`: одна команда, где важна свежесть и надо обойти сохранённый ответ; никогда внутри цикла по сущностям.
- `--cache-mode off`: отладка кэша, приватные чтения или частый опрос.
- `--cache-mode readwrite`: автоматизация с фиксированным сроком; всегда вместе с явным `--cache-ttl-seconds`.

Используй `refresh` один раз, когда корректность важнее повторного использования:

```bash
kaiten --json --cache-mode refresh spaces list --compact --fields id,title
```

Для повторно используемого снимка предпочитай один `snapshot refresh` вместо `--cache-mode refresh` в каждом чтении источника.

## Диагностика

Когда путь кажется неожиданно медленным, повтори с:

```bash
kaiten --json --verbose ...
```

Смотри на:

- `execution_mode`
- `cache_policy`
- `cache: request hit/miss`
- `cache: disk hit/miss/bypass`
- сообщения `retry:`
- итоговую сводку `stats:` с длительностью, числом HTTP-запросов, ожиданием API и попаданиями в кэш

Каждый ответ `--json` также содержит `stats` верхнего уровня. Смотри `stats.http_request_count`, `stats.api_wait_ms`, `stats.cache_hits` и `stats.groups`, прежде чем решать, повторять ли запрос или расширять тяжёлый запрос.

Для длинных сценариев записывай трассировку команд:

```bash
kaiten --json --trace-file ./kaiten-trace.jsonl cards list-all --board-id 10 --selection active_only
```

Трассировка сохраняет ту же статистику между командами и помогает объяснить реальную стоимость HTTP, когда внешние логи агента видят только скрипт-обёртку.

Трассировка обязательна, когда обёртка выполняет три и более команды CLI, ожидается больше десяти HTTP-запросов или внешний цикл неизбежен. Смотри трассировку локально:

```bash
kaiten --json trace summarize --file ./kaiten-trace.jsonl
```

## Быстрое правило выбора

- Нужно много карточек: `cards list-all`
- Нужны детали многих карточек для суженных кандидатов: `cards batch-get`
- Нужно много чтений журналов работ: `time-logs batch-list`
- Нужно много связей с дочерними объектами: `card-children batch-list`
- Нужно много чтений комментариев: `comments batch-list`
- Нужна одна структура пространства: `space-topology get`
- Нужно много историй карточек: `card-location-history batch-get`
- Нужны привязки дополнений по многим карточкам: массового пути нет; сначала сузь набор карточек, затем итерируй с трассировкой
- Нужно много последующих вопросов по одному набору: `snapshot build` → `query cards` и `query metrics`
- Нужна одна сущность много раз в разных вызовах CLI: оставляй `--cache-mode auto` по умолчанию; `--cache-mode readwrite` бери только для фиксированного срока
- Нужно сначала понять путь: `describe <tool>`
