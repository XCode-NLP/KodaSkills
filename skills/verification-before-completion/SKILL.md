# Проверка перед заявлением о завершении

## Обзор

**Главный принцип:** сначала доказательства, потом заявления. Всегда.

**Нарушение буквы этого правила означает нарушение его сути.**

## Железный закон

```
НИКАКИХ ЗАЯВЛЕНИЙ О ЗАВЕРШЕНИИ БЕЗ СВЕЖИХ ДОКАЗАТЕЛЬСТВ ПРОВЕРКИ
```

Если ты не запускал команду проверки в этом сообщении, ты не можешь утверждать, что она проходит.

## Порядок действий

```
ПРЕЖДЕ ЧЕМ заявить о статусе или выразить удовлетворение:

1. ОПРЕДЕЛИ: какая команда докажет это утверждение?
2. ЗАПУСТИ: выполни ПОЛНУЮ команду (заново, целиком)
3. ПРОЧИТАЙ: весь вывод, проверь код возврата, посчитай сбои
4. СВЕРЬ: подтверждает ли вывод утверждение?
   - ЕСЛИ НЕТ: назови фактический статус с доказательствами
   - ЕСЛИ ДА: сделай заявление ВМЕСТЕ с доказательствами
5. ТОЛЬКО ПОСЛЕ ЭТОГО: заявляй

Пропуск любого шага = обман, а не проверка
```

## Частые ошибки

| Заявление | Что требуется | Чего недостаточно |
|-------|----------|----------------|
| Тесты проходят | Вывод команды тестов: 0 сбоев | Прошлый запуск, «должно проходить» |
| Линтер чист | Вывод линтера: 0 ошибок | Частичная проверка, экстраполяция |
| Сборка проходит | Команда сборки: код возврата 0 | Линтер проходит, логи выглядят нормально |
| Ошибка исправлена | Тест на исходный симптом: проходит | Код изменён, «предположительно исправлено» |
| Регрессионный тест работает | Проверен цикл «красный — зелёный» | Тест прошёл один раз |
| Агент завершил работу | Дифф системы контроля версий показывает изменения | Отчёт агента об «успехе» |
| Требования выполнены | Построчная сверка с контрольным списком | Тесты проходят |

## Тревожные сигналы — СТОП

- Слова «должно», «вероятно», «кажется»
- Удовлетворение до проверки («Отлично!», «Готово!», «Идеально!» и подобное)
- Намерение закоммитить, запушить или создать пул-реквест без проверки
- Доверие отчётам агента об успехе
- Опора на частичную проверку
- Мысль «только в этот раз»
- Усталость и желание поскорее закончить
- **ЛЮБАЯ формулировка, подразумевающая успех без выполненной проверки**

## Профилактика оправданий

| Оправдание | Действительность |
|--------|---------|
| «Теперь должно работать» | ЗАПУСТИ проверку |
| «Я уверен» | Уверенность ≠ доказательство |
| «Только в этот раз» | Исключений нет |
| «Линтер прошёл» | Линтер ≠ компилятор |
| «Агент сказал, что всё получилось» | Проверяй самостоятельно |
| «Я устал» | Усталость ≠ оправдание |
| «Частичной проверки достаточно» | Частичная проверка ничего не доказывает |
| «Сформулировал иначе, значит правило не действует» | Суть важнее буквы |

## Ключевые шаблоны

**Тесты:**

```
✅ [Запуск команды тестов] [Вижу: 34/34 пройдено] «Все тесты проходят»
❌ «Теперь должно проходить» / «Выглядит правильно»
```

**Регрессионные тесты (цикл «красный — зелёный» по TDD):**

```
✅ Написать → Запустить (проходит) → Откатить исправление → Запустить (ДОЛЖЕН УПАСТЬ) → Вернуть → Запустить (проходит)
❌ «Я написал регрессионный тест» (без проверки цикла «красный — зелёный»)
```

**Сборка:**

```
✅ [Запуск сборки] [Вижу: код возврата 0] «Сборка проходит»
❌ «Линтер прошёл» (линтер не проверяет компиляцию)
```

**Требования:**

```
✅ Перечитать план → Составить контрольный список → Проверить каждый пункт → Сообщить о пробелах или завершении
❌ «Тесты проходят, этап завершён»
```

**Делегирование агенту:**

```
✅ Агент сообщил об успехе → Проверить дифф системы контроля версий → Сверить изменения → Сообщить фактическое состояние
❌ Доверять отчёту агента
```

## Когда применять

**ВСЕГДА перед:**
- любым вариантом заявления об успехе или завершении
- любым выражением удовлетворения
- любым утверждением о состоянии работы
- коммитом, созданием пул-реквеста, завершением задачи
- переходом к следующей задаче
- делегированием агентам

**Правило распространяется на:**
- точные фразы
- пересказы и синонимы
- намёки на успех
- любое сообщение, подразумевающее завершённость или правильность
