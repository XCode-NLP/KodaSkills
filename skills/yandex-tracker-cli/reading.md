# Чтение задач

## Лестница детализации

Пять ступеней, от самой дешёвой. Бери самую низкую из тех, что отвечает на вопрос.

| команда | объём | когда |
|---|---|---|
| `ytcli issue count -q PROJ -s open` | одно число | решаешь, тянуть ли список вообще |
| `ytcli issue get PROJ-1 --fields status,assignee` | одна строка | нужны два поля |
| `ytcli issue get PROJ-1` | ~15 строк | нужно понять задачу |
| `ytcli issue get PROJ-1 --full` | + всё описание | первые строки обрезались, а они важны |
| `ytcli issue get PROJ-1 --format json` | полный ответ | нужна точность, а не читаемость |

`--fields` принимает любое имя поля, в том числе своё, и возвращает их в том порядке, в каком ты попросил. Неизвестное или незаполненное поле приходит как `-`, а не исчезает, поэтому колонки не съезжают.

`ytcli queue fields PROJ` показывает, что на самом деле есть у очереди, включая свои ключи. Если угадать имя своего поля и получить `-`, это не отличить от пустого значения; так и проверяй.

Голое число — это номер задачи в очереди по умолчанию для профиля, поэтому `ytcli issue get 42` и `ytcli issue get PROJ-42` — одна и та же задача.

**Не ветвись по статусу или приоритету, прочитанному как текст.** Они приходят на языке организации — российская организация ответит `Закрыт`, а не `Closed`. `--format json` рядом с ними отдаёт `status_key` и `priority_key`, и они одинаковы в любой организации: `open`, `inProgress`, `closed`, `blocker`, `critical`. Показывай отображение, сравнивай ключ.

## Поиск

```bash
ytcli issue find -q PROJ -a me -s open
ytcli issue find --tags QA --limit 50
ytcli issue find --yql 'Queue: PROJ AND Status: Open AND Updated: >now()-7d'
```

`ytcli issue list` — та же команда, названная так, как перечисляются остальные группы. Обе в белом списке; ни одна не умеет писать.

`--yql` — это полный фильтр на языке запросов Яндекса, и он только для чтения, как и любой другой поиск: через него нельзя ничего записать. Операторы, функции, относительные даты, сортировка и имена фильтров — в `yql.md`; незнакомое Трекеру имя отклоняется с 422, где оно названо.

## Пагинация

Списки заканчиваются `shown N of M` и добавляют `next: --page K`, если есть ещё. Больше обрезание никак не сигнализируется: код выхода остаётся `0`, потому что обрезанный ответ — успешный.

`--all` проходит все страницы и отказывается идти дальше `--max`, вместо того чтобы молча обрезать. Лучше сузить фильтр, чем увеличивать `--max`.

## Ключи из нескольких организаций

Голый ключ — норма, и ключ сам решает, какой профиль ответит:

```bash
ytcli issue get LMS-11
→ profile=work org=1234567 (from the only profile that sees LMS)
```

Очередь, которую видит только один профиль, запрашивается через этот профиль, каким бы ни был профиль по умолчанию. Два профиля в *одной* организации — не конфликт: это одна задача, увиденная через два логина.

Два профиля в *разных* организациях с одинаковым ключом очереди — вот настоящая неоднозначность: тогда `LMS-12` называет две задачи, голая форма отклоняется, а сообщение перечисляет оба варианта. Пиши `work/LMS-12`, такая форма принимается всегда.

Каждая команда печатает строку `→ profile=… org=…` в stderr, один раз. В stdout её не бывает, поэтому на разбор вывода она не влияет.

## Свои поля

Компактный вид считает их (`custom: 4 set (components, epic, …) — see --fields`), а не вываливает: набор различается по очередям, большинство пусты, и печать всех сделала бы вид нестабильным от задачи к задаче. Запрашивай нужные по имени.

Ссылочные поля — компоненты, теги, эпики — выводятся отображаемыми именами. Идентификаторы есть в `--format json`, если нужно обращаться по ним.

## Связи

Связи показываются всегда, вместе с типом: `parent`, `subtask`, `is blocked by`, `relates`, `epic` и так далее. Это сделано намеренно — «что это блокирует» следует сразу за «что это такое», и отдельная команда стоила бы дороже, чем четыре сэкономленные строки.

## За пределами задач

Та же лестница, те же итоги:

```bash
ytcli queue list                     # ключи и руководители
ytcli queue get PROJ                 # тип и приоритет, с которыми начинается новая задача
ytcli queue versions PROJ            # на что указывает fixVersions задачи
ytcli board list                     # id, имя, число колонок
ytcli board sprints 6                # для канбан-доски будет отказ словами Трекера
ytcli issue timers                   # запущенные здесь таймеры; запрос не делается
ytcli sprint list                    # все спринты с доской, к которой относится каждый
ytcli sprint list --planning         # тот, куда планировать: ближайший черновик, иначе идущий
ytcli sprint get 21                  # его даты и сколько его задач закрыто
ytcli field list                     # все поля, которые определяет организация
ytcli field get storyPoints          # что принимает поле — до того, как угадывать в --set
ytcli component list -q PROJ         # имена, которые принимает поле components, по очереди
ytcli link types                     # словарь записи рядом с идентификаторами типов
ytcli queue local-fields PROJ        # поля, принадлежащие очереди; field get их не видит
ytcli queue access PROJ              # кто что здесь может и входишь ли в их число ты
ytcli template list --kind comment   # по умолчанию шаблоны задач
ytcli portfolio contents 655…        # портфели и проекты внутри одного
ytcli issue worklogs PROJ-1          # учтённое время с итогом
ytcli issue checklist PROJ-1         # строки, отметки и идентификаторы
```
