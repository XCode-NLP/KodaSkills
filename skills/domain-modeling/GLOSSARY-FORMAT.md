# Формат GLOSSARY.md

## Структура

```md
# {Название контекста}

{Одно-два предложения о том, что это за контекст и зачем он существует.}

## Язык

**Заказ**:
{Одно-два предложения с описанием термина}
_Избегать_: Покупка, транзакция

**Счёт**:
Запрос на оплату, отправленный клиенту после поставки.
_Избегать_: Квитанция, платёжное требование

**Клиент**:
Человек или организация, размещающие заказы.
_Избегать_: Покупатель, заказчик, аккаунт
```

## Правила

- **Будь категоричны.** Когда для одного понятия есть несколько слов, выбери
  лучшее и перечисли остальные в `_Избегать_`.
- **Держишь определения короткими.** Максимум одно-два предложения. Определяй,
  ЧТО это, а не что оно делает.
- **Включай только термины, специфичные для контекста этого проекта.** Общие
  программные понятия (тайм-ауты, типы ошибок, служебные образцы) сюда не
  относятся, даже если проект пользуется ими широко. Прежде чем добавить термин,
  спроси: это понятие, уникальное для этого контекста, или общее программное
  понятие? Место здесь только первому.
- **Группируй термины под подзаголовками**, когда естественно складываются
  кластеры. Если все термины принадлежат одной цельной области, плоский список
  годится.

## Репозитории с одним и несколькими контекстами

**Один контекст (большинство репозиториев):** один `GLOSSARY.md` в корне
репозитория.

**Несколько контекстов:** `GLOSSARY-MAP.md` в корне репозитория перечисляет
контексты, где они живут и как связаны между собой:

```md
# Карта глоссариев

## Контексты

- [Заказы](./src/ordering/GLOSSARY.md): принимает и отслеживает заказы клиентов
- [Биллинг](./src/billing/GLOSSARY.md): формирует счета и обрабатывает платежи
- [Исполнение](./src/fulfillment/GLOSSARY.md): управляет сборкой на складе и отправкой

## Связи

- **Заказы → Исполнение**: «Заказы» порождают события `OrderPlaced`, «Исполнение» их потребляет, чтобы начать сборку
- **Исполнение → Биллинг**: «Исполнение» порождает события `ShipmentDispatched`, «Биллинг» их потребляет, чтобы сформировать счета
- **Заказы ↔ Биллинг**: общие типы для `CustomerId` и `Money`
```

Навык определяет, какая структура применима:

- если `GLOSSARY-MAP.md` есть, прочитай его, чтобы найти контексты;
- если есть только корневой `GLOSSARY.md`, контекст один;
- если нет ни того ни другого, создай корневой `GLOSSARY.md` по мере
  необходимости, когда определён первый термин.

Когда контекстов несколько, определи, к какому относится текущая тема. Если
неясно, спроси.
