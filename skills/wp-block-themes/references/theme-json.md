# Рекомендации по `theme.json`

Используй этот файл, когда меняешь глобальные настройки и стили или оформление
отдельных блоков.

## Структура верхнего уровня

Частые ключи верхнего уровня:

- `version`
- `settings` (что интерфейс показывает и разрешает)
- `styles` (внешний вид по умолчанию)
- `customTemplates` и `templateParts` (необязательно, описывают шаблоны и части)

Источники:

- Theme Handbook: https://developer.wordpress.org/themes/global-settings-and-styles/
- Block Editor Handbook (часто актуальнее):
  https://developer.wordpress.org/block-editor/how-to-guides/themes/theme-json/
- Живой справочник Theme JSON:
  https://developer.wordpress.org/block-editor/reference-guides/theme-json-reference/theme-json-living/
- Заметка о версии 3 Theme JSON:
  https://make.wordpress.org/core/2024/06/19/theme-json-version-3/

## Практические ограничения

- Предпочитай пресеты, когда нужны элементы управления в редакторе (цвета, размеры
  шрифта, отступы).
- Предпочитай `styles`, когда нужны согласованные умолчания без выбора пользователя.
- Осторожно со специфичностью: глобальные стили пользователя переопределяют умолчания
  темы.

## Что добавилось в WordPress 6.9

**Оформление элементов форм:**

- Стилизуй текстовые поля и списки выбора через `styles.elements.textInput` и
  `styles.elements.select`.
- `textInput` нацелен на `<textarea>` и `<input>`, у которых `type` равен одному из:
  email, number, password, search, text, tel, url.
- Ключей элементов `input`, `checkbox`, `radio` и `label` нет.
- Поддерживаются свойства рамки, цвета, контура, тени и отступов.
- Учти: оформление состояния фокуса в 6.9 ещё недоступно.

**Пресеты радиуса рамки:**

- Определи пресеты в `settings.border.radiusSizes`, чтобы они были доступны для выбора
  в элементе управления радиусом рамки.
- Пользователи по-прежнему могут вводить собственные значения.

```json
{
  "settings": {
    "border": {
      "radiusSizes": [
        { "name": "Small", "slug": "small", "size": "4px" },
        { "name": "Medium", "slug": "medium", "size": "8px" },
        { "name": "Large", "slug": "large", "size": "16px" }
      ]
    }
  }
}
```

**Псевдоклассы кнопок:**

- Оформляй состояния наведения и фокуса блока «Кнопка» прямо в theme.json.
- Для простого оформления состояний кнопки больше не нужен собственный CSS.

Ссылки:

- Пресеты радиуса рамки: https://make.wordpress.org/core/2025/11/12/theme-json-border-radius-presets-support-in-wordpress-6-9/
- Оформление элементов форм: https://developer.wordpress.org/news/2025/11/how-wordpress-6-9-gives-forms-a-theme-json-makeover/

## Ловушка нормализации слагов

> **Ловушка нормализатора слагов (тихий сбой).** Перед выводом CSS-переменных
> WordPress вставляет дефисы внутрь пресетных и пользовательских слагов: слаг `3xl`
> превращается в `--wp--preset--font-size--3-xl`, а слаг `cardShadow` — в
> `--wp--custom--card-shadow`. Ссылка, написанная вручную в *ненормализованном* виде
> (например, `var(--wp--preset--font-size--3xl)`), не разрешается ни во что и тихо
> подставляет второй аргумент `var()`.

Перед сборкой имени переменной `WP_Theme_JSON` прогоняет каждый пресетный и
пользовательский слаг через `_wp_to_kebab_case()`, которая разбивает его на слова — на
границах цифр и букв, при переходах camelCase и по небуквенно-цифровым символам, —
приводит их к нижнему регистру и соединяет через `-`. Ссылайся на итоговую форму, а не
на слаг, который ты написал.

Шаблон для grep, чтобы найти ненормализованные ссылки в CSS, SCSS, PHP и JS:

```
var\(\s*--wp--(?:preset|custom)--[a-z-]+--\d+[a-z]
```

Он находит цифру, за которой сразу идёт буква внутри имени переменной (`3xl`, `2xs`,
`4x-large`): итоговая форма всегда содержит дефис (`3-xl`, `2-xs`, `4-x-large`) и
поэтому правильно не попадает в результаты.
