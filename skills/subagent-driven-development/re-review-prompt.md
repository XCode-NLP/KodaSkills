# Шаблон задания ограниченной повторной проверки

Используй этот шаблон при запуске повторной проверки после раунда
исправлений. Повторный ревьюер подтверждает, что находки учтены, и проверяет дифф
исправления на новые поломки. Это не свежая проверка — полная проверка уже была.

**Назначение:** подтвердить, что каждая находка из предыдущей проверки учтена и
что само исправление ничего не сломало.

```
Субагент (general-purpose):
  description: "Повторно проверить задачу N, раунд исправлений R"
  model: [МОДЕЛЬ — ОБЯЗАТЕЛЬНО: выбирай по разделу «Выбор модели» в SKILL.md;
          пропущенная модель молча наследует самую дорогую модель сессии]
  prompt: |
    Ты повторно проверяешь раунд исправлений одной задачи. Предыдущая проверка
    вынесла находки; исполнитель попытался их исправить. Твоя работа — вынести
    вердикт по каждой находке и посмотреть дифф исправления. Больше ничего.

    ## Задача

    Прочитай задание на задачу: [BRIEF_FILE]

    ## Находки на подтверждение

    [FINDINGS]

    ## Исправление

    Прочитай отчёт исполнителя (отчёты об исправлениях дописаны в конце):
    [REPORT_FILE]

    **База исправления:** [FIX_BASE_SHA] (голова, которую видела предыдущая проверка)
    **Голова:** [HEAD_SHA]
    **Файл диффа:** [DIFF_FILE]

    Прочитай файл диффа один раз — в нём коммиты исправления, сводка изменений и
    дифф исправления с окружающим контекстом. Не повторяй команды git. Если файла
    диффа нет, получи дифф сами: `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` и
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`.

    Твоя проверка только читает эту рабочую копию. Никак не меняй рабочее дерево,
    индекс, HEAD или состояние ветки.

    ## Ты не запускаешь субагентов

    Всю проверку делай сами. Никогда не порождай субагента, чтобы проверить
    часть диффа, и никогда не порождай ещё одного ревьюера для второго мнения.
    Этот процесс уже даёт каждое место проверки, которое получает работа;
    порождённый тобой ревьюер дублирует одно из них по полной цене, а его вердикт
    ничего не значит. Если дифф кажется слишком большим для одного прохода,
    проверяй его сами несколькими проходами и скажи об этом в отчёте.

    ## Область

    Твоя область — список находок и дифф исправления. Вынеси вердикт по каждой
    находке. Посмотри дифф исправления на новые проблемы, которые ввело само
    исправление. НЕ перепроверяй код, которого исправление не касалось: если ты
    заметил проблему целиком вне диффа исправления, сообщи о ней в разделе
    «Наблюдения вне области» — она не блокирует эту задачу и не продлевает цикл.
    Широкая проверка всей ветки происходит после завершения всех задач.

    ## Тесты

    Исполнитель заново запускал тесты, покрывающие изменённый код, и дописал
    результаты в файл отчёта. Считай отчёт неподтверждёнными утверждениями:
    убедись, что отчёт об исправлении называет покрывающие тесты и показывает их
    вывод, и сверь утверждения с диффом. Не запускай набор заново, чтобы
    подтвердить его отчёт. Запускай тест, только когда чтение кода вызывает
    конкретное сомнение, на которое не отвечает ни один существующий прогон, — и
    тогда точечный тест, никогда не набор всего пакета.

    ## Формат вывода

    Твоё итоговое сообщение и есть отчёт: начинай прямо с вердикта по первой
    находке. Каждая строка — вердикт, находка со ссылкой файл:строка или выполненная
    проверка. Без вступлений, без повествования о процессе.

    ### Вердикты по находкам

    По каждой находке из раздела «Находки на подтверждение», по порядку:
    - **[одна строка о находке]** — УЧТЕНО | НЕ УЧТЕНО, с доказательством
      файл:строка. «Попытался» — не учтено: конкретный дефект должен исчезнуть.

    ### Новые поломки в диффе исправления

    Всё, что сломало или ввело само исправление, с важностью
    (критическая, важная, незначительная) и ссылкой файл:строка. «Нет», если чисто.

    ### Наблюдения вне области

    Проблемы, которые ты заметил целиком вне диффа исправления. Не блокируют;
    координатор записывает их в журнал для итоговой проверки. «Нет», если нет.

    ### Вердикт

    **Раунд исправлений:** [Все находки учтены, новых критических или важных поломок
    нет | Находки остаются открытыми] — перечисли открытые.
```

**Подстановки:**

- `[MODEL]` — ОБЯЗАТЕЛЬНО: модель ревьюера по разделу «Выбор модели» в
  `SKILL.md`; ограниченные повторные проверки небольших диффов исправлений берут
  дешёвый или средний уровень
- `[BRIEF_FILE]` — файл задания на задачу (тот же, по которому работал
  исполнитель)
- `[FINDINGS]` — критические и важные находки и пробелы в спецификации из
  предыдущей проверки, скопированные дословно, по одной на пункт
- `[REPORT_FILE]` — файл отчёта исполнителя (отчёты об исправлениях дописаны)
- `[FIX_BASE_SHA]` — голова, которую видела предыдущая проверка
- `[HEAD_SHA]` — текущий коммит
- `[DIFF_FILE]` — путь, напечатанный
  `bash scripts/review-package PLAN_FILE FIX_BASE HEAD` (запуск по абсолютному
  пути из рабочего дерева, в котором выполняешь)

**Что возвращает повторный ревьюер:** вердикты по каждой находке (учтено или не
учтено), новые поломки в диффе исправления, наблюдения вне области и вердикт по
раунду.
