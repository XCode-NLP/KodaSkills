# Быстрые пути отладки

## Блок не появляется в списке вставки

- убедись, что `name` в `block.json` корректен и блок зарегистрирован;
- убедись, что результаты сборки есть и скрипты подключены;
- при регистрации на PHP убедись, что выполняется
  `register_block_type_from_metadata()` (частая причина — неверный хук или файл не
  загружен).

## «Этот блок содержит неожиданное или невалидное содержимое»

- ты изменил сохранённую разметку или разбор атрибутов;
- добавь версии в `deprecated` и путь миграции;
- воспроизведи на старой записи с прежней разметкой.

## Атрибуты не сохраняются

- убедись, что описание атрибута соответствует реальной разметке;
- если значение лежит в JSON разделителя, избегай хрупких селекторов;
- избегай источника атрибута `meta` (устарел).

## Предупреждения в консоли про apiVersion (WordPress 6.9+)

Если видишь «The block 'namespace/block' is registered with API version 2 or
lower»:

- обнови `apiVersion` до `3` в block.json;
- это предупреждение появляется только когда `SCRIPT_DEBUG` истинно;
- WordPress 7.0 требует apiVersion 3 для правильной работы редактора во фрейме.

## Стили не применяются в редакторе (apiVersion 3 и фрейм)

Если стили работают на лицевой части, но не в редакторе:

- убедись, что дескрипторы стилей объявлены в block.json (`editorStyle`, `style`);
- стили, не указанные в block.json, не загрузятся внутри редактора во фрейме;
- проверь Dashicons и другие зависимости, которые нужно подключать явно.
