# Руководство по `block.json` (метаданные)

Используй этот файл, когда правишь поля `block.json` или выбираешь между полями
скриптов и стилей.

## Практические правила

- считай `name` стабильным API: переименование ломает существующее содержимое;
- предпочитай добавлять новую функциональность, не меняя сохранённую разметку; если
  разметку менять всё же нужно, добавь версию в `deprecated`;
- держи ресурсы ограниченными по области: ресурсы редактора не должны уходить на
  лицевую часть без необходимости.

## Версия API и схема

**WordPress 6.9+ требует apiVersion 3.** Схема block.json теперь проверяет только
блоки с `apiVersion: 3`. Более старые версии (1 или 2) вызывают предупреждения в
консоли, когда включён `SCRIPT_DEBUG`.

**Почему apiVersion 3 важна:**

- редактор записей будет во фрейме, если у всех зарегистрированных блоков
  apiVersion 3 и выше;
- WordPress 7.0 всегда использует редактор во фрейме независимо от apiVersion;
- выгоды: изоляция стилей (административные стили не влияют на содержимое
  редактора), правильные единицы области просмотра (vw, vh), штатные медиазапросы.

**Контрольный список перехода:**

1. Обнови `apiVersion` до `3` в block.json.
2. Убедись, что все дескрипторы стилей объявлены в block.json (стили, которых там
   нет, не загрузятся во фрейме).
3. Проверь блоки, зависящие от сторонних скриптов (область видимости `window` может
   отличаться).
4. Добавь `$schema`, чтобы улучшить работу инструментов и проверку.

## Современные поля ресурсов, которые стоит знать

Это не полная схема, а список «что важно на практике»:

- `editorScript` и `editorStyle`: ресурсы только для редактора;
- `script` и `style`: общие ресурсы;
- `viewScript` и `viewStyle`: ресурсы для лицевой части;
- `viewScriptModule`: скрипты лицевой части на модулях (новые версии WordPress);
- `render`: указывает на PHP-файл отрисовки для динамических блоков (новые версии
  WordPress).
