# Объяснение фильтра

## Выбери проект и исходные данные

Найди у подключённого сервера инструменты `filter_*`. Если подключения нет, объясни это. Держи вызовы на этом сервере: имена и идентификаторы опознают записи только внутри проекта, которому он служит.

Используй полный исходный JSON фильтра. Ссылку на отфильтрованный список импортировать нельзя, а эти инструменты не достают сохранённые фильтры по имени. Если дали только ссылку или незнакомый фильтр, попроси его JSON. Для удачной сборки, уже сделанной в этом разговоре, переиспользуй её подтверждённые `finalSql` и выбранные записи, а не конвертируй заново.

Заново прочитай актуальную точку входа подключённого сервера: `filter_wiki_read` с `paths = ["README.md"]`.

Используй её навигацию и актуальные указания по инструментам. Переиспользуй страницы в пределах этого объяснения. Примеры ниже называют инструмент и аргументы, которые несут запрос; остальное заполняй по схеме, которую отдаёт сервер. Используй фактические входные данные и возвращённые пути. У имён инструментов может быть префикс сервера.

## 1. Преобразуй исходный JSON в SQL

Передай полный JSON без изменений в `filter_json_to_sql` как его объект `filterJson` — например, такой фильтр по клиентам от 30 лет:

```json
{
  "entityType": "User",
  "filterFactory": "and",
  "innerConditions": [{
    "entityType": "User",
    "filterFactory": "age",
    "value": {"mode": "concrete", "value": {"range": {"from": "30", "to": ""}, "unit": "Years"}}
  }]
}
```

Прочитай возвращённые `sql`, выбранные записи и предупреждения. Инструмент уже пытается развернуть идентификаторы каталога в имена; не повторяй удачные подстановки. `status: read` значит, что JSON прочитан, а не что платформа приняла фильтр. `unlabelled` значит, что часть значений осталась без имён; `unsupported` или `UNSUPPORTED_FILTER(...)` отмечает условия, которые преобразование объяснить не может. Держи исходный JSON и эти пробелы видимыми в своих рассуждениях. Не пересобирай фильтр попроще, чтобы они исчезли.

## 2. Прочитай смысл и разверни оставшиеся названия

Определи в SQL корень, поля, связи, операторы и бизнес-понятия. Для каждого отдельного понятия, чей смысл или ограничения тебе нужно установить, ищи в вики, объединяя связанные термины в регулярное выражение и переиспользуя уже прочитанные страницы:

Ищи через `filter_wiki_grep`, затем читай найденное через `filter_wiki_read`. Для условия по возрасту клиентов это `pattern = "возраст|\\bage(?:d|s)?\\b"` по `paths = ["field/user"]`, затем `paths = ["field/user.age.md"]`, оба с `root = "User"`.

`pattern` — регулярное выражение без учёта регистра. Здесь `возраст` совпадает с формами вроде `возраста` и `возрастной`; `\\bage(?:d|s)?\\b` совпадает с английскими словами `age`, `aged` и `ages`, но не с `message`. В строках JSON для передачи границы регулярного выражения `\b` нужно `\\b`. Для условий подписки `подпис(?:к|ок|ан)|subscri(?:b|pt)` покрывает формы вроде `подписка`, `подписок`, `подписан`, `subscribe` и `subscription`. Выбирай термины, нужные для фильтра.

`paths` задаёт приоритет разделов, но не исключает остальные. Следуй `skip`/`limit`, если результаты продолжаются. Копируй возвращённые пути точно, включая подчёркивания, регистр и `.md`. Читай страницы полей и связей ради поведения, а страницы рецептов и глоссария — ради бизнес-смысла. Если продуктовый вопрос всё равно остался, ищи по бизнес-терминам с `paths: ["help"]`; отсутствие записи в README само по себе не доказывает, что справка недоступна. Документация объясняет условие, но не добавляет условий в фильтр.

Для неразвёрнутого значения каталога найди подходящий тип справочника и поддерживаемый поиск:

Перечисли справочники через `filter_wiki_ls` по `path = "lookup"`, прочитай нужный через `filter_wiki_read` — `paths = ["lookup/segment.md"]` для сегмента — и затем ищи через `filter_search_entities`, передав `types = ["segment"]` и `context`, где сказано, что ты опознаёшь. Держи `root = "User"` в вызовах вики.

Просматривай список, когда это практично, или ищи известное имя через `query`. Продолжай возвращённым `nextCursor` как `cursor`, сохраняя остальные аргументы. Если запрос отклонён, один раз перезапусти тот же листинг без `cursor`; повторный сбой раскрой как неразвёрнутый справочник. Сверяй возвращённые `ref.ids`, тип и родителя с исходной ссылкой, прежде чем присвоить название. Похожее имя или оценка релевантности не опознают идентификатор, а `query` — не универсальная операция «получить по ID». Если личность так и не установлена, скажи об этом. Неполный поиск или отсутствующее название сами по себе не доказывают, что запись удалена или что аудитория пуста.

## 3. Объясни фактическую выборку

Используй язык разговора и бизнес-термины. Строй объяснение вокруг:

- **Результат:** что такое одна возвращённая строка и какую аудиторию или объекты выбирает фильтр.
- **Условия:** сгруппированные включения, альтернативы и исключения, со значениями и периодами.
- **Ограничения и пробелы:** существенное поведение из справочника и всё, что прочитать не удалось.

Сохраняй группировку И/ИЛИ, отрицание, включительные и исключительные границы, относительные и абсолютные временные окна, количества и условия, которые должны выполняться на одном и том же связанном объекте. Отличай один сегмент от всей его сегментации, текущее членство от исторического, любое подходящее событие от последнего события, когда такие конструкции встречаются. Не заменяй эти различия широкой меткой вроде «активные клиенты».

Указывай задокументированные оговорки, влияющие на этот фильтр, и объясняй, почему каждая важна. Называй безымянные значения их ролью и ID, когда нужно; никогда не подавай ID как название каталога. Описывай неподдержанное условие как пробел, а не считай, что оставшийся SQL и есть весь фильтр. Не выводи пустую или неограниченную аудиторию из нечитаемой части.

Держи SQL и внутренние имена полей вне ответа, если об этом не просили или если они не нужны для обозначения пробела. Объяснение не требует валидации и компиляции и не меняет данные проекта. Если пользователь просит исправить фильтр, переходи к навыку mindbox-filter-build с исходным JSON, восстановленным SQL и выбранными записями; не тронутые условия сохраняй.
