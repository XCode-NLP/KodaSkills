# Маршруты и эндпоинты (кратко)

## Регистрация маршрутов

- регистрируй маршруты на хуке `rest_api_init` через
  `register_rest_route( $namespace, $route, $args )`;
- **маршрут** — это шаблон адреса, а **эндпоинт** — метод с обратным вызовом,
  привязанный к этому маршруту;
- при невключённых постоянных ссылках маршрут доступен через
  `?rest_route=/namespace/route`.

## Пространства имён

- всегда давай маршрутам пространство имён (`vendor/v1`);
- **не** занимай пространство `wp/*`, если не работаешь с ядром.

## Методы

- используй `WP_REST_Server::READABLE` (GET), `CREATABLE` (POST), `EDITABLE`
  (PUT и PATCH), `DELETABLE` (DELETE);
- несколько эндпоинтов могут делить один маршрут, по одному на метод.

## permission_callback (обязателен)

- всегда указывай `permission_callback`;
- публичные эндпоинты должны использовать `__return_true`;
- для закрытых эндпоинтов проверяй права (`current_user_can`) или авторизацию на
  уровне объекта;
- без `permission_callback` в современных версиях WordPress выдаётся замечание
  `_doing_it_wrong`.

## Аргументы

- регистрируй `args`, чтобы проверять и очищать ввод;
- используй `type`, `required`, `default`, `validate_callback`,
  `sanitize_callback`;
- читай параметры через объект `WP_REST_Request`, а не `$_GET` и `$_POST`.

## Возвращаемые значения

- возвращай данные через `rest_ensure_response()` или `WP_REST_Response`;
- для ошибок возвращай `WP_Error` со `status` в `data`;
- не вызывай `wp_send_json()` в обратных вызовах REST.
