# REST API WordPress

## Когда использовать

Используй этот навык, когда нужно:

- создать или обновить маршруты и эндпоинты REST;
- разобраться с ошибками 401, 403 и 404 либо с проблемами прав и nonce;
- добавить свои поля и метаданные в ответы REST;
- показать свои типы записей или таксономии через REST;
- реализовать схему и проверку аргументов;
- настроить ссылки, встраивание и постраничный вывод в ответах.

## Что нужно на входе

- корень репозитория и целевой плагин, тема или mu-плагин (путь к точке входа);
- нужное пространство имён и версия (например, `my-plugin/v1`) и маршруты;
- способ аутентификации (куки с nonce, пароли приложений или плагин
  аутентификации);
- ограничения по версии WordPress (если ниже 7.0, скажи об этом).

## Порядок работы

### 0. Разберись и найди использование REST

1. Запусти разбор:

   ```bash
   node skills/wp-project-triage/scripts/detect_wp_project.mjs
   ```

2. Поищи существующее использование REST:
   - `register_rest_route`;
   - `WP_REST_Controller`;
   - `rest_api_init`;
   - `show_in_rest`, `rest_base`, `rest_controller_class`.

Если это репозиторий всего сайта, выбери конкретный плагин или тему, прежде чем
менять код.

### 1. Выбери правильный подход

- **Показать тип записей или таксономию в `wp/v2`:**
  - используй `show_in_rest => true` и `rest_base`, если нужно;
  - при необходимости укажи `rest_controller_class`;
  - прочитай `references/custom-content-types.md`.
- **Свои эндпоинты:**
  - используй `register_rest_route()` на `rest_api_init`;
  - для всего нетривиального предпочитай класс-контроллер (наследник
    `WP_REST_Controller`);
  - прочитай `references/routes-and-endpoints.md` и `references/schema.md`.

### 2. Регистрируй маршруты безопасно (пространства имён, методы, права)

- используй уникальное пространство имён `vendor/v1`; не занимай `wp/*`, если это
  не ядро;
- всегда указывай `permission_callback` (для публичных эндпоинтов —
  `__return_true`);
- используй константы `WP_REST_Server::READABLE`, `CREATABLE`, `EDITABLE`,
  `DELETABLE`;
- возвращай данные через `rest_ensure_response()` или `WP_REST_Response`;
- возвращай ошибки через `WP_Error` с явным `status`.

Прочитай `references/routes-and-endpoints.md`.

### 3. Проверяй и очищай аргументы запроса

- описывай `args` с полями `type`, `default`, `required`, `validate_callback`,
  `sanitize_callback`;
- предпочитай проверку по схеме JSON через `rest_validate_value_from_schema`, а
  затем `rest_sanitize_value_from_schema`;
- никогда не читай `$_GET` и `$_POST` прямо внутри эндпоинтов, используй
  `WP_REST_Request`.

Прочитай `references/schema.md`.

### 4. Ответы, поля и ссылки

- **не** удаляй поля ядра из стандартных эндпоинтов, добавляй свои;
- для вычисляемых полей используй `register_rest_field`; для метаданных —
  `register_meta` с `show_in_rest`;
- для метаданных типа `object` и `array` опиши схему в `show_in_rest.schema`;
- если нужен нефильтрованный текст записи (например, плагины оглавления
  вставляют HTML), запроси `?context=edit`, чтобы получить `content.raw` (нужна
  аутентификация), и добавь `_fields=content.raw`, чтобы ответ оставался небольшим;
- добавляй ссылки на связанные ресурсы через `WP_REST_Response::add_link()`.

Прочитай `references/responses-and-fields.md`.

### 5. Аутентификация и авторизация

- для административной части и JavaScript: аутентификация по кукам плюс
  `X-WP-Nonce` (действие `wp_rest`);
- для внешних клиентов: пароли приложений (basic auth) или плагин
  аутентификации;
- в `permission_callback` проверяй права (авторизацию), а не просто «вошёл ли
  пользователь».

Прочитай `references/authentication.md`.

### 6. Поведение для клиентов (обнаружение, постраничный вывод, встраивание)

- убедись, что обнаружение работает (заголовок `Link` или
  `<link rel="https://api.w.org/">`);
- поддерживай `_fields`, `_embed`, `_method`, `_envelope` и заголовки
  постраничного вывода;
- помни, что `per_page` ограничен 100.

Прочитай `references/discovery-and-params.md`.

## Проверка

- в индексе `/wp-json/` есть твоё пространство имён;
- `OPTIONS` по твоему маршруту возвращает схему (если она задана);
- эндпоинт возвращает ожидаемые данные; при нехватке прав возвращаются 401 или 403,
  как положено;
- маршруты типов записей и таксономий появляются в `wp/v2`, когда `show_in_rest`
  истинно;
- запусти линтер и тесты репозитория, а также шаги сборки PHP и JavaScript.

## Режимы отказа и отладка

- 404: `rest_api_init` не срабатывает, опечатка в маршруте или выключены
  постоянные ссылки (используй `?rest_route=`).
- 401 и 403: нет nonce или аутентификации, либо `permission_callback` слишком
  строг.
- `_doing_it_wrong` из-за отсутствия `permission_callback`: добавь его (для
  публичного — `__return_true`).
- Неверные параметры: нет схемы `args` или неверные проверки.
- Поля отсутствуют: `show_in_rest` ложно, метаданные не зарегистрированы или тип
  записей не поддерживает `custom-fields`.

## Когда эскалировать

Если поддержка версии или поведение неясны, сверься со справочником по REST API и
документацией ядра, прежде чем придумывать собственные образцы.
