# Сборка расширений VS Code

Этот навык помогает проектировать, реализовывать, упаковывать и публиковать расширения VS Code по практичному сквозному порядку работы.

## Когда вызывать

Вызывай навык, когда пользователь:
- хочет создать новое расширение VS Code с нуля;
- хочет добавить возможности расширения (дерево, команды, webview, пользовательский редактор, поддержку языка);
- хочет упаковать расширение в `.vsix`;
- хочет опубликовать расширение в VS Code Marketplace;
- упёрся в предусловия публикации (издатель, токены, предупреждения упаковки, включение файлов).

## Что выяснить сразу

- Цель расширения и целевые типы файлов (например, `.pkl`, `.log`, `.foo`).
- Основной интерфейс: дерево, пользовательский редактор, команды или сочетание.
- Зависимости времени выполнения (только Node, помощник на Python, другой CLI).
- Целевые платформы (только VS Code либо VS Code и другие).
- Намерения по публикации (Marketplace, внутренний реестр или только `.vsix`).

## Порядок реализации

### 1) Каркас на TypeScript

Обязательные вклады в `package.json`:
- `activationEvents`;
- `contributes.commands`;
- `contributes.viewsContainers` и `contributes.views` (если есть дерево);
- `contributes.customEditors` (если есть пользовательский редактор);
- `contributes.configuration` (пользовательские настройки).

Предлагаемая раскладка файлов:
- `src/extension.ts` — точка активации;
- `dist/extension.js` — результат компиляции;
- `media/` — ресурсы webview;
- `resources/` — иконки;
- необязательный помощник: `python/` или `bin/`.

### 2) Шаблоны возможностей

Дерево:
- дай `TreeDataProvider` со стабильной моделью узла (id, path, label, type);
- добавь команду `refresh` и автообновление по выделению в активном редакторе.

Пользовательский редактор (предпросмотр только для чтения):
- реализуй `CustomReadonlyEditorProvider`;
- рисуй интерфейс через webview;
- используй обмен сообщениями (`postMessage`) для обновления, поиска, копирования пути и т. п.

Помощник времени выполнения (Python или CLI):
- запускай отдельный процесс;
- предпочитай стабильный протокол JSON между расширением и помощником;
- всегда показывай ошибки как узлы или сообщения для пользователя, а подробности пиши в `OutputChannel`.

### 3) Гигиена упаковки

Добавь `.vscodeignore` или `package.json.files`, чтобы VSIX оставался минимальным:
- исключай `src/`, тесты, локальные наборы данных, кэши сборки;
- по умолчанию исключай чувствительные и крупные файлы.

Проверь упаковку:
- `vsce package`;
- установи локально через «Install from VSIX…».

### 4) Чек-лист публикации в Marketplace

Подготовь метаданные:
- `publisher` точно совпадает с именем издателя в Marketplace;
- `repository`, `homepage`, `bugs`, `license`;
- `README.md` ясно описывает установку, настройку и использование;
- нормальная иконка (рекомендуется PNG).

Варианты публикации:
- публикация из CLI: `vsce publish` (нужны учётные данные для публикации в Marketplace);
- загрузка через портал: загрузить `.vsix` из интерфейса управления Marketplace.

Частые причины сбоя:
- издатель не создан или не связан с аккаунтом;
- у токена не хватает области прав (Marketplace Manage);
- в VSIX попали лишние файлы (исправь `.vscodeignore`).

## Что должно быть на выходе

При вызове выдавай:
- краткую архитектуру и план файлов;
- конкретные правки файлов с путями;
- план проверки (упаковка, установка, проверка основных возможностей);
- путь публикации (CLI или портал) с минимально необходимыми шагами.
