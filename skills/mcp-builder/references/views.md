# Представления

## Привязка представления

Создай `views/<name>/view.tsx`. Экспортируй ссылку на инструмент отрисовки, объяви его
`outputSchema`, привяжи `view: { name }` и возвращай соответствующий `structuredContent`. Имя
директории и `view.name` должны совпадать точно.

Используй `content` результата для краткого читаемого моделью резюме, `structuredContent` для
типизированных данных отрисовки и `_meta` для данных, специфичных для вызова, которые должны быть
видны только представлению.

## Чтение вызова отрисовки

Деструктурируй `useToolContext()` и сузь его размеченный жизненный цикл, прежде чем читать
`toolOutput`:

```tsx
import { useToolContext } from "mcp-use/react";

export default function ProductResults() {
  const { status, toolInput, toolOutput, error, meta } =
    useToolContext<"search-products">();

  if (status === "pending") {
    return <SearchSkeleton query={toolInput?.query} />;
  }

  if (status === "error") {
    return <ErrorBanner message={error.message} />;
  }

  const source = typeof meta?.source === "string" ? meta.source : undefined;
  return <Results items={toolOutput.items} source={source} />;
}
```

`toolInput` может быть частичным, пока вызов в состоянии ожидания. Считай `meta` нетипизированными
внешними данными и проверяй или сужай их перед использованием.

## Выбор канала взаимодействия

- `useCallTool("tool-name")`: вызов экспортированного инструмента сервера с выведенными типами.
- `useDynamicTool`: вызов инструмента, созданного во время работы, когда статической ссылки нет.
- `useSendFollowUp`: запрос нового хода модели.
- `useOpenExternal`: просьба к хосту открыть URL вне песочницы.
- `useDisplayMode`: просмотр и запрос поддерживаемого режима показа.
- `useViewTool`: показ временного действия, работающего с примонтированным интерфейсом.
- `useFiles`: использование файловых возможностей хоста после проверки поддержки.

Защищай действия хоста сигналами возможностей из `useHostContext()`. Хост может отклонить или
изменить запрос, поэтому отрисовывай состояния ожидания и сбоя и читай получившееся состояние
хоста.

## Состояние и контекст модели

- Используй состояние React для временных деталей интерфейса, которые модели не нужны.
- Используй `useViewState(objectDefault)` для сериализуемых в JSON выбранных значений, фильтров,
  черновиков и прогресса, которые должны понимать будущие ходы модели.
- Используй `<ModelContext content="...">`, чтобы декларативно описать текущий видимый интерфейс.
- Храни долговременные бизнес-данные в бэкенде, а не в состоянии представления.

Не помещай секреты и большие полезные нагрузки, нужные только для отрисовки, в состояние, видимое
модели. Держи `_uiContext` зарезервированным для среды выполнения.

## Показ, ресурсы и CSP

Используй `ThemeProvider`, `ViewControls`, `useViewTheme` или `viewConfig`, только когда нужно их
поведение: среда выполнения сама поднимает мост хоста и по умолчанию включает автоматическое
изменение размера. Именованный `viewConfig` может ограничить поддерживаемые режимы показа или
отключить автоматическое изменение размера.

Держи код и CSS представления в его директории. Общие публичные файлы кладите в `public/` и
разрешай их через публичную базу ресурсов фреймворка, а не через зашитый в код URL localhost.

Объявляй точные внешние источники в `view.csp`:

- `connectDomains` — для fetch, EventSource и WebSocket;
- `resourceDomains` — для скриптов, стилей, изображений, шрифтов и медиа;
- `frameDomains` — для встроенных фреймов;
- `baseUriDomains` — только для намеренного внешнего базового URI.

## Источник интерфейса, идентичность эндпоинта и метаданные хоста

В версиях SDK с автоматическими доменами Claude на основе эндпоинта настрой источник интерфейса
на инструменте: `view: { name: "wave", domain: "https://wavebyvento.com" }`.
Установи `MCP_URL=https://wave-by-vento.run.mcp-use.com` и `basePath: "/mcp"` у сервера.
ChatGPT получает `ui.domain: "https://wavebyvento.com"`; Claude получает первые 32
шестнадцатеричных символа SHA-256 от полного эндпоинта
`https://wave-by-vento.run.mcp-use.com/mcp` плюс `.claudemcpcontent.com`. Не хэшируй сайт или
источник ресурсов.

Изучи установленный SDK: старые версии хэшируют сам `view.domain`. Переходи на обработку на основе
эндпоинта, прежде чем удалять существующий помощник совместимости. Не выдумывай поля конфигурации
`uiOrigin` и `mcpEndpoint`.

Для разрешения домена представления `MCP_URL` только с источником дополняется `basePath`; URL с
путём считается полным эндпоинтом и сохраняется дословно. С OAuth используй `MCP_URL` только с
источником, потому что конфигурация OAuth этого требует. Без `MCP_URL` SDK использует путь и
параметры запроса и переданный или запрошенный источник. Указывай публичный URL явно, когда прокси
переписывает пути. `MCP_ASSETS_URL` управляет ресурсами и никогда — идентичностью Claude.

URL `view.domain` со схемой HTTP(S) нормализуются до источников. Для ChatGPT используй источник
HTTPS без `/mcp`. Предвычисленные домены Claude по-прежнему поддерживаются, но работают только для
Claude; замени их источником интерфейса для приложений на нескольких хостах. Если `view.domain`
не указан, остаются значения хоста по умолчанию. Без HTTP-запроса и `MCP_URL` Claude откатывается
к указанному в коде домену.

Удаляй помощники, которые перезаписывают сгенерированный `_meta.ui.domain` ресурса после
`next()`: они ломают преобразование для Claude. Сохраняй сгенерированные поля `ui` при добавлении
посторонних метаданных. Настраивай ресурс через `view.domain`, а не через `_meta` инструмента или
`_meta` результата инструмента. Сгенерированные ресурсы используют только стандартный
`ui.domain`. В написанных вручную ресурсах ChatGPT `openai/widgetDomain` — это псевдоним, а не
переопределение некорректного `ui.domain`; если выводятся оба, держи их согласованными. Собственные
ресурсы и промежуточное ПО ответов остаются под контролем автора.

`frameDomains` разрешает вложенные iframe внутри представления. Оно не задаёт источник
представления и не исправляет проверку домена. Добавляй его только для настоящих вложенных
встраиваний.

Проверяй `resources/read` для ChatGPT и Claude, включая эндпоинт с `/mcp` и источник интерфейса на
другом хосте. Обнаружение Claude использует заявленное имя клиента, откатываясь к User-Agent,
когда имени нет; неизвестные клиенты получают источник интерфейса. Не заявляй о проверке
публикации на хосте, опираясь только на тесты SDK.
