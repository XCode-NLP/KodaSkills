# Проверка

Запускай минимальные проверки, доказывающие запрошенное поведение, и расширяй их для изменений,
затрагивающих сгенерированные типы, аутентификацию, представления, границы пакета или параллелизм.

## Статические проверки

Используй пакетный менеджер и скрипты проекта. Для типичного проекта:

```bash
npx mcp-use typecheck
npm run typecheck
npm run build
```

Не считай, что в каждом проекте определены обе команды проверки типов. `mcp-use build` собирает и
транспилирует, но не заменяет проверку типов. Устраняй новые ошибки типов, линтера, границ пакета и
сгенерированного реестра до передачи работы.

## Проверки сервера и возможностей

Запусти настоящий сервер разработки, подключись через его публичный эндпоинт MCP и прогони
изменённую возможность:

```bash
npm run dev
npx mcp-use client connect dev http://localhost:3000/mcp
npx mcp-use client dev tools list
npx mcp-use client dev tools call lookup-inventory sku=item-1
```

Для инструментов проверь корректный ввод, отклонение по схеме, ожидаемые сбои и соответствующий
`structuredContent`. Для ресурсов прочитай статические и шаблонные URI и проверь дополнение. Для
подсказок изучи точные сгенерированные сообщения и предложения. Проверь пути авторизации и отмены,
если они менялись.

## Проверки представлений

Отрисуй каждое затронутое представление через его привязанный инструмент в инспекторе. Проверь:

- отрисовку в состояниях ожидания, готовности и ошибки;
- вызовы из представления к инструментам и действия хоста;
- состояние, видимое модели, против временного состояния интерфейса;
- тему, размеры, поддерживаемые режимы показа и доступность;
- публичные ресурсы, внешние запросы, CORS, ошибки времени выполнения и CSP.

Снимай настоящее представление командой скриншота, а не флагом `tools call`:

```bash
npx mcp-use screenshot --server dev --tool show-product id=item-1
```

## Расширенные проверки и проверки упаковки

- Для навыков поверх MCP проверь каталог, получи навык, прочитай поддерживающие файлы и запусти
  строгую рабочую сборку.
- Для уведомлений держи слушатель активным и подтверди недолговечное поведение инвалидации.
- Для уточнений проверь обязательный ввод, принятие, отказ, отмену, некорректный ввод, повтор
  колбэка и порядок побочных эффектов.
- Для проксирования и OpenAPI проверь представительные сгенерированные возможности и
  задокументированные неподдерживаемые границы.
- При изменениях экспорта, зависимостей или упаковки собери пакет и установи его в пустого
  временного потребителя: сборка в рабочей области не доказывает опубликованную границу.

Не развёртывай что-либо только ради проверки изменений исходников. Если развёртывание не
запрашивали, проверь локальные артефакты сборки и укажи непроверенную внешнюю границу.
