# Расширенные возможности

Используй эти возможности, только когда задача их требует. Сверяй точные параметры и текущие
ограничения с установленным пакетом.

## Инструменты из OpenAPI

Используй `MCPServer.fromOpenAPI()` с разобранным и включённым в пакет документом OpenAPI 3.x.
Указывай `baseUrl`, когда в документе нет пригодного URL сервера. Используй `tags` и `exclude`,
чтобы ограничить публикуемые операции.

Включай внешние цели `$ref` в пакет до создания сервера. Сгенерированный ввод покрывает путь,
параметры запроса, заголовки и тела запросов, совместимые с JSON; параметры cookie и тела не в
формате JSON не публикуются. Сгенерированные инструменты не выводят `outputSchema` из описаний
ответов.

## Проксирование серверов MCP

`server.proxy()` требует необязательный пакет `@mcp-use/client`. Вызывай его до `listen()` или до
первого запроса `server.fetch`. Ключи карты конфигурации задают пространство имён для вышестоящих
инструментов, статических ресурсов и подсказок.

Передавай bearer-токены и заголовки явно: запуск прокси не выполняет интерактивный OAuth.
Соединение, созданное из конфигурации, принадлежит серверу, а явно переданный `MCPConnection`
должно закрывать приложение.

Не считай, что все возможности пересылаются. Перед проектированием под них проверь текущую
поддержку шаблонов ресурсов, дополнений, подписок и повторной синхронизации вышестоящих списков.

## Уведомления в рамках запроса

Отправляй статус только пока исходный колбэк активен:

```ts
await ctx.sendNotification("com.example/import-status", { status: "started" });
await ctx.reportProgress(50, 100, "Halfway");
await ctx.sendLog("info", { imported: 42 }, "import-worker");
```

Дожидайся уведомлений перед возвратом. Это не канал широковещательной рассылки после ответа.
`reportProgress()` возвращает `false`, когда вызывающий не передал токен прогресса.

## Инвалидация списков и ресурсов

Публикуй межзапросные инвалидации только клиентам с активным слушателем подписки:

```ts
await server.notifyToolsChanged();
await server.notifyPromptsChanged();
await server.notifyResourcesChanged();
await server.notifyResourceUpdated("config://settings");
```

Считай их недолговечной инвалидацией кэша. Держи ресурс или реестр источником истины, делай
чтения повторяемыми и никогда не полагайся на доставку каждого события.

## Запрос уточнения

Используй `ctx.elicit(key, message, schemaOrUrl)`, когда способный клиент должен собрать
структурированный ввод или завершить внешний сценарий. Возвращай `required.result` напрямую, затем
обрабатывай `accept`, `decline` и `cancel`, когда колбэк запускается повторно.

```ts
const approval = await ctx.elicit("publish-approval", "Publish now?", schema);
if (approval.status === "required") return approval.result;
if (approval.status !== "accept" || !approval.data.approve) {
  return { isError: true, content: [{ type: "text", text: "Not approved" }] };
}
```

Колбэки запускаются повторно для раундов, где нужен ввод. Выполняй необратимые побочные эффекты
только после принятого ввода, используй отдельный стабильный ключ для каждого вопроса, проверяй
любые ответы с голым вводом и применяй проверенное состояние запроса, когда непрерывность влияет на
авторизацию или бизнес-логику. Никогда не собирай пароли, ключи API, платёжные данные и секреты
OAuth через форму уточнения.
