# Переход со старых шаблонов mcp-use

Читай этот справочник, только когда в проекте есть устаревшие или оставленные для совместимости
шаблоны, которых нет в установленном пакете или которые он больше не предпочитает. Переноси
поведение, а не только имена, и проверяй каждую изменённую границу по установленным типам.

## Замена устаревших шаблонов

| Старый шаблон или шаблон совместимости | Актуальная замена |
| --- | --- |
| Импорт сервера из `mcp-use/server` | Импортируй публичные API сервера из `mcp-use` |
| `schema` инструмента | `inputSchema` инструмента; аргументы подсказок по-прежнему используют `schema` |
| Встроенные поля колбэка | Передавай колбэк вторым аргументом метода регистрации |
| Цепочка `server.tool(...).tool(...)` | Регистрируй по отдельности; `tool()` возвращает `ToolRef` |
| Вложенная конфигурация шаблона ресурса | Поля верхнего уровня `uriTemplate` и `complete` |
| Помощники ответа как путь результата по умолчанию | Необработанные конверты протокола инструмента, ресурса или подсказки |
| `resources/<name>/widget.tsx` | `views/<name>/view.tsx` |
| `widget: { name }` инструмента | `view: { name }` инструмента |
| `widget({ props, output })` | `{ content, structuredContent, _meta? }` |
| `useWidget()` или `useWidgetProps()` | Деструктурированный `useToolContext<"tool-name">()` |
| Обёртка агрегированного поставщика | Инициализация среды выполнения плюс точечные хуки и компоненты React |
| Агрегированное состояние виджета и методы хоста | `useViewState`, `useHostContext`, `useDisplayMode` и точечные хуки |

Не переименовывай механически каждый `schema`: подсказки намеренно сохраняют это поле. Проверяй
подписи колбэков ресурсов и подсказок отдельно от инструментов.

## Пересборка интерактивного интерфейса

Для каждого инструмента отрисовки:

1. Перенеси точку входа в `views/<name>/view.tsx`.
2. Экспортируй ссылку на инструмент из точки входа сервера.
3. Добавь `outputSchema` и `view: { name }`.
4. Помести читаемый моделью текст в `content`, типизированные данные отрисовки в
   `structuredContent`, а данные вызова, видимые только представлению, в `_meta`.
5. Деструктурируй `useToolContext()` и обработай состояния ожидания, ошибки и готовности до чтения
   `toolOutput`.
6. Замени агрегированные методы интерфейса точечными хуками.
7. Перенеси CSP в `view.csp` и разрешай публичные ресурсы через базу фреймворка.

## Удаление допущений о транспорте и сеансе

Считай колбэки ограниченными запросом и потенциально параллельными. Замени реестры активных
сеансов, привязку к сеансу, идентичность пользователя в памяти и адресацию клиента после ответа на
контекст запроса или внешнее хранилище. Используй `ctx.client` только для самостоятельно заявленных
возможностей, а `ctx.auth` — для проверенной идентичности.

Используй `basePath` для пути эндпоинта MCP и `MCP_URL` для внешне видимого публичного источника.
Не восстанавливай публичные URL из допущений о localhost.

## Контрольный список перехода

1. Найди в исходниках, тестах, примерах и документации проекта устаревшие идентификаторы выше.
2. Подтверди публичные импорты и подписи регистрации по установленному пакету.
3. Запусти генерацию типов и проверку типов, прежде чем толковать ошибки ниже по стеку.
4. Прогони каждый перенесённый инструмент, шаблон ресурса и подсказку через настоящий клиент.
5. Отрисуй каждое перенесённое представление и проверь поведение в состояниях ожидания, ошибки и
   готовности, а также взаимодействие, ресурсы и CSP.
6. Проверь аутентификацию, уведомления и уточнения через поддерживаемые клиенты, если эти границы
   менялись.
7. Собери пакет и импортируй его из чистого потребителя, если менялись экспорты или зависимости.
