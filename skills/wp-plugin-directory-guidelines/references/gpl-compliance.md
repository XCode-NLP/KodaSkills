## Соответствие GPL (правило 1 подробно)

### Проверка (лицензирование)

- Каждая проблема лицензирования должна ссылаться на **правило 1** и содержать конкретный
  найденный файл и значение лицензии.
- Утверждения о совместимости лицензий должны соответствовать таблице совместимых с GPL лицензий
  или [списку совместимых с GPL лицензий GNU](https://www.gnu.org/licenses/license-list.html#GPLCompatibleLicenses).
- Используй локальные файлы в `references/`, когда они есть; иначе — авторитетные внешние URL.

### Сбои (лицензирование)

- Если лицензии нет в таблицах совместимости, не угадывай: проверь
  [список лицензий GNU](https://www.gnu.org/licenses/license-list.html) или эскалируй.
- Если плагин использует модель двойной лицензии, проверь обе лицензии независимо.

### Краткая справка: требования GPL в WordPress

WordPress распространяется под **GPLv2 или новее**. Все плагины, распространяемые через
WordPress.org, должны быть:

1. **на 100% совместимы с GPL** (код, изображения, CSS и все ресурсы);
2. содержать **объявление лицензии** в заголовке основного файла плагина;
3. содержать **полный текст лицензии** или ссылку URI на него;
4. **не ограничивать свободы**, данные GPL.

## Сводка версий GPL

| Версия | Год | Ключевое дополнение |
|---------|------|--------------|
| GPLv1 | 1989 | Базовый копилефт: сохранение тех же прав для изменений |
| GPLv2 | 1991 | Патентный пункт (раздел 7), более ясные условия распространения |
| GPLv3 | 2007 | Запрет тивоизации, явная передача патентных прав, положения о совместимости |

WordPress использует **GPLv2 или новее**, то есть плагины могут быть под GPLv2, GPLv3 или
«GPLv2 или новее».

Полные тексты лицензий:

- [GNU General Public License v1](https://www.gnu.org/licenses/gpl-1.0.html)
- [GNU General Public License v2](https://www.gnu.org/licenses/gpl-2.0.html)
- [GNU General Public License v3](https://www.gnu.org/licenses/gpl-3.0.html)

## Контрольный список соответствия лицензий

При проверке плагина убедись, что:

- [ ] в основном файле плагина есть корректный заголовок `License:` (например,
  `GPL-2.0-or-later`, `GPL-2.0+`, `GPLv2 or later`);
- [ ] в основном файле плагина есть заголовок `License URI:`, указывающий на текст GPL;
- [ ] если есть встроенные библиотеки, у каждой лицензия, совместимая с GPL;
- [ ] нет «раздельного лицензирования» (например, код под GPL, а премиум-функции под
  проприетарной лицензией);
- [ ] нет дополнительных ограничений сверх того, что допускает GPL;
- [ ] нет пунктов, ограничивающих коммерческое использование, изменение или распространение;
- [ ] нет обфусцированного кода (это противоречит духу доступности исходного кода).

## Лицензии, принимаемые каталогом плагинов WordPress.org

Источник: [трейт License_Utils в Plugin Check](https://github.com/WordPress/plugin-check/blob/trunk/includes/Traits/License_Utils.php)

### Лицензии, которые НЕ принимаются

Любая лицензия, не соответствующая идентификаторам выше, будет отклонена. Частые отказы:

- **проприетарные и «все права защищены»**;
- **Creative Commons BY-NC** (ограничение некоммерческого использования);
- **Creative Commons BY-ND** (ограничение на производные);
- **Creative Commons BY-SA** (v3.0 и раньше; v4.0 односторонне совместима с GPLv3, но её нет в
  регулярном выражении Plugin Check);
- **JSON License** («shall be used for Good, not Evil»);
- **SSPL** (Server Side Public License);
- **BSL** (Business Source License);
- **Commons Clause**;
- **Elastic License**;
- **Original BSD (4-clause)** — рекламный пункт несовместим с GPL;
- **MPL-1.0** — совместима с GPL только MPL 2.0;
- **EPL** (Eclipse Public License) — слабый копилефт, несовместим с GPL;
- **EUPL** (European Union Public License) — копилефт, несовместимый с GPL без многошагового
  перелицензирования;
- **Artistic License 1.0** — расплывчатые формулировки делают её несовместимой; используй 2.0;
- **OpenLDAP v2.3** (старая) — несовместима; v2.7 принимается.

## Частые нарушения GPL при ревью плагинов

### 1. Раздельное лицензирование

Плагин заявляет GPL, но ограничивает премиум-функции:

- «бесплатная версия под GPL, премиум проприетарный» — **НАРУШЕНИЕ**;
- весь распространяемый код должен быть совместим с GPL.

### 2. Обфусцированный код

- минифицированный JavaScript допустим, ЕСЛИ предоставлен исходник;
- обфускация PHP (ionCube, Zend Guard и т.п.) — **НАРУШЕНИЕ** (мешает осуществлению свобод GPL);
- закодированный или зашифрованный PHP — **НАРУШЕНИЕ**.

### 3. Отсутствие сведений о лицензии

- нет заголовка лицензии в основном файле;
- нет файла лицензии в пакете;
- встроенные библиотеки без документации о лицензии.

### 4. Ограничительные пункты

- «вы не можете продавать этот плагин» — **НАРУШЕНИЕ** (GPL разрешает коммерческое
  распространение);
- «вы не можете удалять упоминания автора» — допустимо по разделу 7(b) GPLv3, но не как
  всеобъемлющее ограничение;
- «только для личного использования» — **НАРУШЕНИЕ**;
- «вы обязаны ставить обратную ссылку на наш сайт» — **НАРУШЕНИЕ** (дополнительное ограничение).

### 5. Включение несовместимых библиотек

- включение кода под лицензиями, несовместимыми с GPL;
- использование ресурсов (изображений, шрифтов, CSS) под ограничительными лицензиями.

## Ключевые понятия GPL для ревьюера

### Распространение и частное использование

- обязательства GPL возникают при **распространении** (передаче другим);
- частные изменения НЕ вызывают требований GPL;
- публикация на WordPress.org И ЕСТЬ распространение.

### Производные произведения

- плагин WordPress, использующий API WordPress, обычно считается производным произведением;
- у плагинов, которые лишь агрегируются с WordPress, могут быть другие соображения;
- при сомнениях безопасный подход — лицензия, совместимая с GPL.

### Требование к исходному коду

- GPL требует доступа к «полному соответствующему исходному коду»;
- для плагинов WordPress: все исходные файлы PHP и JS, скрипты сборки;
- у минифицированных файлов должен быть доступный соответствующий исходник.

### Пункт «или новее»

- «GPLv2 or later» позволяет пользователю выбрать GPLv2 ИЛИ любую более позднюю версию;
- «GPLv2 only» означает строго GPLv2 (менее гибко, но допустимо);
- сам WordPress использует «GPLv2 or later».

## Порядок сообщения о нарушении

Когда нарушение GPL выявлено:

1. **Задокументируй нарушение** точно:
   - название и версия продукта;
   - сведения о распространителе;
   - конкретные нарушенные условия лицензии;
   - доказательства (скриншоты, фрагменты кода).
2. **Свяжись сначала с правообладателем.**
3. **Сообщи в FSF**, если код принадлежит FSF: license-violation@gnu.org.
4. **Для плагинов WordPress.org**: отметь через процесс ревью плагинов.

## Частые вопросы

Полные ответы по GPL см. в [GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html).

Частые вопросы при ревью плагинов:

**Может ли плагин брать деньги и оставаться под GPL?**
Да. GPL позволяет брать плату за распространение. Требование в том, чтобы получатели получили
свободы GPL (использование, изменение, распространение).

**Нужно ли включать в плагин полный текст GPL?**
Раздел 1 GPLv2 и раздел 4 GPLv3 требуют передать получателям копию лицензии. Стандартная
практика — ссылка URI в заголовке плюс файл LICENSE.

**Может ли плагин ограничивать, кто его использует?**
Нет. GPL прямо запрещает дополнительные ограничения для получателей. Пункты «только для личного
использования» и «некоммерческое использование» несовместимы.

**Является ли минифицированный JS без исходника нарушением?**
Если плагин распространяет только минифицированный JS без какой-либо возможности получить
исходник, это противоречит требованиям GPL к исходному коду. Исходник должен быть доступен (в
пакете или через репозиторий).

**Может ли плагин использовать изображения CC-BY-SA?**
CC-BY-SA 4.0 односторонне совместима с GPLv3 (материал CC-BY-SA можно включать в произведения под
GPLv3). CC-BY-SA 3.0 НЕ совместима.

**А шрифты, включённые в плагины?**
Шрифты должны быть под лицензиями, совместимыми с GPL. Частые приемлемые лицензии шрифтов: OFL
(SIL Open Font License), Apache 2.0 (с GPLv3), MIT, GPL с исключением для шрифтов.
