# Контрольный список отладки

1. Убедись, что интерактивный корень есть в отрисованном HTML
   (`data-wp-interactive`).
2. Убедись, что модуль скрипта вида загружается (сеть и source maps).
3. Убедись, что пространство имён хранилища совпадает с ожидаемым в разметке.
4. Проверь консоль на ошибки до любого взаимодействия.
5. Сузь область:
   - временно убери директивы, чтобы изолировать ломающуюся директиву или путь в
     хранилище.
6. Если возникает несовпадение при гидрации:
   - убедись, что начальное состояние и контекст совпадают с серверной разметкой.

## Особенности WordPress 6.9

**Состояние не сохраняется при навигации:**

- `getServerState()` и `getServerContext()` теперь сбрасываются при клиентских
  переходах между страницами.
- Если ты рассчитывал на сохранение устаревших значений, перепиши код на реактивное
  состояние хранилища.

**Несколько плагинов конфликтуют на одном элементе:**

- Используй уникальные идентификаторы директив с разделителем `---`, чтобы избежать
  столкновения атрибутов.
- Пример: `data-wp-on--click---my-plugin="actions.handle"`

**`data-wp-ignore` не работает:**

- Эта директива устарела в 6.9 и будет удалена. Она вызывала ошибки наследования
  контекста и навигации.
- Найди другой подход (условная отрисовка, отдельные интерактивные области).

**Области роутера и наложения не отрисовываются:**

- В WordPress 6.9 добавлено свойство `attachTo` для областей роутера, позволяющее
  выводить наложения в любом месте страницы.
- Убедись, что вложенные области роутера структурированы правильно.
