# WordPress Interactivity API

## Когда использовать

Используй этот навык, когда пользователь упоминает:

- Interactivity API, `@wordpress/interactivity`;
- `data-wp-interactive`, `data-wp-on--*`, `data-wp-bind--*`, `data-wp-context`;
- `viewScriptModule` блока или модульные скрипты вида;
- проблемы гидрации или «директивы не срабатывают».

## Что нужно на входе

- Корень репозитория и вывод разбора (`wp-project-triage`).
- Какие поверхности блока, темы или плагина затронуты (лицевая часть, редактор,
  и то и другое).
- Ограничения: версия WP, поддерживает ли сборка модули.

## Порядок работы

### 1) Определи текущее использование и способ интеграции

Поищи:

- `data-wp-interactive`
- `@wordpress/interactivity`
- `viewScriptModule`

Реши:

- это блок, дающий интерактивность через модуль скрипта вида в `block.json`?
- это интерактивность на уровне темы?
- это использование на стороне плагина по принципу «улучшить существующую
  разметку»?

Если ты создаёшь новый интерактивный блок (а не только отлаживаешь), предпочитай
официальный шаблон-заготовку:

- `@wordpress/create-block-interactive-template` (через `@wordpress/create-block`)

### 2) Определи хранилища

Найди определения хранилищ и подтверди:

- форму состояния;
- действия (мутации);
- колбэки и обработчики событий, используемые в `data-wp-on--*`.

### 3) Отрисовка на сервере (лучшая практика)

**Отрисовывай HTML на сервере** до вывода, чтобы обеспечить:

- правильное начальное состояние в HTML до загрузки JavaScript (без сдвига вёрстки);
- пользу для SEO и более быстрое восприятие загрузки;
- бесшовную гидрацию, когда управление перехватывает клиентский JavaScript.

#### Включи обработку директив на сервере

Для компонентов с `block.json` добавь `supports.interactivity`:

```json
{
  "supports": {
    "interactivity": true
  }
}
```

Для тем и плагинов без `block.json` используй
`wp_interactivity_process_directives()` для обработки директив.

#### Инициализируй состояние и контекст в PHP

Используй `wp_interactivity_state()` для начального глобального состояния:

```php
wp_interactivity_state( 'myPlugin', array(
  'items'    => array( 'Apple', 'Banana', 'Cherry' ),
  'hasItems' => true,
));
```

Для локального контекста используй `wp_interactivity_data_wp_context()`:

```php
<?php
$context = array( 'isOpen' => false );
?>
<div <?php echo wp_interactivity_data_wp_context( $context ); ?>>
  ...
</div>
```

#### Определи производное состояние в PHP

Когда производное состояние влияет на начальную отрисовку HTML, повтори логику в PHP:

```php
wp_interactivity_state( 'myPlugin', array(
  'items'    => array( 'Apple', 'Banana' ),
  'hasItems' => function() {
    $state = wp_interactivity_state();
    return count( $state['items'] ) > 0;
  }
));
```

Это гарантирует, что директивы вроде `data-wp-bind--hidden="!state.hasItems"`
отрисуются правильно при первой загрузке.

Подробные примеры и шаблоны см. в `references/server-side-rendering.md`.

### 4) Меняй директивы безопасно

Когда правишь директивы в разметке:

- держи использование директив минимальным и ограниченным по области;
- предпочитай стабильные атрибуты данных, однозначно связанные с состоянием
  хранилища;
- следи, чтобы серверная разметка и клиентская гидрация совпадали.

**Изменения в WordPress 6.9:**

- **`data-wp-ignore` устарела** и будет удалена в будущих версиях. Она ломала
  наследование контекста и создавала проблемы при клиентской навигации. Не используй её.
- **Уникальные идентификаторы директив**: теперь на одном элементе может быть
  несколько директив одного типа — с разделителем `---` (например,
  `data-wp-on--click---plugin-a="..."` и `data-wp-on--click---plugin-b="..."`).
- **Новые типы TypeScript**: `AsyncAction<ReturnType>` и `TypeYield<T>` помогают
  типизировать асинхронные действия.

Краткую памятку по директивам см. в `references/directives-quickref.md`.

### 5) Согласуй со сборкой

Проверь, что репозиторий поддерживает нужный путь сборки модулей:

- если используется `@wordpress/scripts`, следуй его соглашениям;
- если используется собственная сборка, убедись, что вывод в виде модулей
  поддерживается.

### 6) Отладь частые сбои

Если при взаимодействии «ничего не происходит»:

- убедись, что `viewScriptModule` подключён и загружается;
- убедись, что у элемента DOM есть `data-wp-interactive`;
- убедись, что пространство имён хранилища совпадает со значением директивы;
- убедись, что до гидрации не было ошибок JavaScript.

См. `references/debugging.md`.

## Проверка

- `wp-project-triage` показывает `signals.usesInteractivityApi: true` после твоих
  изменений (если применимо).
- Ручная дымовая проверка: директива срабатывает, состояние обновляется как ожидалось.
- Если тесты есть, добавь или расширь сквозной тест Playwright на путь взаимодействия.

## Сбои и отладка

- Директивы есть, но не работают:
  - скрипт вида не загружается, неверная точка входа модуля или нет
    `data-wp-interactive`.
- Несовпадение при гидрации или мерцание:
  - серверная разметка отличается от ожиданий клиента: упрости или согласуй начальное
    состояние;
  - производное состояние не определено в PHP: используй `wp_interactivity_state()` с
    замыканиями.
- Начальное содержимое отсутствует или неверно:
  - для блоков не задан `supports.interactivity` в `block.json`;
  - для тем и плагинов не вызывается `wp_interactivity_process_directives()`;
  - состояние и контекст не инициализированы в PHP до отрисовки.
- Сдвиг вёрстки при загрузке:
  - производное состояние вроде `state.hasItems` отсутствует на сервере, из-за чего
    нет атрибута `hidden`.
- Падение производительности:
  - слишком широкие интерактивные корни: ограничивай интерактивность меньшими
    поддеревьями.
- Проблемы клиентской навигации (WordPress 6.9):
  - `getServerState()` и `getServerContext()` теперь сбрасываются при переходах между
    страницами: не рассчитывай на сохранение устаревших значений;
  - области роутера теперь поддерживают `attachTo`, чтобы динамически выводить
    наложения (модальные окна, всплывающие панели).
