# Линтинг Bash

Запускай этот навык, когда просят линтинг, форматирование или проверку стиля скриптов Bash и других оболочек.

## Шаг 1. Определи доступный инструментарий

```bash
which shellcheck shfmt 2>/dev/null
```

Если ни одного инструмента нет, сообщи пользователю и спроси перед установкой:

```bash
brew install shellcheck shfmt
```

---

## Шаг 2. Найди скрипты оболочки

```bash
find . -type f \( -name "*.sh" -o -name "*.bash" \) -not -path "*/node_modules/*" -not -path "*/.git/*"
```

Проверяй также файлы с шебангом `#!/usr/bin/env bash` или `#!/bin/bash`, но без расширения `.sh`:

```bash
grep -rl '^#!.*\(bash\|sh\)' . --include="*" -l 2>/dev/null | grep -v -E '\.(sh|bash)$'
```

---

## Шаг 3. Запусти линтинг (проверка только на чтение)

```bash
shellcheck <file>
```

Сообщай обо всех находках, сгруппированных по файлам, с номерами строк и кодами правил SC (например, `SC2086`).

---

## Шаг 4. Проверь форматирование

```bash
shfmt -d -i 2 -ci <file>
```

Покажи пользователю предлагаемый дифф, прежде чем применять какие-либо изменения форматирования. `-i 2` задаёт отступ в два пробела, а `-ci` делает отступ у тел `switch-case` — подгони под существующий стиль проекта, если он отличается.

---

## Шаг 5. Примени форматирование (только с подтверждения пользователя)

```bash
shfmt -w -i 2 -ci <file>
```

Находки `shellcheck` почти всегда требуют ручной правки кода (безопасного автоисправления нет) — покажи каждую находку с предлагаемым исправлением и применяй только после подтверждения пользователя.

---

## Соглашения, которые проверяются

- Всегда бери подстановки переменных в кавычки: `"$var"`, а не `$var` (SC2086).
- Используй `[[ ... ]]` вместо `[ ... ]` для условий в скриптах Bash.
- Ставь `set -euo pipefail` в начало скриптов, чтобы быстро падать на ошибках, неинициализированных переменных и сбоях в конвейере.
- Используй подстановку команд `$(...)`, а не обратные кавычки.
- Объявляй локальные переменные функций через `local`.
- Отступы: два пробела, без табуляций (если `.editorconfig` проекта не задаёт иное).

## Правила

- НИКОГДА не устанавливай `shellcheck` и `shfmt` без предварительного согласия пользователя.
- Всегда сначала запускай в режиме проверки и диффа — автоисправления применяй только после подтверждения пользователя.
- Уважай существующие `.shellcheckrc` и `.editorconfig` проекта, если они есть: не переопределяй их настройки.
- Сообщай точную запущенную команду и её полный вывод — не сокращай находки в пересказе.
- Помечай любой `eval`, невзятое в кавычки раскрытие глоба и риск инъекции команды (например, непроверенный ввод, переданный в команду оболочки) как находку безопасности, даже если `shellcheck` её прямо не отмечает.
