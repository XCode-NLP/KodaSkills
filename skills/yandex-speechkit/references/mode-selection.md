# Выбор режима

Этот файл нужен, когда надо решить, какой путь STT в SpeechKit подходит под запрос.

## Соответствие по умолчанию

- Живой микрофон, ассистент, бот или живые субтитры: потоковое распознавание.
- Короткое заранее записанное голосовое сообщение: синхронное распознавание.
- Длинная запись, встреча, телефонный звонок, субтитры или пакетная обработка: асинхронное распознавание.

## Потоковый режим

Бери потоковый режим, когда:

- звук производится в реальном времени
- приложению полезны промежуточные результаты распознавания
- система сразу реагирует на законченные высказывания

Не выбирай потоковый режим только потому, что API удобен. Если источник — уже готовый файл, потоковый режим обычно добавляет сложность без выгоды.

## Синхронный режим

Бери синхронное распознавание, когда:

- вход короткий
- достаточно простого цикла запрос-ответ
- вызывающей стороне не нужно работать с асинхронными задачами

Типичные примеры:

- Голосовые заметки в мессенджере.
- Короткие загруженные аудиофрагменты.
- Небольшие утилиты, которые сразу возвращают текст.

## Асинхронный режим

Бери асинхронное распознавание, когда:

- файл длинный или большой
- задача может завершиться вне цикла запроса
- вывод может включать метки времени, нормализацию или последующую обработку

Типичные примеры:

- Расшифровка встреч.
- Записи колл-центра.
- Генерация субтитров.
- Офлайн-конвейеры обработки медиа.

## Эвристики выбора

- Если источник живой — бери потоковый режим.
- Если источник файл и нужен сразу текст короткого фрагмента — рассмотри синхронный.
- Если источник файл и задача похожа на пакетную расшифровку или обработку медиа — бери асинхронный.
- Если сомневаешься между синхронным и асинхронным для работы с файлом, предпочитай асинхронный: для длинных задач он безопаснее.
