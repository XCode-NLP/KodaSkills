# Подводные камни

Этот файл нужен при диагностике интеграций SpeechKit и подготовке деталей реализации.

## Авторизация

- Запросы требуют авторизации по IAM-токену или API-ключу.
- Приложенные скрипты SpeechKit предпочитают IAM-токены API-ключам. Используй `YANDEX_IAM_TOKEN` или `--iam-token` для асинхронного STT v3, когда это возможно.
- Запросам также обычно нужен контекст каталога.
- При авторизации сервисным аккаунтом не включай `folder_id` в запросы слепо: SpeechKit может взять каталог, в котором создан сервисный аккаунт.
- Учётные данные Object Storage отдельные от учётных данных SpeechKit. Загрузка по статическим ключам S3 доказывает доступ к бакету, но не к SpeechKit.
- При HTTP 403 PermissionDenied проверь права на SpeechKit у сервисного аккаунта, `YANDEX_FOLDER_ID`, принадлежность токена или ключа к ожидаемому облаку и каталогу, и повтори с `--iam-token` вместо `--api-key`.

## Правила потоковой сессии

- Потоковый режим предназначен для распознавания звука в реальном времени.
- Первое сообщение в потоке должно быть `session_options`.
- Отправляй куски примерно в темпе реального времени.
- Не допускай пауз больше примерно 5 секунд между сообщениями.
- При нарушении темпа или лимитов размера сессия может завершиться, и её надо создавать заново.

## Работа с результатом

- `partial` — не итоговый текст.
- `final` не всегда последнее полезное событие текста, когда включена нормализация.
- `final_refinement` может нести более чистый итоговый вывод.
- Большие ответы могут превышать лимиты принимаемого сообщения в gRPC-клиенте по умолчанию.

## Ошибки выбора режима

Частая ошибка интеграции:

- Длинные заранее записанные файлы направляют в потоковый режим, потому что у команды уже есть потоковый клиент.

Как правильно:

- Для длинных записанных файлов используй асинхронное распознавание, а потоковый режим оставь для живого звука.

## Подготовка аудио

- Не доверяй одному расширению файла.
- Подтверди фактический кодек и контейнер, прежде чем выбирать настройки запроса.
- Преобразуй неудобные исходные форматы до вызова API.
- Для синхронного `format=lpcm` отправляй сырые байты LINEAR16 (`s16le`). Не отправляй контейнер WAV с пометкой LPCM.
- Сохраняй точность таймингов, когда нужны субтитры, метки времени или вывод вроде разделения спикеров.

## Продвинутые возможности

STT v3 умеет больше, чем просто расшифровку:

- классификация
- анализ спикеров
- анализ диалога
- суммаризация

Считай это опциями по явному включению. Не примешивай их к стандартному потоку расшифровки, если пользователь их не просил.
