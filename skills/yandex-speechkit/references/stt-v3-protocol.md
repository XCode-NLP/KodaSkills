# Заметки по протоколу STT v3

Этот файл нужен при реализации gRPC-клиентов или разборе ответов STT v3.

## Файлы в cloudapi

Основные proto-файлы STT v3:

- `yandex/cloud/ai/stt/v3/stt_service.proto`
- `yandex/cloud/ai/stt/v3/stt.proto`
- `yandex/cloud/ai/stt/v3/package_options.proto`

## Основные сервисы

Поверхность сервиса строится вокруг:

- `Recognizer.RecognizeStreaming` — двунаправленное распознавание в реальном времени.
- `AsyncRecognizer.RecognizeFile` — асинхронное распознавание записанных файлов.
- `AsyncRecognizer.GetRecognition` — получение результатов асинхронного распознавания.
- `AsyncRecognizer.DeleteRecognition` — удаление сохранённых результатов.

## Форма запроса в потоковом режиме

Для потокового распознавания:

1. Открой `RecognizeStreaming`.
2. Отправь первое сообщение с `session_options`.
3. Отправляй последующие сообщения с одним из:
   - `chunk` — сырые байты аудио
   - `silence_chunk` — известная длительность тишины
   - `eou` — когда границы высказываний явно контролирует клиент

Не отправляй куски аудио до `session_options`.

## Форма ответа в потоковом режиме

Обрабатывай эти варианты ответа явно:

- `partial`: промежуточная гипотеза
- `final`: результат законченного высказывания
- `eou_update`: обновление по границе высказывания
- `final_refinement`: нормализованный итоговый текст
- `status_code`: сигнал состояния от сервиса
- `classifier_update`: вывод классификатора
- `speaker_analysis`: статистика по спикерам
- `conversation_analysis`: анализ на уровне диалога
- `summarization`: краткое изложение

Когда включена нормализация, жди `final_refinement` после `final`, а не считай `final` единственным итоговым текстом.

## Форматы аудио

Протокол поддерживает такие входные форматы:

- `LINEAR16_PCM`
- `WAV`
- `OGG_OPUS`
- `MP3`

Если приложение контролирует предобработку, предпочитай явно проверенный формат вместо догадок по исходному файлу.

## Режимы обработки и модели

Важные элементы управления на уровне протокола:

- режимы обработки `REAL_TIME` и `FULL_DATA`
- потоковые модели вроде `general` и `general:rc`
- отложенные модели для асинхронного распознавания
- опции нормализации текста
- опции ограничения языка
- разметка спикеров и анализ спикеров
- анализ диалога
- суммаризация

Не включай поля продвинутого анализа, если этого не требует продукт. Они не должны входить в стандартный путь расшифровки.

## Практическое правило разбора

Собирай текст по типу ответа, а не только по порядку прихода:

- `partial` — для временного показа в интерфейсе.
- `final` — для устойчивых границ высказываний.
- `final_refinement` — заменяй или дополняй, когда включена нормализация.
- Аналитические выводы держи отдельно от текста расшифровки, если вызывающая сторона явно не просит их объединить.
